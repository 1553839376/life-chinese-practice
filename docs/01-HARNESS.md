# 01 · HARNESS 机制（项目开发与验收规范）

> 目的：让这个项目**不依赖任何单次对话的上下文**也能持续迭代。
> 任何人（或任何模型）接手时，靠「读文档 → 跑门禁 → 按任务卡执行 → 写日志」四步就能安全改动、自动验收。
> 生效日期：2026-10-22

---

## 1. 三条底层原则

| 原则 | 含义 | 反例（禁止） |
|---|---|---|
| **文档是唯一真相源** | 功能状态只看 `docs/00-功能清单.md`，进度只看 `docs/STATE.md`，历史只看 `docs/03-变更日志.md` 与 `docs/logs/` | 靠对话记忆「上次好像改过」 |
| **门禁是唯一验收标准** | 「做完了」= `python harness/run_gate.py` 全绿 + 任务卡验收项逐条勾选 | 「我感觉没问题」 |
| **一次只改一件事** | 每个任务卡只对应一个可验证的改动，改完立刻跑门禁 + 写日志 | 一个任务里塞 5 个不相关修改 |

---

## 2. 目录契约

```
项目根/
├─ docs/                        ← 文档体系（唯一真相源）
│  ├─ README.md                 索引 + 新会话 5 分钟上手
│  ├─ 00-功能清单.md            【现状】已实现功能全量清单（改功能必须同步）
│  ├─ 01-HARNESS.md             【规范】本文
│  ├─ 02-验收清单.md            【标准】自动门禁 + 人工验收项
│  ├─ 03-变更日志.md            【历史】按版本倒序，只追加
│  ├─ STATE.md                  【快照】当前版本/线上链接/已知问题/待办队列
│  ├─ tasks/                    任务卡：一任务一文件（T-编号-短名.md）
│  └─ logs/                     工作日志：一天一文件（YYYY-MM-DD.md，只追加）
├─ harness/                     ← 自动化门禁
│  ├─ run_gate.py               一键门禁（构建→静态→测试→报告）
│  ├─ manifest.json             回归护栏：关键符号 + 资产条数下限 + 体积上限
│  └─ reports/                  每次门禁产出 gate-YYYYMMDD-HHMM.md
└─ build/                       源码分片 + 构建产物
```

**命名规则**：任务卡 `T-{三位序号}-{短名}.md`；日志 `YYYY-MM-DD.md`；门禁报告 `gate-YYYYMMDD-HHMM.md`。

---

## 3. 任务生命周期（状态机）

```
待办 backlog → 进行中 doing → 待验收 review → 已上线 done
                    ↓                ↓
                 阻塞 blocked      回滚 rolled-back
```

| 状态 | 判定 | 必须存在的文档痕迹 |
|---|---|---|
| backlog | 用户提出但未开工 | `STATE.md` 待办队列一行 |
| doing | 已建任务卡并开始改代码 | `tasks/T-xxx.md` 有目标 + 验收标准 |
| review | 代码改完、门禁通过 | 任务卡有「门禁结果」+ `reports/` 有报告 |
| done | 已发布并校验 / 或仅本地交付确认 | 任务卡结项 + `03-变更日志.md` 一条 + `logs/` 当日记录 |
| blocked | 外部依赖缺失（如账号、网络、用户决策） | 任务卡「阻塞原因」+ 已尝试方案 |

## 4. 单个任务的固定七步（自闭环）

> Agent 必须按顺序走完，不得跳步。每一步都有产物。

### Step 1 · 读取（Restore）
按顺序读 4 个文件，恢复上下文：
1. `docs/STATE.md`（当前版本、线上链接、待办队列）
2. `docs/00-功能清单.md` 中与本次需求相关的章节
3. `docs/02-验收清单.md`（知道哪些门禁会拦你）
4. 上一个任务卡 + 最近一篇日志（知道刚发生过什么）

### Step 2 · 建卡（Plan）
复制 `docs/tasks/T-000-模板.md` → `T-00x-短名.md`，写清：
- 用户原话（逐字引用，不许转述）
- 目标 / 非目标（明确不做什么）
- 验收标准（**可执行**：门禁项 + 具体断言 + 人工验收步骤）
- 影响面（改哪些分片、会不会动数据格式）
- 回滚方式

### Step 3 · 基线（Baseline Gate）
```bash
python harness/run_gate.py
```
必须先拿到**绿色基线**。红线不许在红基线上开工——否则分不清是自己弄坏的还是本来就坏的。
把基线报告编号写进任务卡。

### Step 4 · 实现（Implement）
- 只改 `build/` 下的分片源文件，**不直接改** `build/生活语文练习台.html`（它是产物）
- 改完跑 `python build/build_html.py` 重新生成
- 涉及数据格式变更时，必须写迁移逻辑（参考 `migrateCharset`），并保证老数据可用
- 涉及节奏/语音常量（`PACE`、`PACE_GAP`、语速）时：**先问用户，不凭感觉改**

### Step 5 · 验收（Verify Gate）
```bash
python harness/run_gate.py
```
- 门禁必须全绿
- 新增功能必须**补测试**（加到现有 5 套脚本之一，或新建并在 `manifest.json` 登记）
- 报告写入任务卡「门禁结果」

### Step 6 · 记录（Record）
- 任务卡填「实际改动」「门禁结果」「偏差与原因」
- `docs/03-变更日志.md` 追加一条
- `docs/logs/YYYY-MM-DD.md` 追加当日记录
- `docs/00-功能清单.md` 同步功能状态
- `docs/STATE.md` 更新版本快照/待办队列

### Step 7 · 交付（Deliver）
- 本地交付：`present_files` 展示产物
- 线上发布：走第 6 节发布流程 → 校验线上产物 → 更新 `STATE.md` 链接与版本

## 5. 门禁定义（run_gate.py 的四个关口）

| 关口 | 检查内容 | 失败即阻断 | 超时 |
|---|---|---|---|
| **G0 构建** | `build_html.py` 成功、输出存在、12 段齐全、体积 ≤ `manifest.max_bytes`（v21 起 16 MB，原 6 MB；换豆包语音后单文件 13.99 MiB 属自觉取舍） | 是 | 60 s |
| **G1 静态** | `manifest.json` 中全部关键符号在场、`check_docs.py` 与 `check_buttons.py` 双双退出码 0（文档数字与真实代码/产物一致、没有点不动的按钮）；资产条数不低于下限（语音 ≥1690、图示 ≥111、字库 ≥700、册次 =22）；无外部 `http(s)://` 资源引用 | 是 | 30 s |
| **G2 测试** | 5 套 jsdom 测试全部 0 失败，总项数 ≥ 429 | 是 | 300 s |
| **G3 报告** | 生成 `harness/reports/gate-*.md`，退出码 0 | 是 | 5 s |

`manifest.json` 是**回归护栏**：功能清单里每个关键能力对应至少一个符号，符号被误删即报红。

> 已知性能坑：`lint_page_quality.py` 在 >2 MB 文件上要跑 16 分钟（base64 正则回溯），**不放进门禁**，需要时后台单独跑。

## 6. 发布流程（已踩过的坑，照做）

```bash
# 1. 创建事务（拿 transactionId + baseVersion + 静态 URL）
python <skill>/create_page_transaction.py --node-id nU41kHmAoelqM2mGxWRFll
# 2. 用 curl 下载基线（urllib 走代理会 502）
# 3. 覆盖为本地产物后，用 curl PUT 上传（不要用 upload_page_artifact.py，它走 urllib 必失败）
python build/upload_curl.py
# 4. 提交 → 发布
python <skill>/commit_page_transaction.py
python <skill>/publish_page.py
# 5. 校验：download_page_artifacts.py --source publish（不要 curl workbuddy.link，直连 502）
```

**重试规则**：`commit` / `publish` 会随机 `TEMPORARY_ERROR`，必须循环重试（10–12 s 退避，常见 1–6 次）；取预签名 URL 也可能偶发，需 6 次退避。

## 7. 记录规范（写什么、不写什么）

### 每篇日志必须含
1. 今日任务编号 + 用户原话摘要
2. 做了什么（改哪些文件、加哪些函数）
3. **踩了什么坑、根因是什么**（这是最有价值的部分）
4. 门禁结果（项数 / 通过 / 失败）
5. 遗留问题 + 下一步

### 禁止写入
- 临时路径、一次性调试输出、模型内部思考过程
- 未验证的猜测（要写就标「待验证」）
- 密钥、账号、隐私数据

### 文档更新责任表

| 文档 | 何时更新 | 谁看 |
|---|---|---|
| `00-功能清单.md` | 功能增删改 | 所有人 |
| `01-HARNESS.md` | 流程变化时（很少） | Agent |
| `02-验收清单.md` | 新增验收项 | Agent / 验收人 |
| `03-变更日志.md` | 每任务结项 | 所有人 |
| `STATE.md` | 每任务结项 / 发布后 | 新会话首先看 |
| `tasks/T-*.md` | 任务全生命周期 | 执行者 |
| `logs/*.md` | 每天一次 | 追溯 |

## 8. 交接协议（给下一个模型 / 下一个人）

**5 分钟恢复上下文的标准动作**：

1. 读 `docs/STATE.md` → 知道版本、链接、当前在做什么
2. 读 `docs/00-功能清单.md` 的目录 → 知道能力边界（别重复造轮子）
3. 读 `docs/logs/` 最新一篇 → 知道上一次踩的坑
4. 跑 `python harness/run_gate.py` → 确认基线是绿的
5. 才开始改代码

**禁止**：
- 不跑门禁就宣布「已完成」
- 不看功能清单就重新实现已有能力
- 凭记忆改 `PACE` / 语音参数 / 数据格式
- 直接编辑 `build/生活语文练习台.html`（那是构建产物）

---

## 9. Done 的定义（Definition of Done）

一个任务只有**同时**满足以下 6 条才算完成：

- [ ] 任务卡「验收标准」逐条勾选
- [ ] `run_gate.py` 全绿（G0–G3）
- [ ] 新增/变更行为有对应自动测试（或任务卡写明为何无法自动测）
- [ ] `00-功能清单.md` 已同步
- [ ] `03-变更日志.md` 已追加
- [ ] `logs/` 当日记录已写（含踩坑与根因）

需要上线的任务额外两条：
- [ ] 线上产物已校验（关键符号在新版本里存在）
- [ ] `STATE.md` 的线上链接与版本号已更新

---

## 10. 变更分级（决定要不要走全流程）

| 级别 | 例子 | 流程 |
|---|---|---|
| **L1 轻改** | 文案、颜色、间距 | 建卡（简版）→ 门禁 → 日志 |
| **L2 功能** | 新增游戏、新增题型、改交互 | 全七步 |
| **L3 结构性** | 数据格式、语音方案、页面结构重构 | 全七步 + 先出方案给用户确认 + 回滚演练 |
