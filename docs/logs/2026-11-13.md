## v51 · 练习结算页按「一次就点对」算正确率（T-044）

**老师**：「还有个问题，我发现练习部分也是，学生都做错了好几个，最后结果依然是100%」。

**先诊断，按敏感口径先问再改**：判分口径是用户敏感参数，先查清 `build/p5.js` 的
`renderSummary()` / `gradeAnswer()` / `missOption()` / `wrongLogged`，再对比 `build/p7.js`
的 `gameOver()`（v39），确认不是判分错、而是分母恒等于答对数。给了三个口径，
老师选「**跟游戏一致（推荐）**」。

**根因**：v22 起「答错可重试」，点错不判死、只灰掉那一个选项，孩子最后每题都会点对。
旧 `renderSummary()` 用 `var rate = denom ? Math.round(right * 100 / denom) : 0;`，
`right` 最终恒等于题数 → **必然 100% + 三星**。v39 当时只补了一行「其中 N 题是试了再答对的」，
数字没降；游戏乐园 v39 早已按 `GAME.oneTry / total` 算，历史注释写「练习结算页刻意不跟」，
两处口径不同。这次统一到游戏侧。

**改了什么**：
- `build/p5.js` `renderSummary()` 三处：`oneTry = Math.max(0, right - (z.retried || 0))`
  → `rate = Math.round(oneTry * 100 / denom)`；`if (allDone && rate >= 90) msg = '太棒了！'`；
  结算提示改成「其中 N 题是试了再答对的，**不计入正确率**」。
- `retried` 不用新字段：`gradeAnswer()` 里本来就有 `wrongLogged`（`missOption()` /
  `logWriteMiss()` 置位，一题最多一次），直接 `if (STATE.quiz.wrongLogged) STATE.quiz.retried++`。
- `build/smoke2.js` 新增 §44 18 条；`harness/run_gate.py` 新增 G1 八条护栏
  （含两条防回潮：不许 `right * 100 / denom`、游戏侧口径不许被顺手改坏）；
  `harness/manifest.json` 登记 `oneTry` / `pickOption`，`smoke2.min_cases` 877 → 895；
  `APP_VER` 与 `p2.html` 角标 → v51。

**范围守住**：不动出题、`levelOf()`、`syncActive()`、跨天掌握（v50）、`gameOver()`、
学习记录 / 云端 / 导出导入、`PACE`。`retried` 只在 `STATE.quiz` 内存里。
