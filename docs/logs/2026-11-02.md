## v34 · 老师入口改双击（T-028）

老师一句话：「把老师那个图标的触发方式改为双击吧，长按有点难触发。学生其实也不会去按那个按钮。」

**长按为什么难触发**：`pointerdown` 起 900ms 定时器，`pointerup / pointerleave / pointercancel`
三处任一触发就清掉——手指微动、早松半拍都白按，而屏幕上没有任何进度反馈。老师还补了一句关键的：
「学生其实也不会去按那个按钮」，131 个像素的小胶囊本来就藏在右上角，为一个几乎不存在的误触
让老师每天多按两次不划算。

**改法**：入口自己数两次 `pointerup`（`TAP_GAP = 520` / `TAP_SLOP = 40`），触发后 `tapAt` 归零；
不挂浏览器自带的双击事件（触屏派发不一致）；`.nav-teach` 补 `touch-action:manipulation` +
`user-select:none`，否则第二下会被「双击放大」手势吃掉；文案（按钮 title / 空态 / 练习页 5 处）
统一成「连点两下」。

**真浏览器实测**（`build/_probe_v34.py`，Chrome headless）：
`start=true one=true two=false slowA=true slowB=true`，`touchAction=manipulation`——单击不进、
紧接着点第二下进、隔 0.64 秒不算双击。截图 `build/预览-v34-乐园顶部.png`。

门禁 109 → **113 项**，测试 685 → **689**（smoke2 516 → 520）。产物 15,400,858 B / md5 94c53d48…，v34。

**踩的坑**：护栏判「入口不许再有 dblclick」时，被我自己写的注释「不依赖 dblclick（触屏派发不一致）」
判红——注释里写旧词等于自己给自己下绊子，改成「不靠浏览器自带的双击事件」。

## T-030 · 先选游戏再选字（v35）

老师原话：「同事提了个意见，就是能否先选择游戏再去选练哪个字呢……然后这个字可以选很多个字，
让学生针对性做这些字的练习」。

**病根**：原来只有「点字 → 卡里挑玩法」一条路，`startGame(kind, [CARD_CH])` 一次一个。
练 6 个字要点 6 遍，每遍重新选玩法；想「一上挑两个、二上挑三个」得来回翻册次。

**改法**：乐园顶部加「先选游戏」→ `#gpMask` 选四款玩法之一 → 字格整体进多选态（每卡一个
`.ch-ck` 圆圈，点一下勾上、再点取消，边框和字变绿）→ 底部常驻 `#pickBar`「钓鱼 · 已选 3 个字」
+「开始练习（3）」，空选时按钮是灰的。**册次筛选和搜索照旧能用**，跨批次勾选不丢。
**游戏引擎一个字没改**：`startGame(kind, chars)` 本来就收数组，整批交进去；`GAME.origin` 沿用，
所以「再玩一次 / 换个玩法」还带着这批字。

**踩的坑**：
1. 玩法面板**不能复用 `data-gk`**——那条委托读 `CARD_CH`，乐园里是 null，复用就变成
   「弹一句『先选一个字』然后什么都不发生」。新面板用 `data-gp`。
2. 底部条是 `position:fixed`，**离开乐园必须自动退出选字态**（`showScreen` 兜一道），
   否则进老师端还压着一条「开始练习」。
3. 写测试时发现搜索是三路匹配（字 / 拼音 / 组词）：搜「人」会带出「大人」「二人」，
   第一张卡可能就是已选的字——测试里要挑「还没勾的那张」。
4. headless 窗口宽度被钳到 ~500px，直接开 `--window-size=390` 会「看起来溢出」，
   其实是截图裁掉了右边；要看真实 390 排版得套一个 390px 的 iframe。

**验收**：真浏览器探针 `build/_probe_v35.py` → `entry=true mask=true games=4 picking=true bar=true`
→ 点三张 `sel=3` → 再点第三张 `sel2=2` → 开始 `phase=game|kind=fish|origin=2|queue=6`，
`barGone=true`、`ckGone=true`。门禁 113 → **121 项**，测试 689 → **727**（smoke2 520 → 558）。
