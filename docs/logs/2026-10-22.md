## T-002 · 音效重做 + 游戏画面升级 + 首载优化（→ v8）

**用户原话**
> 还有几个需要优化的地方，1.优化正确反馈音效，目前的音效不够直接，尤其是正确的音效，听起来反而像错误的。2.优化游戏逻辑和画面：目前的游戏主题不错，但是画面需要优化，特别是操作后应该有一些对应的变化，这一部分可以不用这种扁平的画风 ，戳泡泡还好，但是其他的就显得有点生硬。首次加载优化

### 拆解与判断

用户说「正确的音效听起来像错的」，这不是音量问题，是**方向性问题**：原采样音偏闷、偏低、尾音拖，与「下降=否定」的听觉直觉撞车。所以没有调音量，而是**整段换掉**——改用 Web Audio 现场合成，音高和波形都由代码决定，可控且零解码延迟。

### A. 音效（`build/p8.js`）

新增通用合成器，一个函数覆盖全部需求：

```js
function synthTone(ctx, freq, at, dur, vol, type, bendTo)  // bendTo 可选，做滑音
```

| 场景 | 波形 | 音符 | 听感 |
|---|---|---|---|
| 正确 | `triangle` | E5 659.25 → G#5 830.61 → B5 987.77 → E6 1318.51 | 大三和弦向上琶音，明亮、上扬 |
| 错误 | `sine` | G4 392 → C4 261.63（各带下滑） | 两声下行，柔和不刺耳 |
| 连对 | `triangle` | 以 C 大调音阶按半音逐级抬高 | 越玩越顺 |

关键点：**点下去即响**（`currentTime + 0.005`），不走 `decodeAudioData`，彻底摆脱解码延迟导致的「音画不同步」。

### B. 画面（`build/p7.js` + `build/p1.html`）

统一成**三段式捕获反馈**，四款游戏共用一套机制：

1. `gameFx(el, kind)` → 在点击位置飘 `+10`（`.fx-score` + `@keyframes fxFloat`）
2. 物件沿 `--dx/--dy` 飞向容器（`.fx-fly` + `flyTo`）
3. 容器里的实物 +1、右上角计数 +1（`lootHTML` / `basketSVG(kind,n)`）

立体感靠 SVG 渐变，不靠投影：`fishSVG` 鳞光 `linearGradient`、`fruitSVG` 高光 `radialGradient`、`basketSVG` 编织纹、树冠三层 `radial-gradient` + 不规则 `border-radius`。

顺带修的产品逻辑：「喂鱼给鱼很怪」→ `FEED_ANIMALS` 去掉 `'鱼'`，一局固定一只动物。

### C. 首载（`build/build_html.py` + `p6.js` + `p2.html`）

1. 语音包从 `var VOICE_PACK = {...}`（4 MB 参与脚本编译）改为 `<script type="application/json" id="voicePack">`，`voicePackLoad()` 惰性 `JSON.parse`，`voicePackWarm()` 走 `requestIdleCallback`

3. `build_html.py` 加 `newline=''`，顺带还清 T-001 记的技术债

## T-003 · 鱼与果树重画（→ v9）

**用户原话**
> 有几个问题，一个是钓鱼游戏的鱼画的不对，很奇怪，尾巴长在嘴上。还有摘果子的树很怪，树干很细也不衔接。

### 两个根因（都不是"感觉问题"，是坐标错了）

**鱼**：`fishSVG` 身体 `ellipse cx=82 rx=58`（跨度 24–140），眼睛 `cx=116`、嘴 `x=138` → 头在右端。
而尾鳍 `M132 56 L176 27 Q167 56 176 85 Z` 起点 `x=132` 就压在嘴上，向右张开。**尾鳍画在了头那一侧**。
顺带发现鳃线在 `x=56`（尾部）也放反了。

**树**：`.tree-trunk` 38px 等宽直棍，`height:32%`，顶端 `y=68%`；`.tree-crown.a` 的椭圆最底点也在 `y=68%` 正中。
两者**只在一个点上相接**，且树干是平顶直棍 → 视觉上就是"绿墙下面插了根签子"。
树冠本身是单个椭圆铺满 86% 宽，也读不出树的轮廓。

### 改法

- 鱼：按「尾鳍→背鳍→身体→头」重排坐标，viewBox 180×112 → 200×116。尾鳍接身体左端 `M58 58 L14 24 Q36 58 14 92 Z`，眼 `cx=142`、嘴 `x=155`、鳃线 `M120 32 Q132 58 120 84`。
- 树：新增 `treeSVG()`，整棵树一张 SVG（400×250）。树干上口 22 / 下口 38 单位，顶端 `y=124` 插进树冠（树冠底 ≈140），接缝由几何保证。树冠 9 圆取并集 `clipPath` + 径向渐变统一打光 + 线性渐变压暗右下。
- `.grass` 下沉 z-index 0：原来草地渐变在树干之上，把树干底部冲成半透明。
- `.game-field` 加 `max-height:min(620px,80vw)`：窄屏实测场景 468×511（比例 0.92），等比 SVG 被纵向拉 1.74 倍，树干又变细；封顶后 468×374（比例 1.25）。
- `gameRight` 里树冠重启动画从 `void crown.offsetWidth` 改为 `crown.getBoundingClientRect()`——SVG 元素没有 `offsetWidth`。

### 踩坑

1. **headless 下动画探针假阴性**：`getAnimations()[0].playState === 'running'` 但 `currentTime` 恒为 0，
   采样 `getBoundingClientRect` 得到 `dx=0`，误以为 CSS transform 没作用到 SVG `<g>` 上。
   正确做法是手动 `a.currentTime = 150` 再读计算样式 —— 得到 `matrix(...,-6.83,0)`、位移 −25.76px，确认生效。
2. **窄屏截图"横向被切"是假象**：`--window-size=430` 截图宽 430，但 `documentElement.clientWidth` 是 492，
   `scrollWidth === clientWidth`，实际没有横向溢出。截图尺寸和布局视口不是一回事，要量 `clientWidth`。
3. 草的层叠顺序错了会让树干底部"消失"，这种问题只有看图才发现，代码里看不出来。

### 门禁与发布

- `gate-20261022-0958.md`、`gate-20261022-1002.md` 均全绿：19 项检查 0 红，208 项测试 0 失败
- 关键符号 83 → **91**（补登记 `fishSVG` `fruitSVG` `treeSVG` `lootHTML` `basketSVG` `gameFx` `treeCrown` `feedAnimal`）
- 发布链：tx `U5Lz4tPPKxNYmsM3v11qtm` → 上传第 2 次成功（5,233,901 B）→ commit newVersion **9** → publish 链接不变

**① 音量**：`VA_SFX_GAIN = 0.9`，正确音四个音的峰值 0.075/0.068/0.062/0.052，而语音是 `VA_VOICE_GAIN = 1`。

**② 鱼的动效**：这里我一开始判断错了方向——以为 CSS 动画没生效，写了探针量，结果是：
`animationName=swim`、`state=running`，把 `currentTime` 依次跳到 0/1050/2100/3150，
rect 左边界 83.8 → 96.3 → 105.8 → 96.3，**动画一直在跑**，只是 ±11px / 4.2s，肉眼几乎看不出。

**③ 跟读按钮**：按钮原在底部 `#btnRight`（老师辅助条），孩子视线里根本没有。
现在 76px 高绿色主按钮「读完啦，下一个 →」放在字正下方，下面一行小字「先跟着念一遍，再点这个按钮」；
底部那个「读对了」隐藏，避免两个入口并存；答过后大按钮收起，反馈条的「下一题」成唯一出口。

**① 最危险的一条默认值**：`charsOf` 原逻辑是「学生没选组 → 回退全库 700 字」。
对普通班算省事，对特需学生是灾难。这次直接删掉，改成没选字就不出题。

**② 云端没有字表这一列**。`mapStudent` 只读「字组」多选。如果不管，
`mergeCloudStudents`（云端为准）每次刷新都会把本机字表覆盖掉，老师今天剔的字明天又回来。
修法：合并时显式继承本机 `chars`。

**③ 迁移时机**。`migrateStuChars()` 必须在 `migrateCharset()` **之后**——
字库换代后再按组展开，组名才对得上。所以 `boot()` 里是 loadSnap → migrateCharset → migrateStuChars。
云端路径在 `loadAllData()` 里合并完学生、重建完字库后再迁一次。

**④ 700 条 ≠ 700 字**。实测字库 700 条只有 **561 个不重复字**（138 个字跨册重复，教材本来就会重）。
字表按汉字存，所以组内计数必须走去重后的 `expandGroups`。第一版截图就是这里出的问题：
组头写「10 字」，但 `expandGroups` 只返回 8 个字，「整组加入」永远点不成「整组移除」。

### 测试是红的，而且是对的

改完直接跑门禁：
- smoke2 掉 1 条（当前题有 4 个选项）
- check_pair 掉 1 条（进度显示：无）
- 合计 228 < 229

根因都一样：**旧测试数据靠「空组回退全库」**。smoke2 三个预置学生 `字组: []`，
check_pair 造的学生 `groups: []`。默认值一删，它们就没字可练了。

处理方式不是把默认值加回来，而是给测试数据补明确字组 / 字表。
另外 smoke2 新增 §16 共 17 条，把「迁移 / 空字表 / 逐字剔除 / 搜索 / 整组切换」全钉住。

### 一个刻意保留的语义

迁移是**一次性快照**。之后老师往字库里新加字，已有学生的字表**不会**自动多出来。
这是对的——字表是老师明确决定的教学范围，不该被字库变动偷偷改。
写了一条专门断言，防止以后有人"顺手"改成自动同步。

## T-008 · 「拼词语」题型（v14）

**用户原话**：「内置一个词库，每个汉字有对应的 1-2 个词语可以组词，老师在练习端选择了组词练习，
就是依据选择的汉字来出对应的词语题目，一次练习多个词语」；样子是
「下面有散乱的各种字 人、大、太、阳、木、头，然后学生就可以从中找出全部三对词语」。
上一轮给的三个候选（拼词 / 看图选词 / 选词填句）里，用户否掉了看图选词（要补很多图）。

### 先查数据，再决定要不要"建词库"

用户说「内置一个词库」。查了 `lib.js` 的 700 条字库：

```
700 条全部有「组词」栏（0 条空缺）
拆开去重 → 972 个词，969 个双字词、3 个三字词
每字 1~2 个词（只有 5 个字只有 1 个）
```

**词库已经在了**，而且是教材配套。所以没有另建一份 JSON —— 另建必然和字库分叉
（老师改字库、词表不跟着变）。改成 `wordBank()` 开题时现抽，顺带把老师自建词库也接进来，
上一轮那个「词库用在什么地方」的问题也一起回答了。

### 一个巧合

用户举例的 6 个字（人、大、太、阳、木、头），实测第一组出的就是 `大人 / 太阳 / 木头`，
正是他描述的三对词。这说明出题规则和用户脑子里的画面是对上的。

### 规则里最容易忽略的三条

1. **同组 6 个字块互不共用**。否则会出现「大」一块、「人」两块，孩子点哪个都算对。
2. **任取两字不能拼成本组以外的词**。这条不写就会有幽灵 bug：词表里有「大小」，
   本组正好有「大」和「小」，孩子拼出「大小」却判错——他会认为程序坏了。
   实现是 `wbCrossHit()`：把组内所有字两两组合，查一遍词表，命中非目标词就换候选。
3. **顺序反过来也算对**。先点「人」再点「大」，孩子心里想的是「大人」，
   纠正他的手指顺序只会让他不敢点。

### 记分口径

拼对一个词，给**词里属于学生字表**的那两个字各记一次独立答对；
词的另一半不在字表里就不记——记进去会让「已掌握」虚高，档案里的字表字数也对不上。
结算正确率按**词**算：8 个词对 6 个 = 75%，按组算会崩成 0% 或 100%。

### 六个坑

**① 题量被「字数」截断**。`total` 已经被 `if (total > pool.length) total = pool.length` 截断，
6 个字的字表只出 2 组。拼词语的题量单位是**词**，和字数无关 → 改读 `stu.count` 原始值。

**② 字表小时整组重复**。只有 2 个字（吸、冻）时，3 组全是「吸水/冰冻」。
加了 `usedW` 惩罚（前面组出过的词压到 10000 分）+ 整组都是旧词就收工。
这个坑的教训：**出题算法一定要用最小的字表跑一遍**，正常字表跑不出来。

**③ `dead` 黑名单跨组累积**。排除歧义词的 `dead` 集合忘了每组重置，
第 2、3 组可选词越来越少，最后凑不满。临时黑名单的生命周期要和它服务的循环对齐。

**④ 语音只加了一半**。`gen_tts.py` 加了句子、`p_voice.json` 加了音频（1690 → 1691），
但 `p8.js` 的 `SENT_FULL` 漏了映射 → 读题回退成逐字念「找、出、下、面、的、词、语」。
**加语音是三处：生成脚本、资源包、文本映射表。** e2e_av 的 `q_word` 断言一次抓到。

**⑤ 测试字库组词栏是空的**。smoke2 的 mock 字库 8 条 `'组词': ''`，
拼词语一条词都抽不到，`STATE.quiz` 直接是 null，下一行断言崩在 `null.qs`。
只在本节临时注入组词，不改全局 SEED（否则会影响前面字卡/配对的断言）。

**⑥ CSS 类名进不了符号表**。manifest 的符号检查只认 `function/var/id` 声明，
`wb-tile` 这种类名匹配不到，门禁报「缺 5 个」。类名改由 G1 的字符串检查覆盖。
