# 2026-11-05 · 加载手术（v41）

## 一、用户的两个问题

> 「帮我想想现在是继续可以增加新的游戏？还是优化现在有的游戏的动效，这些是否会增加很多网页负担？是否需要先优化一轮网页加载速度？」

> 「帮我优化一下我看看是什么效果，如果不好再退回来」

第一个问题是选择题，先算账再回答；第二个是让我动手。

## 二、算账结果（推翻了直觉）

体积构成：语音 12.90 MB（87.6%）/ 图示 0.75 / 笔顺 0.54 / 全部 JS+CSS 0.55（其中游戏 0.05，占 0.3%）。
动效：29 条 keyframes，25 条只用 transform，3 条 box-shadow，**0 条 filter/blur**，同时动画的元素个位数。

→ 「加游戏」和「改动效」在负担上都可忽略；真问题是加载链路。

## 三、发现的真问题：加载页在装死

`build_html.py` 把 12.9 MB 语音包拼在「结构之后、所有脚本之前」。浏览器必须读完一个 `<script>` 元素
才能执行它，所以音频把后面 2.5 MB 的脚本全堵住。而 `.boot-mask` 写死
`animation:bootFade .45s ease 2.4s forwards`——2.4 秒无条件淡出。

教室 10 Mbps 下的真实三段：

1. 0~2.4 秒 遮罩转圈（体验好）；
2. 2.4 秒遮罩自己走 → 露出唯一没 hidden 的 `#scrPick`：「班级练习 / 点一下自己的照片」+ **空白照片格**；
3. 2.85~8 秒 停在这屏，**写着点照片但没有照片**；
4. 约 8 秒脚本到，照片字格一次出现。

第 3 段比一直转圈更糟：它假装加载完了。

## 四、改了什么

- `build_html.py`：语音包挪到 TAIL 之后（文档末尾）+ 紧跟 `<script>if (window.voicePackWarm) voicePackWarm();</script>`。
- `p1.html`：`.boot-mask` 去掉 2.4 秒自动淡出 → `.boot-mask.out` 由 JS 触发；新增 `.boot-slow`（纯 CSS 12 秒淡入）。
- `p2.html`：文案「正在准备字卡和声音…」→「正在准备字卡…」；加慢网络提示行。
- `p6.js`：boot() 撤遮罩改成加 `.out` 淡出 + 460ms 摘 DOM。
- `run_gate.py`：G1 新增 4 条；`manifest.json` 登记 `voicePackLoad` / `voicePackWarm` / `bootMask`。

## 五、验数据

## 六、坑

- 护栏第一版把末尾那行触发脚本当成「普通脚本」，导致「语音块必须在最后」自己判红。改成先剔除触发脚本再取 max。
- **第一版把语音块追加到 `</html>` 之后**（p_close.txt 结尾就是 `</body></html>`），已发出去的 v41 结构不合规；
  改成按 `</body>` 切开插中间，重发 v42。
- **护栏量错了位置**：p8.js 注释里也有那串 script 标签名，`find` 命中注释（1.6 MB 处）而不是真块（1.83 MB 处），
  必须用 `rfind`。所以「首屏 1.66 MB」这个数是错的，真实是 1.83 MB。
- `.boot-slow` 看着像宋体，怀疑继承断了；用 `--dump-dom` + `getComputedStyle` 量出来三行 font-family 完全一致，
  差异只是 14px 与 22px 加粗的观感。**判字体不对先量声明，别凭眼睛。**
- headless 截图必须用绝对 Windows 路径，相对路径报「拒绝访问 (0x5)」。
- 加载页文案必须跟着改口：遮罩撤掉时声音确实还没到，继续写「准备字卡和声音」就是撒谎。

## 十二、钓鱼收线（10:00~10:20）

老师：「做一下钓鱼的游戏优化，能不能在学生点对之后，这个钓竿的线拉到鱼上把学生钓上来呢」。

- 旧实现 `.fish.hit{animation:fishCatch}` 是鱼自己往右上飘 186px 淡出，跟竿子无关。
- 新增 `fishReel(el, fr)`（`p7.js`）+ `.reel-line`（`p1.html`）。第一版：0ms 甩线 → 180ms 钩住炸水花 → 线 `scaleY` 收短、鱼同参数平移到竿尖并缩到 .34（540ms）→ 760ms 撤线。全程只动 transform，不挂 rAF，计数仍只有 `gameFx` 那一处（后面两轮见下表）。
- 三个坑：① 方向写反（`dx=tip-bx` 当成线方向，而竿上本来那条 57px 装饰曲线在截图里看着「像连上了」，误判两轮）；② `.fish` 的 `animation:swim` 关键帧压住 inline transform，不 `animation:none` 鱼一步不动，停完还要 `void offsetWidth` 再量；③ 水花原来点下就炸，改成钩住才炸。
- 门禁 **165 项 0 红 / smoke2 712 项 0 失败**（新增 §37 共 24 条）；1100×800 无头摆帧核过 p=0.05 / 0.5 两帧线端都贴着鱼。**未发布。**

### 改了三轮

| 轮次 | 做法 | 结果 |
|---|---|---|
| 一 | `div` + `scaleY`，从钩子拉一条直线 | 老师打回：「一个自然的曲线拼接一个生硬的直线」（竿上那条短线本来就是弯的，接直棍一眼看出是两样东西） |
| 二 | 整条线换 SVG `<path>` 二次贝塞尔弧；收线缩 `stroke-dasharray` | 线是弧了，但弧画死、鱼沿弦走，中途线头偏出 `sag`≈40px（540ms 太快，肉眼没抓到，自查时算出来的） |
| 三 | 整条弧以钩子为心**等比缩到 0.02**，鱼位移 `弦×(−0.98)`，同一 `k` 同一条缓动 | 线头与鱼心逐帧重合；`non-scaling-stroke` 定住线宽 |

第三轮同时把门禁那两条按第二版写的断言改了（不是删）：方向那条改查 `ax * (REEL_END - 1)`；
「不是直棍」那条改查 `translate(钩子)·scale(0.02)·translate(-钩子)` + `strokeDashoffset =` 只出现 2 次（多一次就是又在拿 dasharray 收线）。
smoke2 基线 710 → 712，产物 15,449,040 B（md5 `116374320004770b18389169b35c1460`）。

**摆帧核对（`build/_mk_reel.py` → `_reel.html`）**：headless 里 CSS transition 不随 `--virtual-time-budget` 推进，所以把「收到 p」这一帧直接摆出来——弧按 `translate(钩子)·scale(k)·translate(-钩子)`、鱼按 `弦×(k−1)`，再用
`path.getPointAtLength(total).matrixTransform(path.getCTM())` 与 `fish.getBoundingClientRect()` 量实测间距，写进 `document.title` 用 `--dump-dom` 读。
三帧实测 **gap = 2.7 / 2.7 / 2.8 px**（p=0.15 / 0.55 / 0.92），也就是弧端就在鱼心上——线画在鱼的**下面**（`.reel-svg` z-index 7 < `.fish` 9），所以肉眼看到的线头是「钻进鱼身」那一点。

**又踩一个坑**：`.fish` 带 `filter:drop-shadow`，会被提到独立合成层；摆帧后主线程 rect 已经变了，截出来的像素**还在旧位置**，两条错开 40~70px。害我两轮以为「线没搭上鱼」。验证办法是给副本加 `.fish{filter:none !important}` 再拍，或干脆只信 rect 数值。

### 第四版（11:15~11:40）：两根线合成一根

老师：「钓竿上的线不应该出现两段。现在没有点击的时候钓竿上就有一条线，点击了之后又会出现另一条线……当点击时，钓竿伸出一条线，自然的有弧度的线去把鱼钓上来」。

- 病根：竿子的 SVG 里本来就有 `.rod-string`（`M112 29 Q122 58 116 86`）+ `.rod-bob`（116,88），前三版从**浮标**起笔 → 场上两根线。
- 改法：起点挪到**竿尖 112,29**；起手切线沿用竿上那条短线（→122,58）；甩线时把 `.rod-string` / `.rod-bob` 藏起来、760ms 放回；形状二次 → **三次贝塞尔**（两头切线各自说了算）；收线比例改成 `k = 竿尖到浮标距离 / 弦长`（0.04~0.30），鱼停在浮标处。
- G1 两条断言按新几何改（起点/等比缩放中心），新增两条：竿上旧线与浮标必须被藏、起手切线必须接得上。smoke2 §37 从 24 条扩到 33 条。基线 712 → **721**，门禁 165 → **167 项**。
- **被 headless 骗了第三次**：`.fish` 的 `filter:drop-shadow` 让它进了合成层，摆帧后截图仍按旧帧画（线看着悬在鱼头上方 50~80px），而同一帧 rect 量出来只有 2.8px。改拍「只点击、不摆帧」的副本（`_click_only.html`）才看清：一条线从竿尖垂到鱼身上。以后核鱼的位移就别摆帧了。
