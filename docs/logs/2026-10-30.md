## 结算页：「做得不错」和「下一个题型」终于不像一家子了（T-021 第七节）

**起因**：老师看窄屏截图后一句话否掉——「学生等下在那一直点做的不错怎么办，这两个都没有区分开来。

盘下来是真问题：鼓励语用的是 `.feedback.ok`（浅绿底 + 2px 描边 + 圆角块），
跟下面的「下一个题型：看拼音写字 →」几乎同一个形状，只有字号差几像素。
特需学生认不了几个字，判断「能不能点」全靠形状和颜色；两个一样，孩子就一直戳那句表扬。

**改了三处**（只动结算页）：

1. `build/p5.js` 的 `renderSummary()`：鼓励语 `<div class="feedback ok">` → `<div class="fb-say">`；
2. `build/p1.html` 新增 `.fb-say{font-size:21px;font-weight:700;color:var(--green);text-align:center;…}`，
   **无底色、无描边**；
3. `.next-type` 改实心：`background:var(--green);color:#fff;border:3px solid #245741;
   box-shadow:0 4px 0 #245741`，24px / `min-height:76px` / `width:100%`，按下 `translateY(3px)`。
   它必须写在 `.primary.sm` **之后**——两个都是单类选择器、同优先级，后写者胜；
   第一版写在前面，字号底色全被 `.primary` 压回去（这个坑在 v26 第一版就踩过一次）。

**验证**：

  鼓励语计算样式 `background-color: rgba(0,0,0,0)`、按钮 24px > 鼓励语 21px、`.next-type.primary` 恰 1 个；
- G1 加 5 条：题型进度结构（`#typeProg` + `.tp-dot` + `renderTypeProg`）、「下一个题型」入口、
  `renderSummary` 体内不用 `.feedback`、`.fb-say` 样式里没有 background/border、`.next-type` 下标在 `.primary` 之后。

## v27：听写拆成两个 + 认字乐园加笔顺描写（T-023）

老师两句需求：「上次让你增加了汉字听写，但是你是词语听写，我建议可以分开来，是两个练习，汉字听写和词语听写。
还有，在最开始的全班都可以学习的地方应该增加一个描写。就像练习那样的。而且应该有笔顺才对。
笔顺是用灰色底图汉字上的动画变红色来先呈现怎么写，再让学生描写」。

**拆分听写**：`writesWord()` 只认「词语听写」，`isDictation()` 认两个；汉字听写只出一个方框、答案取单字，
词语听写按字数给格、答案取整词。老学生由 `migrateTypes()` 自动补一项（幂等 + `bak-T023` 备份），老师可取消勾选。
词语听写先筛「组词栏里真有 2~4 字词」的字，凑不出时给明确提示而不是空白页。

**笔顺描写**：学字卡加「描写这个字」。三层画法 —— 灰底整字 / 已写完的填红 / 当前笔裁到自己轮廓里画粗线
（`lineWidth 300`）。一笔 300ms 长出来，播完整字红着停 0.7s 再淡回灰底（提示语写的是「照着灰字描一遍」，
底字是红的就自相矛盾）。不判分、不写记录。561 字 / 4168 笔从 1.20 MB 压到 558 KB（数字 → 2 字符 base36，
往返校验 0 处不符），产物 14.10 → 14.66 MiB。

**这个坑值得记一辈子**：hanzi-writer 的笔顺数据 **y 轴朝上、基线 900**，canvas 朝下。第一版直接照抄，
截图里「上」的长横跑到最上面、整个字上下颠倒。jsdom 没有 canvas 实现，结构断言全绿也发现不了，
只能靠无头浏览器截图。中间还误判了两轮（以为「长横没填」「y 反导致漏笔」），最后把每一笔单独画到临时 canvas
数像素（`木[1172,2055,1104,1455]`）才确认填充正常——**肉眼判断 canvas 图形一律不可靠，先数像素**。
另外发现 headless 截图的 canvas 层不刷新（静态画一帧后截图仍是动画最后一帧，`getImageData` 却是对的）。

**结果**：门禁 **84 项 0 红**（G0 分片 12 → 15、G1 新增 10 条、资产加 `stroke_chars = 561`），
测试 **620 项**（smoke2 407 → 451）。版本 v27。
