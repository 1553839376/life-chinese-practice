# 2026-11-04 · 游戏结算正确率（v39）

## 一、用户报的问题

> 「有一个问题，就是在游戏的时候如果点错了后来再点对，最后还是显示100%正确率，有点不对把」

先查清楚「100%」到底是哪个数字：`grep 正确率` 只命中 `p5.js`（练习结算页），游戏结算框里根本没有百分比，
只有「找到 8 / 8 个」+ 三颗星 + 满分。问了老师两件事：

1. 是哪一屏 → **游戏结算页的三颗星**（不是练习结算页）；
2. 判分口径 → **错过的就不算对（正确率下降）**。

## 二、根因

`p7.js`：`gameRight()` 只 `GAME.done++`；`gameWrong()` 只 `GAME.miss++`，而 `GAME.miss` 在
`gameQuestion()` 里每题清零；`gameOver()` 的星数只看 `done >= total`，而这个条件一局打完必然成立。
所以「先错后对」和「一次就对」在结算眼里完全一样。

## 三、改了什么

- `GAME` 新增 `oneTry` / `retried` 两个账（`startGame()` 清零）。
- `gameRight()`：`if (GAME.miss > 0) GAME.retried++; else GAME.oneTry++;`
- `gameOver()`：`rate = Math.round(oneTry * 100 / total)`；星数 `>=90 / >=70 / >=40`；
  标题只有 100% 才「全部一次就找到啦！」；副标题「正确率 83% · 得了 90 分」；
  新增 `.go-note` 注脚「找到 6 / 6 个，有 1 个是试了才找到的」。分数公式没动。
- `p1.html` 加 `.go-note` 样式。

## 四、验证

- `smoke2.js` §34 新增 14 条：6 题错 1 → **83% / 两颗星**、标题「这一轮结束」、注脚报「有 1 个是试了才找到的」；
  另一局一次全对 → 100% / 三颗星 / 「全部一次就找到啦！」。
- `harness/run_gate.py` G1 新增 4 条护栏（分账、按 `oneTry` 算、不许再出现「全部找到啦！」、`.go-note`）。
- `manifest.json`：smoke2 下限 627 → 641。
- 门禁 145 → **149 项**，测试 798 → **812 项**，全绿。

## 五、坑

- `GAME.queue` 里装的是 `STATE.chars` 的字对象**引用**，往题上写 `q.retried = 1` 会污染字表、
  还会被 `saveSnap` 存进本机数据 —— 所以只能读 `GAME.miss`，不能往题对象上加字段。
- 测试别等 `gameRight()` 那个 880ms 的推进定时器，手动 `GAME.i = i; gameQuestion(); clearGameTimer();` 摆位。

## 六、没做的事

- 线上还是 **v38**（2026-11-03 发布，newVersion 27）。v39 只在本机构建好，等老师确认后按
  「create_page_transaction → upload_curl ×2 → commit → publish」五步发。
