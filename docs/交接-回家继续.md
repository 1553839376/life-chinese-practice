## 五、发布到线上（有一堆坑，都在这里）

线上发布**依赖 WorkBuddy 自带的 library skill 脚本**，不在这个仓库里。先找它：

```bash
python build/where_skill.py      # 打印脚本目录；找不到会告诉你怎么办
```

拿到目录后，**五步**（`$PAGE` = 那个目录）：

```bash
# 1. 开事务（记下 transactionId 和 baseVersion）
python "$PAGE/create_page_transaction.py" --node-id nU41kHmAoelqM2mGxWRFll

# 2. 上传（必须用 curl 版，urllib 走代理必失败）
python build/upload_curl.py <txId> "index.html" "build/生活语文练习台.html"
python build/upload_curl.py <txId> "生活语文练习台.html" "build/生活语文练习台.html"

# 3. 提交
python "$PAGE/commit_page_transaction.py" --transaction-id <txId> --message "v21 ..."

# 4. 发布
python "$PAGE/publish_page.py" --node-id nU41kHmAoelqM2mGxWRFll

# 5. 校验（下载线上产物逐块比对）
python "$PAGE/download_page_artifacts.py" --node-id nU41kHmAoelqM2mGxWRFll \
  --source publish --out-dir build/_pubcheck21
python build/_g4_check.py        # 里面路径要改成新目录
```

### 发布时必须记住的十条

1. **两个文件名都要传**：`index.html` 是入口（`entry_html` 已确认），中文名那份是短链兜底。只传一个可能掉版本
2. **commit 和 publish 会随机 `TEMPORARY_ERROR`**，必须循环重试（10–12 秒退避，常见 1–6 次）
3. **不要用 `upload_page_artifact.py`**（走 urllib，代理必失败），用 `build/upload_curl.py`
4. **`create_page_transaction` 返回的 url 目录是「旧版」内容**，新版目录要用 `list_page_publish_artifacts.py` 查
5. **G4 比对两边都要过滤空块**（平台会注入一个空 `inject.js` script），只过滤单边会索引错位
6. **线上产物不能做字节比对**：平台给每个元素注入 `data-page-node-id`、重排属性，线上比本地大 ~22.5 KB 属正常
7. **发版前必须改 5 处版本号**：`p4.js` 的 `APP_VER`、`p2.html` 角标、`STATE.md` 一句话现状、`00-功能清单.md` 4.3.8、`README.md`
   —— v19 就是「发完再补文档」，`APP_VER` 停在 v18 发出去了，只能 v20 重发
8. **顺序铁律：先改 5 处 → 构建 → 门禁 → 再发布**
9. `lint_page_quality.py` 在 >2 MB 文件上要跑 16 分钟以上，一律后台跑或跳过
10. 发布完用 `list_page_publish_artifacts.py` 拿新目录，**给用户直链前必须先 curl 抓一次确认是新版**

1. **文档是唯一真相源**：功能状态看 `docs/00-功能清单.md`，不靠记忆；每次改动要同步写 `docs/logs/YYYY-MM-DD.md` 和 `docs/03-变更日志.md`

## 八、家里的环境可能不一样的三个地方

1. **node 路径**：已改成自动探测（环境变量 `NODE_BIN` → PATH → `~/.workbuddy/binaries/...` → Program Files），一般不用管
2. **jsdom**：`npm install` 会装到仓库本地 `node_modules/`，门禁会优先用这个
3. **library skill 脚本位置**：`D:\职称参考\...` 是教室那台 Windows 的；Mac 上是
   `/Applications/WorkBuddy.app/Contents/Resources/app.asar.unpacked/resources/plugins/workbuddy-builtin/skills/library/page`。
   `build/upload_curl.py` **两个平台都会自动探测**（2026-10-25 在 macOS 上实测跑通整条发布链路）；
   其它脚本用 `python build/where_skill.py` 找

如果门禁报「找不到 node」，设一个环境变量即可：
```bash
export NODE_BIN="/c/Program Files/nodejs/node.exe"       # Git Bash
```

**网络**：这台机器访问 GitHub 要走代理（`http_proxy=http://127.0.0.1:59149`，
是 WorkBuddy 起的本地代理，端口每次可能变）。git 本身不读这个环境变量，所以 push 超时时：

```bash
# 查当前代理端口
env | grep -i http_proxy
# 只给这个仓库配（不写全局，换机器不会带过去）
git config http.proxy  http://127.0.0.1:<端口>
git config https.proxy http://127.0.0.1:<端口>
```

家里如果是正常网络，**不需要配代理**，直接 clone/push 即可。
