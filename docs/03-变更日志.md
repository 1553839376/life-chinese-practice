## [v22] 2026-10-24 · 答错可重试 + 错误音提响（T-014 第 1 期）

**任务**：`docs/tasks/T-016-答错可重试与错误音.md`

**起因**：用户 2026-10-23 提的四问里最硬的两条——
「点错了就没办法再试，而是要点下一题」和「错误的反馈音还是太小了」。
对特需学生来说，「我还没试完就不让我试了」比答错本身更挫败。

**根因**：
1. `pickOption` → `gradeAnswer` 里 `STATE.quiz.answered = true` 一次性锁死，点错即判死。
   而**游戏里**（`.miss{pointer-events:none}`）早就实现了「点错变灰、继续找」——练习页是漏掉的那一半。
2. 错误音峰值 0.20 / 0.17，比正确音（0.26 起）**还轻**，方向是反的。教室环境里等于没响。

**做了什么**：
- **点错不再判死**：`pickOption` 分流到新的 `missOption()` —— 只把点错的那个选项加 `.opt.miss`
  （灰化 + 虚线边框 + 抖一下 + `pointer-events:none`），题目不结束，其余选项与「提示一下」全都还能用。
- **连错 2 次才给答案**：把正确项加 `.glow`（复用游戏里的 `glowPulse`）并念一遍读音。
  这时「测」已经失败，目的改成「教会他」，所以视觉 + 听觉各给一遍。第一次错**绝不念答案**（念了就没得试了）。
- **记录口径**（最容易算歪的地方）：
  - 一题最多记 1 次错（宽松口径）。重试的目的是给他机会，不该双重惩罚。
  - `n` 在第一次错时 +1、终局答对时再 +1 —— 一题「错一次再对」确实练了两次。
    `alone + hinted + wrong === n` 这条不变量保持不变（smoke2 有断言钉着）。
  - 重试后答对**算 `alone++`**（没用提示），但 `wrong` 也 +1。于是「每次都错一次再对」的字会停在
    「练习中」而不是「已掌握」——**这是刻意的**：靠试出来的字还不算稳，继续留在在学名单多练几次。
    `levelOf()` **一行没改**。
  - **没新增 `retry` 字段**：云端日志 schema 没有这一列，写进去会被同步覆盖成 0（比不写更糟）。
    结算页用本次练习内的 `STATE.quiz.retried` 报一句「其中 N 题是试了再答对的」，不落库。
- **结算页**：`rate` 仍按「最终答对 ÷ 总题数」，重试不扣分（结算页是给孩子的激励，不是考核榜）。
  多一行 11.5px 灰字让老师看出这轮是靠试出来的。
- **错误音**：`sine` 0.20/0.17 → `triangle` **0.32/0.30/0.26**，两短下行后再加一个 98 Hz→82 Hz 的低频「咚」。
  音量全部不低于正确音峰值；低频「咚」和正确音的「明亮上行」在**音区与走向上同时**拉开，闭着眼也能分对错。
  音效总线不动（`VA_SFX_GAIN = 1`），按既有约定只用每个音的 `vol` 控力度。

**测试**：412 → **429 项**（e2e_av 87→92、smoke2 254→266），`manifest.min_cases` 同步抬高。
改掉的旧断言（「选错有文字反馈」「错完把正确的字再读一遍」）**不是删掉过关**，是换成测新行为：
「选错不出反馈块」「第一次错不念答案」「连错 2 次才念」，项数净增。

**验收**：`python harness/run_gate.py` 全绿（**57 项检查 0 红** / 429 项测试）。
新增 4 条 G1 护栏：点错不判死、一题最多记 1 次错、`.opt.miss` 不可点且不置 answered、错误音三音且每个 vol ≥ 0.26。

## [v21] 2026-10-24 · 全部语音换豆包（知性女声 0.85）+ 编码重做

**起因**：用户听完豆包 App 后说「读得特别好，每个音调都准确」，并指出晓晓的具体毛病——
三声（耳 ěr / 雨 yǔ）模糊、单字（江 / 京）偏快，整体还发闷。

**根因不是引擎，是两件事叠在一起**：
1. 老链路是「edge-tts 出 48 kbps MP3 → 再压到 24 kbps / 22.05 kHz」= **两次有损**，
   单字只剩 1323 字节，高频细节早就没了 → 发闷。
2. 晓晓的单字发音本身偏短促（知性女声同等条件下比 Vivi 短 8%~25% 也是同类问题）。

**做了什么**：
- 引擎换豆包语音合成 2.0，音色 `zh_female_zhixingnv_uranus_bigtts`（知性女声），`speed_ratio 0.85`。
  用户从 6 个「通用场景」音色里挑选，并明确不要儿童绘本 / 少儿故事那类带情感的。
- 编码改为「豆包直出 24 kHz 无损 WAV → **一次编码** 48 kbps AAC / mono（MP4）」，
  裁 50 ms 头 / 150 ms 尾静音，RMS 归一到 -20 dBFS（限幅 -1 dB）。
  选 AAC 不选 Opus：`decodeAudioData` 在旧 Safari/iPad 上对 ogg-opus 不可靠，
  课堂里「完全没声音」比多 2 MB 严重得多。
- 1691 条全部重生成（701 单字 + 972 整词 + 18 指令句），键集合与 v20 逐一致，无失声。

**数字**：语音包 3.95 → **12.85 MB**；产物 5,339,184 → **14,667,672 B**（5.09 → 13.99 MiB）；
裁掉 521 秒冗余静音（1800 → 1278 秒）；响度跨度 12.8 dB 归一。
体积预算 `manifest.max_bytes` 6 MB → 16 MB，且 `01-HARNESS.md` / `02-验收清单.md` 同步。

**踩到的坑（已做成护栏）**：
- 豆包接口**偶发返回垃圾音频**：「到了」单独合成被拉长到 3.2 秒、「破了」3.0 秒，
  同参数重请求就正常。→ 新增 `VERIFY=1` 时长自检 + `TEXT_OVERRIDE` 覆盖表；
  教训是「0 失败」不等于「全对」，必须按时长做统计体检。
- 「到了」连重请求都长，加一个空格（`到 了`）后才回到 0.47 秒。

**验收**：门禁 53 项 0 红 / 412 项测试全绿。

## [v19] 2026-10-23 · 在学上限与字表状态机（T-009 A 方案）+ 下线旧页面 + 改名 index.html

**A 方案怎么落地的**

不新增 `cap` 字段，而是把原来的 `stu.count`（每日题量）**升格成「在学字数」**——
同时在手上练的就这么多，一次练习正好把这几个字过一遍。两个数字并存只会互相打架。

| 概念 | 存哪 | 说明 |
|---|---|---|
| 在学上限 | `stu.count`（3–10，默认 6） | 原 4–20 收紧；超范围钳制 |
| 在学名单 | `stu.active`（汉字数组） | 长度 = 上限；老数据懒初始化 |
| 锁定 | `stu.lock` | 锁住的字学会也不自动退出 |
| 学习阶段 | `stageOf()` 算出来 | 在学 / 已掌握 / 待学——**和 `levelOf` 的三态不是一回事**（那个说"练得怎么样"，这个说"排没排进手上这批"） |

**自动补位的边界（这里踩了两次）**
1. 补位**只补「因为学会而让出来的」名额**。第一版无脑补满，老师点「先移出在学」下一轮又被补回来，按钮等于没做。
2. 手动「加入在学」的字要 **unshift 到最前**（下次先练它）；第一版 push 到末尾，被「保留前 N 个」直接截掉。
3. 已掌握的字被手动拉回来 = 复习，**顺手锁定**，否则下一轮 `syncActive` 又判定已掌握剔出去。
4. 「在学 11 / 10」这种数比上限还大——字库 700 条只有 561 个不重复字，学生字表可能带重复字，计数必须按字去重。

**老师端**
- 学生表单：「每日题量（字 / 词）」→「在学字数（同时在手上练几个）」3–10，带一行说明
- 档案页：顶部 meta 与图例都写「在学 6 / 6」「排队等学 16 个字」；逐字网格里在学的字加蓝点 + 蓝描边；点字展开后可「加入在学 / 先移出在学 / 锁定不换」

## [v18] 2026-10-23 · 今日字卡：进练习前先认一遍（T-013）

**用户要什么**：「这个识字启蒙台还是可以借鉴的，这个显示学生每天要学的字在一个界面，可以让学生整体复习学习一遍。我认为可以放在所有学生个人练习之前。点进学生后，应让学生看今天所学的字卡，每个读一下，再去做各种练习」。

**旧流程的洞**：点学生卡片直接 `startQuiz(第一个题型)`，孩子一进门就是一道题，没有「先认一遍」。

**做成什么样**：点学生 → 一屏「今天的字」→ 点一张读一张 → 读完点「开始练习」才进题。

| 元素 | 内容 |
|---|---|
| 字卡 | 大汉字 76px（主角）+ 拼音 15px + 组词 20px；左上序号、右上四态标签 |
| 点卡片 | 朗读该字（走 `charKey` 单字录音，不是拿词语去猜），卡片描绿 + 右下「读过了」 |
| 底部 | 「开始练习」62px 大按钮；全部读过时变成「都读过啦，开始练习」；没排题型则禁用并说明 |
| 顶栏 | 题数位显示「预习 / 8」 |

**三个关键决定**

1. **字单 = 档案里的建议顺序**（需巩固 → 靠提示 → 练习中 → 待学），不是出题的 `weightOf`。
   那个权重里「待学」最低（新字先出），拿来当字单会把最该补的「需巩固」挤到后面。
   第一版就是这么错的 —— 测试里「需巩固必须出现在前两张」直接把它抓出来了。
2. **出题收敛到这份字单**：`startQuiz` 读 `PRE.list`，题目只从这批字里抽。
   否则预习和做题各自随机一次，孩子刚认完 8 个、做题却是另外 8 个，这一步就白做了。
3. **预习不写学习记录**：点卡只打勾，不碰 `logs`；预习态把「提示一下 / 读对了 / 跳过这题」藏起来
   （`useHint` 里有 `if (!STATE.quiz) return` 不会崩，但对特需孩子「按了没动静」比没按钮更糟）。

**代码**：`p5.js` 新增 `PRE` / `todayChars()` / `renderPreStudy()` / `preSay()` / `preStart()` / `preMode()` / `firstWordOf()`；
`enterStudent` 改为进预习；`startQuiz` 新增 `isDrill`（只有真抽练才缩词量、才点亮抽练条）；
`p1.html` 新增 `.pre-*` 与 `.is-pre` 样式；`p6.js` 点击委托加 `[data-pre]` / `#preGo`（排在 `.opt` 之前，预习态 `STATE.quiz` 是 null）。

6 个字的字表被压成 2 组 —— 改成 `if (isDrill)` 才对（T-008 那条「不能拿字数当词数」又踩了一次）。

**验收**：门禁 **47 项检查 0 红 / 382 项测试 0 失败**（36+87+224+16+19），报告 `gate-20261023-1204.md`；
