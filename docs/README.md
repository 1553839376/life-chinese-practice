# 生活语文练习台 · 项目文档

面向培智 / 特需学生的认字练习平台。单文件 HTML，离线可用，数据留在本机。

**线上**：https://workbuddy.link/p/nU41kHmAoelqM2mGxWRFll　**当前版本**：v29

---

## 文档地图

| 文件 | 作用 | 什么时候看 |
|---|---|---|
| [`STATE.md`](STATE.md) | 当前版本、线上链接、待办队列、已知问题 | **新会话第一个看** |
| [`00-功能清单.md`](00-功能清单.md) | 已实现功能全量清单（状态 / 代码位置 / 验收方式） | 想知道「有什么、改哪里」 |
| [`01-HARNESS.md`](01-HARNESS.md) | 开发与验收机制：七步闭环、门禁定义、发布流程、交接协议 | 动手改之前 |
| [`02-验收清单.md`](02-验收清单.md) | 自动门禁项 + 人工验收项 + 回归红线 | 验收时 |
| [`03-变更日志.md`](03-变更日志.md) | 按版本倒序的变更历史 | 追溯「为什么这样改」 |
| [`tasks/`](tasks/) | 一任务一卡（`T-000-模板.md` 为模板） | 开工建卡 |
| [`logs/`](logs/) | 一天一篇工作日志（含踩坑与根因） | 看最近发生了什么 |

## 常用命令

```bash
cd build && python build_html.py     # 构建单文件产物
python harness/run_gate.py           # 一键门禁（构建→静态→测试→报告）
python build/check_docs.py           # 文档数字与真值核对（也进了门禁 G1）
python build/check_buttons.py        # 按钮体检：找点了没反应的控件
```

## 新会话 5 分钟上手

1. 读 `STATE.md` → 知道版本和在做什么
2. 读 `00-功能清单.md` 目录 → 知道能力边界，别重复造轮子
3. 读 `logs/` 最新一篇 → 知道上次踩了什么坑
4. 跑 `python harness/run_gate.py` → 确认基线是绿的
5. 复制 `tasks/T-000-模板.md` 建卡，按 `01-HARNESS.md` 七步走

## 三条不可破的约定

1. **文档是唯一真相源** —— 功能状态看 `00-功能清单.md`，不靠对话记忆
2. **门禁是唯一验收标准** —— 不说「感觉没问题」，只认 `run_gate.py` 全绿
3. **一次只改一件事** —— 一任务一卡，改完立刻门禁 + 写日志
