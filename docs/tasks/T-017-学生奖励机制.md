## 二、先分清两件被混为一谈的事

| | 反馈（feedback） | 奖励（reward） |
|---|---|---|
| 时间尺度 | 每一题，几百毫秒 | 每一天 / 每一周 |
| 回答的问题 | "这一题我做对了吗" | "我明天还愿意来吗" |
| 现状 | **已经很密**：答对音、亮起正确项、错误音、连对音、答错可重试 | **只有星星和连续天数，且都不合格** |

**关键判断：我们缺的不是反馈，是"跨天的理由"和"我一直在做"的可见积累。**

而现有的两个刻度都有同一个毛病——**它们都是能力的刻度，不是坚持的刻度**：

- 掌握率：学得慢的孩子可能半年停在 2/12。
- 星星：按掌握率折算，一个学期可能一直只有 1 颗。

于是所有指标都在同时告诉他"你不行"。

> **奖励机制的第一职责，是提供一条人人都能拉满的轨道。**
> 掌握率拉不满、星星拉不满，但"我今天来了"这件事，班里每个人都能 100%。

这句话是整个设计的支点，后面所有取舍都从这里推。

## 三、四个候选方案的四维对比

评估维度（针对培智 / 特需学生选定）：

1. **因果看得懂吗** —— 做了 A 就得到 B，孩子能不能立刻明白
2. **要不要照顾** —— 不照顾会怎样（会不会变成惩罚缺席）
3. **有没有随机** —— 可变比率强化容易形成固着行为
4. **会不会变成孩子之间的比较** —— 跨学生比较对这些孩子没好处

| 方案 | 因果看得懂 | 要不要照顾 | 有没有随机 | 会不会变成比较 |
|---|---|---|---|---|
| 浇水养花 | 强 | 不用 | 无 | 弱 |
| 集卡片 | 强 | 不用 | 无（若抽卡则有） | **强** |
| 盲盒抽取 | **弱** | 不用 | **有** | 中 |
| 养宠物 | 强 | **要** | 无 | 中 |

### 1. 浇水养花 —— 最优

- 因果最直白：练了 → 有水上 → 花长大。不需要任何解释，看一遍就懂
- 没有照顾义务、没有随机、人人一周一朵 → 天然不具备可比性
- **风险**：如果"长大"按练习量算，练得少的孩子花就更小 → 变成第二个掌握率。**必须按天算**
- **边界**：不枯萎、不倒退、不补浇。请假一周回来只是"没长"，不是"掉了"

### 2. 集卡片 —— 有吸引力的第二层，但不做主机制

- 最像"收藏"，成人视角很有吸引力
- 两个隐患：**卡片数量会变成比较**（"我 8 张你 3 张"）；**集齐之后空洞**
- 最大成本是美术：现在图示覆盖率只有 **16%**，做一套 20 张卡是实打实的活
- **但有一个让它值得做的角度**：不要做"字卡"（那就是掌握率换皮，激励增量几乎为零），
  做**生活场景卡**（超市 / 公交 / 医院 / 厨房 / 菜场……）—— 它本身就在教生活语文的学科内容，一举两得
- 定位：**第二层**，每开一朵花解锁一张，顺序固定

### 3. 盲盒 / 抽卡 —— 明确不做

三条理由，都不是"品味问题"：

1. **可变比率强化是最容易形成固着行为的程式**。对智力障碍儿童尤其容易变成"为了抽而去点"，练习本身被工具化——而我们要的不是让他多点几次，是让他真的认下字。
2. **"我努力了但抽到重复的"** —— 这个挫折的解释成本，恰恰是这些孩子最难承受的。他们最难处理的正是"我做了却没得到"。
3. **学校场景**：随机抽取机制一旦被家长质疑，整个设计要推翻重来。

**如果一定要"惊喜感"**：做**确定性惊喜**——顺序固定（我知道下一个是哪一类），内容未知（不知道具体长什么样）。可预期 + 有新鲜感，两者不冲突。

### 4. 养宠物 / 精灵 —— 只有砍掉"照顾"才可用

- 真实优势：**拟人依恋最强**，"我的"归属感最足。而特需孩子对"有人在等我"的回应很强
- 致命问题：只要有"照顾"，就有"亏欠"。宠物饿了 / 难过了 / 生病了 = **惩罚缺席**。
  孩子请假一天回来看到宠物难过，这是最坏的一种反馈
- 如果做成"只成长、不衰退、不用喂"，那它就退化成花，只是换了个更好看的外形
- **折中方案**：花为主 + 一个固定的小同伴站在花旁边说一句话（"今天也来啦"）。
  既有面孔、又不承担照顾义务。成本是多一套美术

## 四、推荐方案：我的小花园

### 主机制

| 项 | 建议 | 理由 |
|---|---|---|
| 计价单位 | **按天**（每完成一次"今天的练习"记 1 格） | 按题量会诱发"刷已会的字"（专挑会的字刷成长）；按天还能保证练得少的孩子花不会更小 |
| 一朵花 | 5 格 = 5 个练习日 | 一周 5 个上学日 ≈ 一周开一朵，一学期 20 朵 = 一座花园 |
| 清零 / 枯萎 | **不清零、不枯萎、不补浇** | 只暂停，不倒退。只要"不变小"，落后感就很轻 |
| 浇水动作 | 结算页 **1 次点击**（不是自动播放） | 参与感 > 自动播放；但不能有操作成本（不能点三下看动画） |
| 动画时长 | **≤ 2 秒** | 这些孩子的注意力经不起 5 秒烟花；超过 3 秒就是干扰 |
| 花种 | 按学生名 hash 固定，每人不同 | 稳定、不用存、不能改（"我的"但要避免选择困难） |

### 流程位置

```
我的主页（花园现状，静态）
   ↓ 开始今天的学习
今日字卡 → 正式练习 → 结算页（答对几题 / 正确率）
                          ↓
                    [浇点水] ← 1 次点击，花长一格，≤2 秒
                          ↓
                    满 5 格 → 开花，进花园，换新的一株（第 1 天）
```

**为什么放在结算页而不是主页**：那里是"我做到了"情绪最高的时刻，正好承接因果。主页只展示状态，不放动画。

### 第二层（后置，可选）

花园里每开一朵花 → 解锁一张**生活场景卡**（顺序固定：超市 → 公交 → 医院 → 厨房 → 菜场……）。
一学期 20 朵 = 一套。卡片有独立的教学价值，不是字的重复表达。

## 六、技术边界（先划清，免得后面推翻）

1. **不能存进 `logs`**：云端 logs schema 没这列，写了会被同步覆盖成 0（v16 组词栏、v22 `retry` 同类坑）。
   需要独立的 `STATE.garden`，且 `saveSnap` / `loadSnap` / 导出 / 导入**四处都要带上**
   （参考 `repairCharWords()` 三处必调的教训：少一处就静默丢失，重启就空回去）
2. **体积**：花园只存日期字符串数组（10 字符/天）—— 一学期 100 天 × 30 人 ≈ 30 KB，可接受。
   但如果做场景卡美术，那是几十 KB 级的 SVG，要过 G0 体积预算（当前 14 MB / 上限 16 MB）
3. **动画**：不能用 `requestAnimationFrame`（后台标签可能永不执行），用 `setTimeout(fn, 0)`；浇水动画 ≤2 秒
4. **语音**：开花如果要配音，加一条要改三处（`gen_doubao_voice.py` 的 SENTS、`p_voice.json`、`p8.js` 的 `SENT_FULL`），
   而且语音包已经 12.85 MB，加一条要重新算体积

# 第二轮（2026-10-25）· 换载体：从「花园」到「线路图」

## 八、用户新意见

> 那就取消盲盒抽取和集卡。我考虑浇水和养宠物主要是觉得可视化，感觉植物对学生没有吸引力怎么办呢？
> 是不是养宠物更好？或者有什么其他有意思的，比如我学生比较喜欢小火车、地铁、汽车这些东西、或者是各种美食？
> 你再思考一下，主要要好玩有趣，能够呈现。

**本轮结论：集卡与盲盒正式否决**（用户拍板）。载体从"花"改为**学生自己在意的对象**。

## 九、先纠正一个前提

"植物对学生没有吸引力"——这不是植物的错，是**我们挑了自己觉得好看的东西**，而不是**孩子已经在意的**东西。
换成宠物只是换成"另一个我们觉得可爱的东西"，如果这个孩子对宠物也无感，一样没吸引力。

**用户其实已经给出了答案：小火车、地铁、汽车、美食。** 这就是动机来源，不用教、不用解释。

## 十、宠物为什么反而更差（不只是照顾问题）

| | 花 | 宠物 | 火车 / 线路 |
|---|---|---|---|
| 美术成本 | 5 级 = 5 张 | 4 阶段 × 3 情绪 = 12 张 + 动作 | 1 列车 + 轨道（程序画） |
| 变化是否有动作 | 无，只是"变大" | 有，但需要动画 | **有，列车移动** |
| 照顾义务 | 无 | **有（饥饿/难过＝惩罚缺席）** | 无 |
| 对不感兴趣的孩子 | 无感 | **更糟**（有面孔却不想理） | 无感（但可换皮肤） |

结论：宠物是**成本最高、风险最大**的那个。用户想要的是"可视化"，而宠物的可视化优势可以用列车完全覆盖。

## 十一、推荐载体：「我的线路图」（火车 / 地铁）

**结构**：5 站 = 一条线；5 个练习日通一条线；通车后换下一条线；条数累计不清零。

**三个它赢的理由**：

1. **每一步都有可见的变化**。花是"变大"，列车是"往前开一站"——位移比尺寸更容易被看见，也更适合"我现在在第几站"这种具体提问。
2. **站名可以是生活场景词**：学校 / 公园 / 超市 / 医院 / 菜场。
   于是线路图本身就是**生活语文的复习材料**——孩子看自己的线路图，就是在看这些字。
   这一条让它从"装饰"升格为"教具"（花园做不到：花和字没有对应关系）。
3. **美术最省**：轨道、车站、线路都是程序画的 SVG 线和圆，只有列车需要一张图。换皮肤也便宜。

**参数**（沿用第一轮的按天口径，只换载体）：

| 项 | 建议 |
|---|---|
| 单位 | 按天，每完成一次"今天的练习"通 1 站 |
| 一条线 | 5 站 ≈ 一周；通车后线变成"已通车"，换下一条（6 条线 30 天，一学期约 4 组） |
| 清零 | 不清零、不倒退、不补站 |
| 动作 | 结算页 1 次点击 → 列车开到下一站，≤2 秒 |
| 站名 | 固定生活场景词（不做"用他学会的字当站名"——会与练习内容混淆） |
| 累计呈现 | 面板下方一排小线：已通车（实线）/ 在建（虚线 + 修到第几站） |

## 十二、皮肤可换（这条是架构层面的，比选哪个更重要）

**奖励状态只存"练过的日期数组"，皮肤是可替换的渲染层**。于是：

- 老师端一个下拉：`线路` / `花园` / `厨房`，换皮肤零数据迁移
- 今年这班爱车就用线路；明年换学生换花园或厨房，不用重做机制
- 也回答了"万一孩子对车也无感"——不是重设计，是换个皮肤

**美食**因此不必和线路二选一：
- **厨房皮肤**（同结构）：每完成一天往锅里加一样食材，5 天做出一道菜，菜进"我的餐桌"
- 或**里程碑奖励**：每通一条线，可以"去终点站吃一顿"

## 十三、待用户确认

1. 载体定线路（火车/地铁）还是厨房（美食）？还是两套皮肤都做、老师端可切？
2. 站名用固定生活场景词（学校/公园/超市/医院/菜场），还是用"第几站"？
3. 一条线 5 站还是 6 站？（5 = 一周，周五通车；6 = 每天一站含周末，但周末不上学）

# 第三轮（2026-10-25）· 美术方向：不许用代码画

## 十四、用户新要求

> 我如果要做这个奖励部分的希望你不要用代码来画这些，太扁平了，不真实的感觉，你需要用更好的美术风格去呈现。

**这条是硬要求，不是口味问题。** 现有装备（鱼 `fishSVG`、果树 `treeSVG`、图标）全是代码画的几何图形：
没有材质、没有光、没有笔触，所以必然「扁平」。孩子一眼能看出它不是真实世界的东西。
奖励面板尤其不能这样——它是**孩子最在意、盯得最久**的那一屏，用最省的方式做最该讲究的一屏，方向是反的。

## 十五、三个风格候选（已出样张）

| 代号 | 风格 | 文件 | 观感 |
|---|---|---|---|
| A | 水彩绘本（厚涂 + 纸纹） | `docs/art/style-A-水彩绘本.webp` | 温暖、手绘感强，但对比弱、结构散，缩进面板里容易发灰 |
| B | **微缩黏土 / 实物模型** | `docs/art/style-B-微缩黏土.webp` | 有材质、有光、有体积，像真的塑料玩具摆在桌上 |
| C | 剪纸拼贴（分层 + 投影） | `docs/art/style-C-剪纸拼贴.webp` | 干净、结构清楚，有纸纤维与层间阴影 |

**推荐 B。** 用户的原话是「扁平、不真实」，B 是唯一在**材质、光照、体积**三个维度同时给到的；
它也是这三张里最像「真的东西」的一张。C 作为第二选择（想要画面更干净、噪点更少时换它）。

## 十六、但不要一整张画好的场景图（这条比选哪个风格更重要）

奖励面板要满足两件整张图做不到的事：

1. **5 个站要变状态**（还没到 / 正在这一站 / 已经过站），整张图无法局部替换；
2. **列车要沿轨道移动**，整张图里列车是"焊死"的。

所以资产必须是**拆开的物件**：

| 资产 | 数量 | 说明 |
|---|---|---|
| 列车 | 1（+ 可选 1 前进态） | 透明底，侧面 3/4 视角，朝右 |
| 站台/站牌 | 5 | 学校、公园、超市、医院、菜场，同一视角、同一底座尺寸 |
| 状态标记 | 3 套 | 未到（灰）/ 当前（亮起 + 光圈）/ 已过（打勾或小旗），叠在站牌上 |
| 场景底 | 1 | 极简：柔和纸感底 + 程序画的轨道线 + 投影，**刻意留白** |

**关键判断：扁平感来自「没有材质和光」，不来自「布局简单」。**
所以正确做法是「**物件做到有材质，布局保持极简**」，而不是"把整个画面画满"。
画满的后果是文字和按钮压不住画面，上课时孩子找不到重点。

## 十七、体积预算（已实测，不是估算）

- 现有产物 **14.68 MB**，G0 预算 **16 MB**，余量约 **1.3 MB**
- 编码链路：本机没有 PIL / cwebp，但 **PyAV 19 的 libwebp 可用**；
  **注意 `pix_fmt` 必须用 `bgra`（支持 alpha），`rgba` 会直接 `avcodec_open2` 失败**（已踩）
- 实测（q=78，宽 720）：单张 **16–27 KB**
- 全套预估：1 底板 + 1 列车 + 5 站牌 + 3 状态标记 ≈ **150–250 KB**，占余量不到 20%

结论：**美术完全放得下**，这个预算级别够用较高分辨率（站牌可用 400–500 px，底板 1024 px）。

## 十八、两个必须先说清的问题

1. **风格会打架**。奖励面板变成厚涂实物，而答题页的鱼、果树、图标还是代码画的线条——
   同一个应用里两种质感并置，会显得奖励页是"贴上去的"。要么一起升级，要么给现有图形加同款材质滤镜（成本低）。
2. **AI 样张右下角有「AI生成」水印**，正式资产必须出**透明底、无水印**的版本；
   且每张要统一视角、统一光源方向，否则拼在一个面板里会露馅。
