# T-023 听写拆成两个题型 + 认字乐园加笔顺描写

- 提出人：老师（2026-10-30）
- 状态：已实现（v27，本地构建通过、门禁全绿）

---

## 一、老师原话

> 「上次让你增加了汉字听写，但是你是词语听写，我建议可以分开来，是两个练习，汉字听写和词语听写。还有，在最开始的全班都可以学习的地方应该增加一个描写。就像练习那样的。而且应该有笔顺才对。笔顺是用灰色底图汉字上的动画变红色来先呈现怎么写，再让学生描写」

拆成三件事：

1. 现有「汉字听写」实际听的是**词** → 拆成「汉字听写」（单字）+「词语听写」（整词）
2. 认字乐园（全员可学的那屏）的学字卡要有**描写**入口，形式同练习里的描红
3. 描之前要有**笔顺演示**：灰底字上逐笔变红，看完再描

## 二、改了什么

### 2.1 听写拆分

| 项 | 之前（v25） | 现在（v27） |
|---|---|---|
| 题型数 | 8 | **9** |
| 汉字听写 | 听一个词、两字词给两格 | 听**一个单字**、**只给一个方框** |
| 词语听写 | 不存在 | 听**整词**、一字一格 |

- `writesWord(t)` 只认「词语听写」，`isDictation(t)` 认两个听写题，`renderStage` 走 `isDictation` 分派；
  `wgAnswerOf(q, type)` 决定答案是一个字还是整词。判分、提示、音效、重写全部复用，没有分叉。
- `buildWriteQuestions` 在词语听写时**先筛出「组词栏里真有 2~4 字词」的字**再抽；
  `startQuiz` 加空题兜底：一个词都凑不出时明确提示去加字或补词，不再是空白页。
- `migrateTypes()`（`p4.js`，boot 里调用）：老学生的「汉字听写」后面自动补一项「词语听写」，
  **幂等**（已有就不加），首次改动前把整份数据备份到 `wb2_data_v1.bak-T023`。老师可以再取消勾选。

### 2.2 学字卡「描写这个字」

流程：点字卡 → 「描写这个字」→ 灰底整字 → 自动播一遍笔顺（逐笔生长变红）→ 停 0.7s 淡回灰底 → 照着描 → 「写好了」。

| 层 | 画什么 | 为什么 |
|---|---|---|
| ① | 所有笔画轮廓填灰 `#DCD4BE` | 这就是要描的底字，形状与笔顺数据同一套，不会错位（用字体画的灰字会和红字对不上） |
| ② | 已写完的笔画整笔填红 `#C0392B` | 「已经写了哪几笔」一眼可见 |
| ③ | 当前笔：裁到自己轮廓里，再画 `lineWidth 300` 粗线 | 裁剪让红色不糊到相邻笔画；粗线让这一笔整块填满。合起来就是「笔画长出来」 |

- 一笔 300ms、6 帧推进（`SO.seq`），笔与笔之间不留空档——太快看不清，太慢孩子走神。
- 播完整字红着停 `SO_HOLD_MS = 700ms`，再重画成灰底。**不能停在整字红**：提示语写的是「照着灰字描一遍」，
  底字是红的就自相矛盾，孩子也无从下笔。`SO_GEN` 计数保证「再看一遍」或换字时上一轮的定时器自动作废。
- 笔迹层独立画布（`#soInk`），复用 `wgRedraw`，灰字和笔迹互不覆盖。
- 按钮：再看一遍 / 写好了 / 重来一遍 / 写下一个（按当前册次列表往下走）。
- **不判分、不写学习记录**：这一屏没有学生档案，也没有手写识别；写好写坏老师看一眼。
  G1 护栏禁止 `traceDoneTap` 里出现 `gradeAnswer` / `saveSnap` / `getLog`，避免有人「顺手」加个判分把进度弄虚。
- 没有笔顺数据的字退回字体灰字（`.so-ghost`），仍可描，不报错。

### 2.3 笔顺数据

- 源：`hanzi-writer-data@2.0.1`（派生自 Make Me a Hanzi，**Arphic Public License**），只取字库中存在的 561 字。
- 生成：`build/gen_stroke_data.py`（下到 `/tmp/hzdata`，只做一次性转换，成果是 `build/p_stroke.js`，
  已入库，重建不需要再联网）。
- 编码：每个坐标数字 → 2 字符 base36（`v + 128`，下表 0–1295）。全库坐标实测 **-92..1005 且全为整数**，
  2 字符够用；`gen_stroke_data.py` 带**往返校验**（解回来逐数字比对原始 JSON，0 处不符）。
- 体积：原始 1.20 MB → **558 KB（45.5%）**；产物 14.10 → **14.66 MiB**，仍在本机 16 MB 预算内。

## 三、踩的坑

1. **y 轴反了（重大）**：hanzi-writer 的数据 y 朝上、基线 900，canvas y 朝下。第一版直接照抄，
   截图里「上」的长横跑到最上面、整字上下颠倒。改 `soFit` 的 `setTransform(dpr*w/1024, 0, 0, -dpr*h/1024, 0, dpr*h*900/1024)`；
   清屏也要先退回单位矩阵（翻转后 `clearRect(0,0,1024,1024)` 覆盖不到画布最底下一条）。
2. **jsdom 测不出来**：jsdom 没有 canvas 实现（`getContext()` 返回 `null`），结构断言全绿、字形却是倒的。
   canvas 相关的验证只能靠无头浏览器 + `getImageData` 数像素。
3. **靠眼睛判断「哪一笔没画上」会误判**：先后怀疑「长横没填」「y 反导致漏笔」，最后把每一笔单独画到
   临时 canvas 数像素（`木[1172,2055,1104,1455]`）才确认填充完全正常，问题只在 y 翻转。
4. **headless 截图的 canvas 层不刷新**：先静态 `soPaint` 一帧再截图，截出来还是动画最后一帧
   （同一时刻 `getImageData` 读到的却是对的）。判静态画面别只信截图，判动画用像素统计。
5. **笔画切分曾担心出错**：担心「一笔含多个 M 子路径」会把 4 笔切成更多。实测 4168 笔中多子路径 **0 笔**，
   `上` 三笔各 1 个 M，与 `medians` 数量一一对应。
