# T-042 · 早读选字记忆（不用每次重新勾）

- 版本：v49（2026-11-09）
- 状态：✅ 已上线（2026-11-09 发布，newVersion 33）（本地，待发布）
- 相关：`T-040`（早读模式）、`T-030`（先选玩法再挑字）、`T-021`（题型进度也是独立 localStorage）

---

## 一、老师的原话

> 「早读模式我希望保持记忆功能，即记住上一次勾选的汉字，这样很多不需要重复勾选」

早读是老师每天带全班读几个字，多数日子用的是同一批，重新勾一遍纯属重复劳动。

---

## 二、目标 / 非目标

**做**：进「早读 → 选字」时预勾上次那批字；可直接点开始，也可增减；改完点开始覆盖记忆。

**不做**：
- 不给别的玩法加记忆（钓鱼 / 摘果子 / 戳泡泡 / 喂小动物 / 乐园听写 / 随便玩仍从空开始）。
- 不跳过选字界面、不新增「一键开始上次」按钮——老师要能看见并改这批字。
- 不进云端、不进学生档案、不写学习记录、不改导出导入格式。
- 不动早读的节奏（5 秒跟读 / 1.7 秒换批）和判分口径（本来就不判分）。

---

## 三、实现口径

| 项 | 定法 |
| --- | --- |
| 键 | `wb2_read_pick_v1`，本机 `localStorage`，和 `wb2_sess_v1` 同口径 |
| 值 | 汉字字符串数组，例如 `['一','二','人']` |
| 写入点 | `pickStart()` 里 `if (kind === 'read') readPickSave(chars);` |
| 读取点 | `pickBegin(kind)` 里 `PICK.list = (kind === 'read') ? readPickLoad() : [];` |
| 恢复 | 按 `w` 回 `STATE.chars` 查，拿到的是同一个对象引用；查不到的字跳过 |
| 复位 | `pickEnd()` 清 `PICK.restored`；`pickToggle()` 也清（老师一改就不再自称「上次那批」） |
| 提示 | `PICK.restored` 为真时底部写「已勾上上次早读的 N 个字，可增减，点右边直接开始」 |

**为什么只存字符串**：`STATE.chars` 里的字对象是引用，JSON 落盘会把整张字表连带写进去；
字库更新后恢复出来的是旧对象，`c.p` / `c.w` 可能和当前字表对不上。按 `w` 回查最稳。

**为什么只在 `pickStart()` 写**：勾了又取消不算一次选择；`shot_read.py` / `probe_read.js`
这类脚本会直接调 `startRead(pool)`，不该改写老师真正的记忆。

## 四、验收

- smoke2 §42 十八条实跑全过：第一次用是空的 / 没记忆时按钮仍禁用 / 点开始才落盘 /
  只存字符串 / 不进 STATE 与 logs / 再进自动勾 3 个 / 提示写明「上次」/ 按钮「开始早读（3）」可直接点 /
  恢复的是同一对象 / 改勾选后提示复位 / 字表改了跳过查不到的字 / 钓鱼不预选也不覆盖记忆 /
  换一批会覆盖。
- G1 七条护栏 + 旧 PICK 护栏改成新形状。
- 门禁 **204 项 0 红 / 1020 项测试 0 失败**（smoke2 831 → **849**）。
- 产物 15,484,754 B / md5 `1a2c62c921277ea1c553735ebc26081c`，`APP_VER` → v49。

**已发布**（2026-11-09，newVersion 33）：线上 15,513,433 B，两个入口 `APP_VER = 'v49'` 且含 `wb2_read_pick_v1`，下载线上副本跑 smoke2 **849 项 0 失败**（含 §42 十八条）。

> 老师在希沃 / 平板上**刷新一下**即可：进「早读 → 选字」自动勾回上次那批字，底部直接点「开始早读（N）」。
> 注意：记忆是**按浏览器本机**存的（`wb2_read_pick_v1`），换设备 / 换浏览器不会带过去，这是刻意的。
