# T-011 · 词库空表抢救（角标 + 组词体检 + 内置兜底）

- 日期：2026-10-23
- 版本：v16
- 触发：用户第二次报「词库还是空的呀，可以用你内置的汉字的组词先把词库放下这些词语进去」

## 一、先说结论：代码里词库不是空的，是**他机器上那一份数据**空了

探针实跑（新装环境）：

| 指标 | 值 |
|---|---|
| 字库 | 700 条 |
| `builtinWords().list` | 969 个词 |
| 词库表行数 | 969 行（全是内置行） |
| 计数文案 | 共 969 条：内置组词 969 条 + 我的词库 0 条 |

同一份产物、同一个页面，我这边有 969 行，用户那边空表 —— 差异只能来自**运行环境**，不来自代码。抽出来三种可能：

1. 他打开的是旧版页面（浏览器缓存 / 用的是老二维码 / 老节点 `lSvkq…`）；
2. 他机器上字库的「组词」栏是空的；
3. 页面在他那边报错，渲染没跑完。

## 二、根因 ②：字库「组词」栏会被抹掉，而且抹掉后界面完全看不出来

`builtinWords()` 是从 `STATE.chars[*].words` 现抽词的。这条链上有三处会把 `words` 弄丢：

| 入口 | 代码 | 为什么会丢 |
|---|---|---|
| 云端载入 | `loadAllData()` → `mapWord(row)` 拿 `row['组词']` | 字词表若没有「组词」列（老表结构 / 新建列没同步），整表 700 条全是 `words:''` |
| 导入备份 | `importBackup()` → `STATE.chars = arr(o.chars)` | 旧备份导出时就没有组词栏 |
| 老本机存档 | `loadSnap()` | 早期版本的种子数据没写 `words` |

`migrateCharset()` 只在 `charsetVer` 不匹配且「字库是纯内置、没动过」时才整表重灌，所以只要 `charsetVer` 已经等于当前值，这张空组词的字库就会**一直空下去**，每次打开都是空词库。

而界面上一点提示都没有：字库页 700 行都在，词库页写「还没有自己的词」，老师看到的就是「词库是空的」。

## 三、改法：体检 + 兜底 + 角标，三层

### 1. `repairCharWords()`（数据层）

只在「整张字表一条组词都没有」时，按字从页面内置字表 `CHARS` 补回 `words`。
老师自己填过的、哪怕只填了一条，一律不动（有测试钉住）。返回补回条数，补了就 `saveSnap()`。

三条入口都调用：`boot()`（本机秒开）、`loadAllData()`（云端整表覆写后）、`importBackup()`（导入备份后）。少哪一条，重启就又会空回去。

### 2. `builtinWords()` 兜底

扫完 `STATE.chars` 仍然一个词都没有（比如字表整张是外来字，内置字表里查不到），直接扫 `CHARS` 出词，并置 `fallback = true`。
这不是「第二份词表」——`CHARS` 就是页面里编译好的那个 700 行内置字库本身。

### 3. 角标 `APP_VER`

老师端顶部加 `v16 · 内置词 969`（走兜底时写 `969（兜底）`）。
用户下次再说「还是空的」，让他看一眼角标：
- 角标是 `v16 · 内置词 969` → 数据正常，问题在别的界面；
- 角标是老版本号 → 他打开的是缓存页面，硬刷新即可；
- 角标写「（兜底）」→ 他的字库组词栏真是空的，已经在兜底了。

词库计数后面同时加一句 `⚠ 字库「组词」栏是空的，已改用页面内置字表的组词`，不让界面装作正常。
