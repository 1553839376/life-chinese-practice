# T-010 · 词库预填内置组词（v15）

| 项 | 内容 |
|---|---|
| 用户原话 | 「你这个词库还是空的呀，可以用你内置的汉字的组词先把词库放下这些词语」 |
| 状态 | done（2026-10-23，v15 已上线） |
| 影响面 | 老师端「词库」页从空表 → 默认 969 条；数据源不变（仍是字库组词栏派生） |

## 1. 先确认"空"在哪：题库有词，界面没露

v14 上线时 `wordBank()` 已经从字库「组词」栏抽出 **969 个双字词**，拼词语出题一直正常。
但老师端词库页渲染的是 `STATE.words`——**只有老师自己录的词**，而新装的页面一条都没有，
所以老师看到的就是一张空表，自然会认为"词库是空的"。

结论：不是数据缺失，是**派生数据没在界面上露面**。这一条要在文档里写清楚，
否则下次又会有人去"补一份词表"。

## 2. 为什么不把 969 条直接写进 `STATE.words`

看着最省事，实际有三个代价：

| 代价 | 说明 |
|---|---|
| 分叉 | 老师改一个字库的「组词」，已落库的旧词不会跟着变；两份数据迟早对不上 |
| 体积 | 969 条 × 约 90 B ≈ 87 KB，还会进备份 JSON 和云端镜像 |
| 语义混乱 | 老师删掉内置词＝字库还留着，下次开题又出来了，删了又回来 |

所以内置词是**派生视图，只读**：`builtinWords()` 每次从 `STATE.chars` 现抽。
老师真想改某个词，点「收进词库」复制一份到 `STATE.words`，之后那一份可编辑、可停用、可删。
两份同名字段在出题时按 `byW` 去重，不会出现两个「大人」。

## 3. 界面

| 位置 | 变化 |
|---|---|
| 来源筛选 | 「筛选分组」→「来源」，三项：全部 / 内置组词 / 我的词库 |
| 内置行 | 行首 `内置` 小绿标、浅底（`tr.tr-builtin`）、分组列显示来源字「字库·大」 |
| 拼音 | 由两个字的拼音拼成（`dà rén`），拼不出就显示「—」 |
| 操作 | 内置行只有「收进词库」；已收过的显示「已在词库」且不再给按钮 |
| 自建行 | 原样：编辑 / 删除 |
| 计数 | 「共 977 条：内置组词 969 条 + 我的词库 8 条」 |

拼音拼法是从字库两条字的 `p` 字段拼的，不另存——所以老师改了单字拼音，词拼音跟着变。

## 4. 踩到的坑

**① 窄屏被压成两行**。969 行塞进 400 px 宽，`table.grid{width:100%}` 会把列压到极限，
「收进词库」拆成"收进/词库"两行、「内置」拆成"内/置"。第一次改成 `min-width:600px` 横滚，
结果按钮被滚出屏幕右边（看不见等于没有）。最终解法：窄屏**隐藏「释义/例句」「图示」两列**
（内置词这两列本来就是空的），剩下 5 列正好塞下。

**② G1 护栏钉在旧结构上**。原护栏断言「`wordBank` 体内有 `STATE.chars`」，
派生逻辑迁到 `builtinWords` 后必然红。这是**改了设计**不是功能坏了，
按项目规矩改断言语义（`builtinWords` 体内有 `STATE.chars` + `wordBank` 复用 `builtinWords`），
检查项数不减，另外补了两条新护栏。

**③ 测试字库组词栏是空的**。smoke2 的 mock 只有 §19 临时注入了 8 个字的组词，
§20 直接继承，所以内置词只有 16 条——断言一律用 `builtinWords().list.length` 而不是写死 969。

**④ 截图共用浏览器数据目录**。三个场景用同一个 `--user-data-dir`，
localStorage 累积，第二张图显示「我的词库 3 条」（实际只点了 1 次）。
改成每个场景一个 `ud_<name>` 目录才干净。

- manifest 符号 118 → **123**
- 真机数据：内置词 **969 条**，词库页首屏即可见，拼音如「一个 yī gè」

## 6. 刻意没做

- **不提供"批量导入内置词"按钮**：会立刻造成两份词表分叉，正好是这一版要避免的
- **不让内置词直接编辑**：编辑就是"改字库的组词栏"，老师该去字库页改那个字，改完这里自动跟着变
- 三字词仍不进库（`红领巾/胖乎乎/为什么`），理由同 T-008
