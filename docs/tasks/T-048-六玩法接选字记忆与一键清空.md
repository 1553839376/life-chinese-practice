- 相关：`T-042`（v49 早读选字记忆，本任务把它推广到其余五种）、`T-030` / `T-031`（选字态与 `#pickBar`）

## 一、老师的原话

> 「4）把练习乐园的全部内容都实现，并在选字界面增加一键取消勾选的按钮，方便重新选字。」

范围问清了，老师选 **「全部玩法接选字记忆」**——戳泡泡 / 钓鱼 / 摘果子 / 喂小动物 / 听写 都跟早读一样记住上次那批字，不只是一次性。

---

## 二、键：早读单独一份，其余五种共用一份

```js
function pickMemKey(kind){ return kind === 'read' ? LS_READ_PICK : LS_PICK; }
```

| 玩法 | 键 |
| --- | --- |
| 早读 | `wb2_read_pick_v1`（v49 原键，**没换**，老师的旧记忆不丢） |
| 戳泡泡 / 钓鱼 / 摘果子 / 喂小动物 / 听写 | `wb2_pick_v1`（v52 新增） |

早读不跟着合并，是因为早读是「今天这一批跟读的字」、其他玩法是「今天要玩的字」，两件事的节奏常常不同；合成一份的话，老师上午早读挑了 6 个字，下午想玩钓鱼又变成那 6 个。

`readPickLoad()` / `readPickSave()` 改成薄包装，v49 的行为一个字没变。

---

## 三、一键取消：只清屏上的勾，不动记忆

`pickClear()`：

```js
PICK.list = [];
PICK.restored = false;
// 只把 .ch-card.sel 去掉并还原 aria-pressed
renderPickBar();
sfxTap();
toast('都取消了，重新点几个字吧');
```

**刻意不写 localStorage**：清空是「这次想重挑一批」，不是「以后都别预选了」；真清掉的话老师第二天进来还是空的，等于把 v49 / 本轮的记忆功能废掉。

`#pickClear` 在 `#pickCancel` 左边、没勾字时 `disabled`（`renderPickBar()` 里 `$('pickClear').disabled = !n;`）。文案用「清空」两个字——跟右边「取消」（退出选字态）区分开，原来的「全部取消勾选」和「取消」并排太像。

## 四、视觉（截图核对过两处）

- 选字条三个按钮：`清空 / 取消 / 开始练习（N）`，宽屏等分留白，窄屏 `@media(max-width:430px)` 一起收一档。
- 乐园「选项个数」控件原本落在七张玩法卡**下面**，截图上像个页脚、要滚到底才看得见 → 移到 `#gamePick` 内**最上方**，改成浅米底卡片（`.optn-bar.learn`）。

---

## 五、目标 / 非目标

**目标**：老师常用的那批字不用每次重勾；想换一批时一下清干净。

**非目标**：
- 不做「多套字单」（A 组 / B 组），老师没提。
- 不改「随便玩」（不挑字，本来就没有选字态）。
- 不动 `pickStart()` 之外的写入时机：勾了又取消、程序化调 `startGame()` 都不算一次选择。
