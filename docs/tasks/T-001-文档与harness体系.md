## 用户原话

> 先结合目前开发的 html 总结所有的功能点已完成事项，后续再和你进行聊天修改项目时，每一项任务都必须以 md 格式的文档记录日志和进展，以便跨越大模型上下文限制。
> 后续再进行项目迭代时都以成熟的 harness 机制驱动和记录文档驱动 agent 自闭环完成项目的开发和验收

## 目标

- 把已实现的全部功能点落成可查询的 md 文档
- 建立「跨上下文」的文档体系（快照 / 清单 / 日志 / 变更 / 任务卡）
- 建立可执行的 harness 门禁，让「完成」有客观标准

## 非目标

- 不改任何页面功能、样式、语音参数
- 不发布新版本（产物字节不变）

## 踩坑与根因

- `smoke2.js` / `check_lib.js` 必须显式传 HTML 文件名（用 `process.argv[2]`），否则 `readFileSync(undefined)` 崩
- jsdom 装在 managed node workspace，需设 `NODE_PATH`

## 回滚方式

删除 `docs/` 与 `harness/` 两个目录即可，不涉及页面代码。

## 遗留

- 后续新增功能必须同步登记到 `manifest.json`，否则门禁保护不到
