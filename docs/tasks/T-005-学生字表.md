| 项 | 值 |
|---|---|

| 建立日期 | 2026-10-22 |
| 关联版本 | v11 |

## 已定口径（用户 2026-10-22 选择）

1. **交互**：整组加入 + 逐字剔除。老师操作路径不变（还是先点组），展开后能点掉个别字。
2. **在学上限**：**第一版不做**。字表里有什么就练什么，不自动补位、不卡 6 个。
3. 底层**存显式字表**（不是存"排除表"），这样以后要加"跨组挑字 / 复制给另一个学生 / 在学上限"都不用再改结构。

## 数据模型

| 字段 | 含义 | 说明 |
|---|---|---|
| `stu.chars` | **字表，出题的真相源** | `['手','大','男']` |
| `stu.groups` | 字表来源标签，仅用于界面回显"这组选了几个" | 不再参与出题 |
| `stu.types` / `stu.count` / `stu.status` | 不变 | |

**迁移**：读到没有 `chars` 字段的学生时，按旧逻辑一次性展开并写回——
`groups` 有值 → 取这些组里所有 `on` 的字；`groups` 为空 → **空字表**（不展开全库）。
迁移前把 `localStorage['wb2_data_v1']` 复制一份到 `wb2_data_v1.bak-T005`，迁移只做一次并置标记位，避免每次启动重算。

**`charsOf(stu)` 改为**：只读 `stu.chars`，过滤掉已下线的字（`c.on === false` 或字库不存在）。
**删掉"空字表回退全库 700 字"这条分支**——这是当前最危险的默认值。

## 界面（老师端 · 学生编辑弹窗内新增「字表」分区）

```
字表            已选 24 个字        [ 搜索：手 / shou ]
┌──────────────────────────────────────────────┐
│ ▸ 第3册 · 第2单元        42 字 / 已选 38  [整组加入]│
│ ▾ 第3册 · 第3单元        36 字 / 已选 8   [整组移除]│
│    [手✓] [大✓] [男✗] [女✗] [人✓] [口✓] …          │
└──────────────────────────────────────────────┘
```

- 组头：册次·单元 + `组内字数 / 已选字数` + 整组加入 / 整组移除
- 展开：每字一枚 chip，选中=实心，未选=灰边；**点一下切换**（不做拖拽，单指可点）
- 搜索：输入汉字或拼音，跨组列出匹配项，点选即加入（不受折叠影响）
- 已选超过 40 字给黄色轻提示「字表有 42 个字，建议先教 20 个以内」，**只提示不阻止**
- 没有选任何字时，分区顶部显示「还没选字，这位同学暂时无法练习」

## 出题

- 练习页：字表为空 → `renderNoType` 同类文案「这位同学还没有字表，请老师先选几个字」，不出题、不朗读
- 题型仍按 `stu.types` 走，图字配对的可配对字不足 4 个的逻辑保持不变

## 风险

| 风险 | 处理 |
|---|---|
| 数据迁移写坏老师的名单 | 迁移前自动备份到 `wb2_data_v1.bak-T005`；迁移函数只读旧字段、写入新字段，不删旧字段 |
| 空字表导致「学生练不了」 | 老师端学生卡片上直接显示「字表：24 字 / 未选字」，一眼能看出谁没配 |
| 一次性大改难回滚 | 改动集中在 `p4.js`（charsOf + 迁移）、`p6.js`（学生表单）、`p1.html`（chip 样式）；三处各自备份 |

## 实现记录（v11）

### 落地顺序

1. `p4.js`：`isArr` / `charMap` / `expandGroups` / `migrateStuChars`，`charsOf` 改为只读字表
2. `p4.js`：`mergeCloudStudents` 在云端覆盖同名学生时**把本机 chars 带回来**（云端 schema 没有字表列，不带就会每次刷新丢）
3. `p6.js`：`STU_CHARS` / `STU_OPEN` / `STU_KW` 三个编辑态 + `renderStuChars` / `bindStuChars` / `stuCharGroupAll`
4. `p2.html`：把「练哪些字组」换成「学哪些字（字表）」分区
5. `p5.js`：`startQuiz` 加空字表 / 不足 4 字两条文案
6. `p1.html`：`.char-*` 样式（chip 最小 44×44）

### 挂载点

- `p6.js boot()`：`migrateCharset()` 之后调 `migrateStuChars()`（字库换代后才展开，组名才对得上）
- `p4.js loadAllData()`：云端学生合并 + 字库重建之后也要再迁一次

### 踩坑

1. **字库 700 条只有 561 个不重复字**（同字跨册重复 138 个）。字表按汉字存，所以
   组内计数必须走 `expandGroups`（已去重），否则组里 10 条记录但只有 8 个字时，
   「整组加入」按钮永远变不成「整组移除」。截图第一版就撞上了。
2. **云端学生没有字表列**。不处理的话每次刷新云端覆盖本机，字表被打回「按组展开」，
   老师今天剔掉的字明天又回来了。修法是在 `mergeCloudStudents` 里显式继承。
3. **迁移是一次性快照**：之后往字库新加的字**不会**自动进已有学生的字表。
   这是刻意行为（字表是老师明确决定的），smoke2 里有一条专门断言这个语义。
4. **旧测试依赖「空组回退全库」**：smoke2 预置学生 `字组: []`、check_pair 也一样，
   改成显式字表后这些用例立刻红。处理方式是给测试数据补明确分组/字表，
   不是把默认值加回来。
