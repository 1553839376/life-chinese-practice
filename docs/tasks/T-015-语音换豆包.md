## 用户原话（需求本体）

1. 「现在我感觉语音有点怪」
2. 「现有的晓晓大部分声音都还可以，但是涉及到**三声**的时候有点模糊不清，例如**耳、儿**，还有时候读**单字**的时候也偏快，很难让学生识别出来，如**江、京**」
3. 「我刚刚听了下**豆包**读的，读的特别好，每个音调都读的准确」
4. 「不要儿童绘本，我试听了不合适，主要还是读的**清晰准确**，不需要那些额外的情感加入，优先选择语音标准的音色」
5. 「**0.85** 的知性女声吧」

## 结论：不是引擎差，是「两次有损 + 低码率 + 单字太快」

- 老链路 `gen_tts.py` → `pack_audio.py`：edge-tts 出 48 kbps MP3，**再压到 24 kbps / 22.05 kHz**。
  单个汉字抠出来只有 **1323 字节**，高频细节全丢 → 必然发闷。
- 晓晓单字本身偏短促。而「快」不能看文件总时长：知性女声总时长比 Vivi 长，却是**尾部垫 0.3~0.5 s 静音 + 有效发音短 8%~25%**，听感就是「说得快、然后愣着」。

## 方案

| 环节 | v20（旧） | v21（新） |
|---|---|---|
| 引擎 | edge-tts `zh-CN-XiaoxiaoNeural` | 豆包语音合成 2.0 `zh_female_zhixingnv_uranus_bigtts`（知性女声） |
| 语速 | `rate=-10%` | `speed_ratio 0.85` |
| 中间产物 | 48 kbps MP3（有损） | **24 kHz 无损 WAV**（`encoding=wav`，原生采样率） |
| 成品编码 | 24 kbps / 22.05 kHz MP3（有损） | **48 kbps / 24 kHz AAC / mono / MP4**（只一次有损） |
| 静音 | ffmpeg `silenceremove` | 自研：头留 50 ms、尾留 150 ms |
| 响度 | 未统一 | RMS 归一到 -20 dBFS，限幅 -1 dB |
| 体积 | 3.95 MB | 12.85 MB |

**为什么不用 Opus**（同码率能省 25%）：`decodeAudioData` 在旧 Safari / iPad 上对 ogg-opus 不可靠。
课堂里「完全没声音」比多几 MB 严重得多。MP4 容器每文件约 1.3 KB 开销，可接受。

## 坑（已做成护栏）

1. **豆包接口偶发返回垃圾音频**：1691 条「0 失败」，但「到了」被拉成 3.21 s、「破了」2.99 s。
   → **「0 失败」≠「全对」**，必须按时长体检。`VERIFY=1` 是离线自检；顽固条目进 `TEXT_OVERRIDE`（「到了」写成 `到 了` 才回到 0.47 s）。
2. **`ogg_opus` 是虚高**：服务端给 48 kHz / 267 kbps，但模型原生只有 24 kHz，等于上采样；拿 `wav` 才是真无损母版。
3. **改预算 ≠ 删断言过关**：体积超了是因为**设计变了**（音质优先），处理方式是把新边界写进 `manifest` + 三份文档，而不是偷偷压回旧码率。
4. **判语速要看有效发音段**：`bounds()` 按 10 ms RMS 去首尾静音，别拿文件长度当判据。
