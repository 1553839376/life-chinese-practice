## 二、真 bug：备份把 v50 的表漏了

v50 把「跨天才算掌握」的日期存进了本机独立键 `wb2_solo_days_v1`，当时明确「不进导出导入」。可这条口径的后果是：**老师换电脑 / 清缓存前做了备份，恢复回来所有字又回到「只差一天就掌握」的状态**——老师以为备份是保险，其实少了一张表。

现在 `exportBackup()` 打包 8 项：

```js
{ v: 2, ts, students, chars, words, logs,
  solo: soloLoad(), review: reviewLoad(), wrong: wrongLoad(), readPick: … }
```

`importBackup()` 在 `repairCharWords()` 之后逐项写回本机键（`SOLO` / `REVIEW` / `WRONG` 三个内存缓存同时置回，`LS_READ_PICK` 直接 `setItem`）。

**仍然不进 STATE / 云端 schema**——备份是另一条通道，跟实时同步无关。

## 三、错字本：错一次就进本子，独立答对才出本子

| 项 | 定法 | 为什么 |
| --- | --- | --- |
| 键 | `wb2_wrong_v1`，按 `学生\|字` 记 `{ n, first, last }` | 跟学习记录同键格式，查起来不用再拼 |
| 进本子 | `wrongBookMark(key)`，在 `missOption()` 与 `logWriteMiss()` **各一处**（`html.count('wrongBookMark(r.key);') == 2`） | 点错选项、手写写错两条路都要记，漏一条就有一半错字进不来 |
| 出本子 | `gradeAnswer()` 里 `if (!STATE.quiz.wrongLogged) wrongBookClear(r.key);` | **独立答对**才出本子；靠提示 / 重试答对不算，否则点两下就洗白了 |
| 排序 | 次数多的在前，同次数按 `last` 新的在前 | 老师最想先看「一直错的」 |
| 结算页 | `wrongBodyHTML(restBook, '错字本里还有这几个，练对了会自动移出', '<button id="btnBookDrill">只练错字本这 N 个字</button>')` | 本轮错的字上面已经列过，这里只列**本子里剩下的**，不重复占地方 |
| 一键抽练 | 点按钮 → 填 `QUIZ_FOCUS` → `startQuiz(z.type)` | 复用 v11 就有的抽练机制，不新造一条出题路 |

最多列 12 个（`wrongBookList()`），空本子时整块不出现（不写「错字本是空的」凑数）。

## 四、目标 / 非目标

**目标**：备份真的能带走老师攒下的全部本机状态；错的字有一个地方能找回来、能一键重练。

**非目标**：
- 不动出题、`levelOf()`、`syncActive()`、在学名单。
- 错字本**不进进度分母**——它只是待办清单，不是第四个状态。
- 不加「清空错字本」按钮（老师没提；本子会自动变短）。
