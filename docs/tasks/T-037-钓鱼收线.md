# T-037 · 钓鱼：点对以后线真的把鱼钓上来

- **日期**：2026-11-05
- **版本**：v44
- **状态**：本地已完成、门禁全绿，**未发布**

## 一、起因

老师原话：

> 「做一下钓鱼的游戏优化，能不能在学生点对之后，这个钓竿的线拉到鱼上把学生钓上来呢」

现有实现（v9 起）是 `.fish.hit{animation:fishCatch}`：鱼自己往右上飘 186px、
转两下、缩到 0.22、淡出。左上角那根 `.rod` 从头到尾只是装饰——**线和鱼没有任何关系**，
孩子看到的其实是「鱼跳了一下不见了」，跟他自己做的那一下动作没关系。

## 二、做成什么样

一条完整的「钓」的动作，时间轴卡在 `gameAward()` 的 880ms 推进之内：

| 时刻 | 发生什么 | 实现 |
|---|---|---|
| 0ms | 竿尖甩出一条细白线，180ms 内长到鱼身上 | `.reel-line` 的 `scaleY .02 → 1`（`transform-origin:0 0`） |
| 0ms | 鱼停止游动，位置锁死 | `el.style.animation='none'` + `void offsetWidth` 再量坐标 |
| 180ms | 钩住：在鱼的位置炸 6 颗水花 | `.catch-splash`（沿用原有 keyframes） |
| 180ms | 线开始收短，鱼同时被拉到竿尖 | 线 `scaleY 1 → 6/len`、鱼 `translate(-ax,-ay) rotate(-14deg) scale(.34)`，两条 `cubic-bezier(.45,.05,.55,.95)` 540ms |
| 760ms | 线撤掉，鱼化在竿尖 | 清 `.reel-line`、鱼 `opacity → 0` |
| 880ms | `gameAward()` 照常推下一题 | 未改动 |

鱼篓里的那颗仍然由 `gameFx` 的 `GAME.caught++` 那一段加，`fishReel` 不碰计数，
避免「钓一条加两条」。

## 三、几何：为什么线能一直贴着鱼

```
tip    = .rod 盒子里钩子的位置（比例 116/150, 88/110，不写死像素）
ax,ay  = 鱼心 - 竿尖            ← 线的方向（竿尖 → 鱼）
len    = hypot(ax, ay)          ← 线长
deg    = atan2(ay, ax) * 180/π - 90   ← div 默认朝 +y，CSS 正角度是顺时针，所以减 90°
鱼的位移 = (-ax, -ay)           ← 鱼往竿尖走，正好是线的反方向
```

因为线缩短和鱼平移用的是**同一条缓动**，两个动作是同一个参数 p 线性耦合的：
线长 `len*(1-p)`、鱼距竿尖 `len*(1-p)`，所以线头永远落在鱼心上，不需要逐帧计算。

## 四、踩到的三个坑

### ① 方向写反（截图骗过了我两轮）

第一版写的是 `dx = tip.x - bx`（鱼 → 竿尖），却拿它当「竿尖 → 鱼」的方向去 `atan2`，
线朝反方向甩出了画面外。**为什么截图没看出来**：竿子上本来就画着一条 57px 的装饰曲线
（`M112 29 Q122 58 116 86`），它天然贴着左上角那条鱼，看起来非常像「线已经连上了」。
直到把「离竿尖最远的那条鱼」钩起来、发现一条线都没有，才回头去量数值：

```
line.height 必须 == hypot(ax, ay)
line.rotate 必须 == atan2(ay, ax)*180/π - 90
鱼的 translate 必须是 (-ax, -ay)
```

现在变量名直接叫 `ax/ay = 竿尖→鱼`，鱼写 `-ax/-ay`，G1 有一条护栏钉住这四个符号。

### ② 鱼一步都不走

`.fish` 挂着 `animation:swim 3.4s infinite`（浮动 ±20px）。CSS 关键帧的 `transform`
**优先级高于** inline `transform`，所以 `el.style.transform` 设了也白设。
必须先 `el.style.animation = 'none'`；而且停完要 `void el.offsetWidth` 强制重算再量坐标，
否则量到的还是「浮动中」的位置，线会差出一截（实测差 20~25px）。

### ③ 水花抢跑

原来 `gameFx` 里钓鱼和泡泡共用一段「点下就炸水花」，视觉上变成「鱼自己跳出水面」。
现在 `gameFx` 的钓鱼分支只调 `fishReel()`，水花挪到钩住那一帧（180ms）才炸。

## 五、验收

- 门禁 **167 项 0 红**（新增 8 条：三次贝塞尔且起点是竿尖 / 竿上旧线与浮标必须藏起来 / 方向符号 / 收线是等比缩放而不是缩 dasharray / 起手切线接着竿上那条线 / 中段下垂 / 停游泳动画 / 水花时机）
- smoke2 **721 项 0 失败**（§37 共 33 条：path 而不是 div、场上只有一条线、起点=竿尖、起手切线叉积≈0 且同向、
  线中点落在弦下方、dasharray=全长、缩放中心 translate·scale·translate、k 由「竿尖到浮标距离/弦长」算出、
  鱼位移=弦×(k−1)、缓动一致、水花时机、撤 svg、收完把竿上旧线与浮标放回来）
- 无头浏览器 1100×800 摆帧核对（`build/_mk_reel.py`）：p=0.15 / 0.55 / 0.92 三帧，**弧端到鱼心实测 2.7 / 2.7 / 2.8 px**（`getPointAtLength → getCTM` vs `getBoundingClientRect`），全程线端都贴在鱼身上、鱼朝竿尖移动
- **jsdom 没有布局**（rect 全 0），所以 §37 量的是「代码算出来的几何自不自洽」，
  真实坐标只能靠截图——这条已经写进测试注释，别再指望 jsdom 抓坐标错。

## 六、没做

- 没给鱼嘴加钩子图标：线从鱼心穿过、被鱼身挡住，看起来已经是「线搭在鱼身上」；
  要挂嘴上的话，缩放（0.34）会让线端和鱼嘴错开 30 多像素，得改成逐帧算，不划算。
- 没动另外三款游戏（泡泡、摘果子、喂食）的反馈，老师这次只点了钓鱼。

## 七、第二版：把直棍换成弧线（同日，被打回后重做）

老师看到第一版后的原话：

> 「这个逻辑不太对吧，应该是竿子上的线延长到把鱼钓上来，现在是一个自然的曲线拼接一个生硬的直线」

**问题是视觉语言不统一，不是动画没跑起来**：竿子上本来就画着一条 57px 的**弯**短线（`M112 29 Q122 58 116 86`），
我在它后面接了一根 3px 的**直**div，两截的曲率、端点切向、粗细都对不上，
所以读起来是「两样东西拼在一起」，而不是「同一条线变长了」。

**改法**：整条线换成一条 SVG `<path>` 的二次贝塞尔。

| | 第一版（被打回） | 第二版 |
|---|---|---|
| 线是什么 | `div`，3px 宽，直的 | `<path>`，二次贝塞尔弧线 |
| 起点 | 钩子 | 钩子（同一处） |
| 弯度 | 0 | 弦长 6%，最少 10px、封顶 40px，朝下弯（重力方向） |
| 收线 | `transform-origin:0 0` + `scaleY` | 整条弧以钩子为心**等比缩到 0.02**（`translate(钩子)·scale(k)·translate(-钩子)`），鱼位移 `弦×(k−1)` |
| stroke 与竿子那段 | 不一样（3px、带 box-shadow） | 一模一样（`#F4F0E4`、2.4px、圆头） |

**为什么这样连线头还贴着鱼**：两端（起点、终点）在数学上完全重合；弧本身跟着一起缩，所以「钩子 + k×弦」永远等于鱼心。

**这一版特意加的护栏**：「是弧线不是直棍」——控制点离弦中点的距离必须等于 `2×sag`，
且必须大于 8px。这条断言就是用来防「有人图省事又改回一根直线」的。

## 八、第三版：收线改成整条弧等比缩小（同日，自查后重做）

第二版虽然不再有「直棍」，但收线方式还是错的：**弧画死、`stroke-dasharray` 只让可见段消失，
鱼却沿弦走**。弧和它的弦之间差一个 `sag`（最多 40px），所以收到一半线头就跟鱼心分家了，
看着像线没搭住鱼——只是 540ms 太快、不加慢放看不出来。

| | 第二版 | 第三版（最终） |
|---|---|---|
| 弧 | 固定不动，只缩 `stroke-dasharray` | 以钩子为心等比缩 `scale(1 → 0.02)` |
| 鱼 | 沿弦平移 `-弦` | `弦×(k−1)`，和线同一个 `k`、同一条缓动 |
| 线头位置 | 沿死弧滑，中途偏出 `sag` | 永远 `钩子 + k×弦` = 鱼心，逐帧重合 |
| 收线初段 | `dasharray` 缩，视觉上是「线从鱼那头退回钩子」 | 弧整体缩，视觉上是「连鱼一起被拉过来」 |
| 线宽 | 跟着 path 长度走 | `vector-effect:non-scaling-stroke` 定住 2.4px |

`REEL_END` 取 **0.02 而不是 0**——`k=0` 会把 path 的 bbox 压成一点，某些浏览器直接不画。
最后 760ms 整块淡出，那 2% 的差看不出来。

## 九、第四版：两根线合成一根（同日，老师第三次点出来）

> 「钓竿上的线不应该出现两段。现在没有点击的时候钓竿上就有一条线，点击了之后又会出现另一条线。我觉得要把这两条线统一为一条。当点击时，钓竿伸出一条线，自然的有弧度的线去把鱼钓上来」

**不是画错，是起点定错**：竿子的 SVG 里本来就画着一条 57px 的短线（`M112 29 Q122 58 116 86`）
和一个黄色浮标（116,88）。前三版我都把钩子放在**浮标**上、从那儿甩出新线，于是场上同时有
「竿上那条短线」+「我新画的线」两根。

| | 前三版 | 第四版 |
|---|---|---|
| 起点 | 浮标（116,88） | **竿尖**（112,29） |
| 竿上那条短线 | 一直亮着 → 两根线 | 甩线时藏起来（`.rod-string`），收完放回 |
| 浮标 | 一直亮着 | 一起藏（`.rod-bob`） |
| 起手切线 | 从浮标往下 | **接着竿上那条线**（竿尖→控制点 122,58） |
| 形状 | 二次贝塞尔（一个控制点） | 三次贝塞尔（两头切线各自说了算） |
| 收线 | 固定 `k=0.02` | `k = 竿尖到浮标距离 / 弦长`（0.04~0.30），鱼停在浮标处 |

**为什么非要换三次贝塞尔**：二次曲线只有一个控制点，控制点同时决定两端的切线——
要接上竿上那条线的方向，就没法让收尾顺着弦接近鱼心（会拐出一个钩）。
三次曲线两个控制点各管一头：`C1 = 竿尖 + 竿上切线方向 × 弦长×0.30`、`C2 = 鱼心 − 弦方向 × 0.22`。

**又一次被 headless 骗了（这次记进 `_mk_reel.py` 注释）**：`.fish` 带 `filter:drop-shadow` 会被提到
独立合成层；只要我手动摆它的 `transform`（哪怕 `translate(0,0)`），截图里它按**旧帧**的像素画——
看上去「线悬在鱼头上方 50~80px」。同一帧把 rect 量出来只有 2.8px，是像素在骗人。
最后是靠「只点击、不摆帧」的副本（`_click_only.html`）才看清真实效果：一条线从竿尖垂到鱼身上。
