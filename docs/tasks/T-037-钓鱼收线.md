# T-037 · 钓鱼：点对以后线真的把鱼钓上来

- **日期**：2026-11-05
- **版本**：v44
- **状态**：本地已完成、门禁全绿，**未发布**

## 一、起因

老师原话：

> 「做一下钓鱼的游戏优化，能不能在学生点对之后，这个钓竿的线拉到鱼上把学生钓上来呢」

现有实现（v9 起）是 `.fish.hit{animation:fishCatch}`：鱼自己往右上飘 186px、
转两下、缩到 0.22、淡出。左上角那根 `.rod` 从头到尾只是装饰——**线和鱼没有任何关系**，
孩子看到的其实是「鱼跳了一下不见了」，跟他自己做的那一下动作没关系。

## 二、做成什么样

一条完整的「钓」的动作，时间轴卡在 `gameAward()` 的 880ms 推进之内：

| 时刻 | 发生什么 | 实现 |
|---|---|---|
| 0ms | 竿尖甩出一条细白线，180ms 内长到鱼身上 | `.reel-line` 的 `scaleY .02 → 1`（`transform-origin:0 0`） |
| 0ms | 鱼停止游动，位置锁死 | `el.style.animation='none'` + `void offsetWidth` 再量坐标 |
| 180ms | 钩住：在鱼的位置炸 6 颗水花 | `.catch-splash`（沿用原有 keyframes） |
| 180ms | 线开始收短，鱼同时被拉到竿尖 | 线 `scaleY 1 → 6/len`、鱼 `translate(-ax,-ay) rotate(-14deg) scale(.34)`，两条 `cubic-bezier(.45,.05,.55,.95)` 540ms |
| 760ms | 线撤掉，鱼化在竿尖 | 清 `.reel-line`、鱼 `opacity → 0` |
| 880ms | `gameAward()` 照常推下一题 | 未改动 |

鱼篓里的那颗仍然由 `gameFx` 的 `GAME.caught++` 那一段加，`fishReel` 不碰计数，
避免「钓一条加两条」。

## 三、几何：为什么线能一直贴着鱼

```
tip    = .rod 盒子里钩子的位置（比例 116/150, 88/110，不写死像素）
ax,ay  = 鱼心 - 竿尖            ← 线的方向（竿尖 → 鱼）
len    = hypot(ax, ay)          ← 线长
deg    = atan2(ay, ax) * 180/π - 90   ← div 默认朝 +y，CSS 正角度是顺时针，所以减 90°
鱼的位移 = (-ax, -ay)           ← 鱼往竿尖走，正好是线的反方向
```

因为线缩短和鱼平移用的是**同一条缓动**，两个动作是同一个参数 p 线性耦合的：
线长 `len*(1-p)`、鱼距竿尖 `len*(1-p)`，所以线头永远落在鱼心上，不需要逐帧计算。

## 四、踩到的三个坑

### ① 方向写反（截图骗过了我两轮）

第一版写的是 `dx = tip.x - bx`（鱼 → 竿尖），却拿它当「竿尖 → 鱼」的方向去 `atan2`，
线朝反方向甩出了画面外。**为什么截图没看出来**：竿子上本来就画着一条 57px 的装饰曲线
（`M112 29 Q122 58 116 86`），它天然贴着左上角那条鱼，看起来非常像「线已经连上了」。
直到把「离竿尖最远的那条鱼」钩起来、发现一条线都没有，才回头去量数值：

```
line.height 必须 == hypot(ax, ay)
line.rotate 必须 == atan2(ay, ax)*180/π - 90
鱼的 translate 必须是 (-ax, -ay)
```

现在变量名直接叫 `ax/ay = 竿尖→鱼`，鱼写 `-ax/-ay`，G1 有一条护栏钉住这四个符号。

### ② 鱼一步都不走

`.fish` 挂着 `animation:swim 3.4s infinite`（浮动 ±20px）。CSS 关键帧的 `transform`
**优先级高于** inline `transform`，所以 `el.style.transform` 设了也白设。
必须先 `el.style.animation = 'none'`；而且停完要 `void el.offsetWidth` 强制重算再量坐标，
否则量到的还是「浮动中」的位置，线会差出一截（实测差 20~25px）。

### ③ 水花抢跑

原来 `gameFx` 里钓鱼和泡泡共用一段「点下就炸水花」，视觉上变成「鱼自己跳出水面」。
现在 `gameFx` 的钓鱼分支只调 `fishReel()`，水花挪到钩住那一帧（180ms）才炸。

## 五、验收

- 门禁 **164 项 0 红**（新增 6 条：锚在竿尖 / 方向符号 / 只动 transform / 停游泳动画 / 水花时机 / 旧帧清掉）
- smoke2 **703 项 0 失败**（新增 §37 共 15 条：线在、挂在游戏场里、起点=竿尖、线长=距离、角度指回鱼、
  鱼停动画、鱼缩小、位移朝竿尖、水花时机、收线态、撤线）
- 无头浏览器 1100×800 摆帧核对：p=0 / 0.35 / 0.7 三帧，线端落在鱼身上、鱼朝竿尖移动
- **jsdom 没有布局**（rect 全 0），所以 §37 量的是「代码算出来的几何自不自洽」，
  真实坐标只能靠截图——这条已经写进测试注释，别再指望 jsdom 抓坐标错。

## 六、没做

- 没给鱼嘴加钩子图标：线从鱼心穿过、被鱼身挡住，看起来已经是「线搭在鱼身上」；
  要挂嘴上的话，缩放（0.34）会让线端和鱼嘴错开 30 多像素，得改成逐帧算，不划算。
- 没动另外三款游戏（泡泡、摘果子、喂食）的反馈，老师这次只点了钓鱼。
