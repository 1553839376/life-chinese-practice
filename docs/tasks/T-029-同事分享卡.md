# T-029 · 同事分享卡（二维码卡片）

- **日期**：2026-11-02
- **状态**：done
- **触发**：用户原话「生成一个分享给同事的生活语文汉字练习台二维码卡片」

## 一、要解决的问题

老师要把这个练习台推给同事（同为培智 / 特需班语文老师）。直接甩一条
`https://workbuddy.link/p/nU41kHmAoelqM2mGxWRFll` 过去有三个问题：

1. **链接长得像后台地址**，同事不敢点；
2. 没有上下文，同事不知道「这是什么、能干什么、要不要注册」；
3. 最关键的**进老师端的方法没人知道**——右上角「老师」要连点两下，
   不写字条的话同事点一下没反应，会以为坏了。

所以卡片必须一句话讲清：这是什么 → 怎么进去用 → 数据在哪。

## 二、产出

| 项 | 值 |
|---|---|
| 成品 | `生活语文练习台-分享卡-v34.png`（根目录，1040 × 1802，2 倍图） |
| 生成脚本 | `build/gen_share_card_v34.py`（改文案只改这一个文件） |
| 二维码内容 | `https://workbuddy.link/p/nU41kHmAoelqM2mGxWRFll`（官方发布短链） |
| 卡片文案 | 标题 + 副标题（认字乐园 / 班级练习 / 学生档案 / 老师端）+ 四宫格数字 + 二维码 + 网址 + 老师须知三条 + 版本脚注 |

四条数字都取自 `docs/STATE.md` 的资源规模表，**不手写**：700 字 / 22 册、9 种题型、每人一份字表、1695 条语音。

## 三、做法（为什么是 HTML + 无头截图）

卡片是排版活：圆角、字距、四宫格对齐、提示框底色。用 PIL 画一遍要自己算每个字的位置，
改一行文案就得重算；改用 HTML + CSS 写版面，再用本机 Chrome `--headless=new` 截图，
改文案只改 HTML 字符串。

**量高度这个坑**：`--screenshot` 只截视口，所以要先知道内容多高。
第一版量的是 `document.documentElement.scrollHeight`，在「视口比内容高」时它返回视口高度
→ 截出来底下拖了一大片空白（2226 px 的图，内容只到 1800）。
改成量卡片自身 `getBoundingClientRect().height + 44`（body 上下 padding 22×2）才准。

## 四、验收

- **二维码可解码**：`build/decode_qr2.js`（jsQR + pngjs）读成品 PNG →
  `https://workbuddy.link/p/nU41kHmAoelqM2mGxWRFll`，与期望完全一致。
- **小屏也扫得出**：`sips -Z 620` 缩到 358 × 620 再解码，仍 PASS（微信预览缩略图那种尺寸）。
- **版面无溢出**：肉眼核对截图，四宫格 / 序号圆点 / 页脚都对齐，卡片下边缘与图片下边缘留 22 px。
- 二维码用 `error='h'`（30% 容错）：打印出来有点脏、或者屏幕反光也能扫。

## 五、后续可改

- 想改文案：编辑 `build/gen_share_card_v34.py` 里的 HTML 字符串 → 重跑。
- 想换尺寸：改 `WIDTH`（CSS 像素）与 `SCALE`（倍率）。
- 发布新版本要更新卡片上的 `v34` 与数字（数字请回 `STATE.md` 的资源规模表核对，别抄上一版）。
