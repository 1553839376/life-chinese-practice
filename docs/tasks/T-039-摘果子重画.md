# T-039 · 摘果子重画：简笔画的树 + 果篮接果子

- **日期**：2026-11-05
- **版本**：v46
- **状态**：本地已完成、门禁全绿，**未发布**

## 一、起因

老师原话：

> 「接下来优化摘果子的游戏，首先要把树优化一下，这个不符合常见的树，有点宽。你可以模仿简笔画的那种树的样子来画。其实要摘苹果就要有个篮子，可以把果篮放旁边，摘一个就掉到果篮里」

三件事：树太宽、要像简笔画、要有果篮接住摘下来的果子。

## 二、"太宽"其实是两个原因叠出来的

| 原因 | 证据 | 改法 |
|---|---|---|
| 画布被拉伸 | `viewBox="0 0 400 250"` + `preserveAspectRatio="none"`，场是 1050×560 | 画布 320×300 + `xMidYMid meet` |
| 树冠本来就是扁的 | 9 团叶簇并成 348×138（**2.5:1**） | 10 团叶簇并成 250×198（**1.26:1**） |
| 树干比例不对 | 树干 126 单位高，占整棵树 60%，像一根杆子顶着一个绿饼 | 短粗（y=238→300）+ 上端分两叉 |

只改其中一个都会"看着还是宽"，所以要一起改。

## 三、树怎么画（`treeSVG()`）

- **画布**：`0 0 320 300`，`preserveAspectRatio="xMidYMid meet"`——等比，任何屏宽都不变形。
- **树冠 = 10 团叶簇的并集**（`crownClip`）：
  ```
  [160,118,80] [100,142,58] [222,140,58] [128,76,50] [200,74,50]
  [72,112,36]  [250,110,36] [120,178,44] [204,176,44] [160,168,40]
  ```
  最后一团（160,168,40）是这次补的：只有 9 团时底部中间比两侧高 26 单位，看着像"两条腿"。
- **轮廓线（简笔画那条边）**：先把同一组圆按 `r + 2.5` 整个涂成深绿（`#4E8B3A`），再把 `clip` 成并集的渐变矩形盖上去——落在并集内部的描边全被盖掉，只剩最外一圈。**不用手画闭合路径**，就不会有切线不接的折角。
- **树干**：底部 `M142 300 … L172 238`（上 30、下 36 宽），两根枝条 `M151 240 → 122 202` / `M169 240 → 198 204` 先粗深色打底、再细浅色盖上去（等于给枝条描了边），顶端伸进树冠被叶子盖住，接缝天然没有。

## 四、布局：为什么要有 `.tree-stage`

果子是 HTML 按钮、树是 SVG，两者要"挂在一起"就得共享同一套坐标。旧版果子网格用 `inset:2% 9% 46% 9%` 铺满整个**场**，所以树一变窄，果子就跑到树冠外面去了。

现在树 / 果子 / 果篮都装在 `.tree-stage` 里：

```css
.g-fruit{--gh:min(clamp(320px,calc(100vh - 250px),620px),80vw)}   /* 场高，必须在 .game-field 改时同步 */
.tree-stage{width:min(96%,calc(var(--gh) * 0.9)); aspect-ratio:320/300}
.fruit-wrap{inset:16% 20% 34% 20%}
```

- `--gh` 和 `.game-field` 的 `height/max-height` 是**同一条公式**（宽屏按高度缩、390 屏按 80vw 缩），改一处必须改另一处——G1 有护栏盯着这两条字符串。
- 舞台比例 = 树的画布比例（320/300），所以"果子挂在树冠的哪个位置"是像素级稳定的。
- 草地留在场这一层（宽屏时地平线要通到两边），果篮跟着舞台走。

## 五、掉果：写死的位移落不进篮子

旧 keyframes：

```css
@keyframes fruitDrop{ … 100%{transform:translate(96px,148px) rotate(30deg) scale(.5)} }
```

不管果子长在左上还是右下，都往右下同一个点飞。宽屏上那个点离篮子还有两百多像素，看到的其实是"果子掉到半路消失了"。

现在（`fruitDropTo()`，在 `gameRight()` 里**先算落点再加 `.hit`**）：

```js
var er = el.getBoundingClientRect(), br = bsk.getBoundingClientRect();
el.style.setProperty('--fd-x', Math.round(br.left + br.width / 2 - (er.left + er.width / 2)) + 'px');
el.style.setProperty('--fd-y', Math.round(br.top + br.height * 0.34 - (er.top + er.height / 2)) + 'px');
```

```css
@keyframes fruitDrop{
  0%{transform:translate(0,0) rotate(0) scale(1); animation-timing-function:cubic-bezier(.2,.8,.4,1)}
  16%{transform:translate(0,-18px) rotate(-10deg) scale(1.06); animation-timing-function:cubic-bezier(.55,0,.9,.5)}
  86%{opacity:1}
  100%{transform:translate(var(--fd-x,96px),var(--fd-y,148px)) rotate(26deg) scale(.42); opacity:0}
}
```

两段缓动＝「先被拽一下（慢出），再自由落体（渐快）」。`var(..., 默认值)` 是给 jsdom / 量不到布局时兜底——那种情况什么都不写，不会飞原地。

## 六、踩到的点

- **顺序**：`gameRight()` 里 `fruitDropTo(el)` 必须在 `classList.add('hit')` **之前**。反了的话动画第一帧读的是旧默认值，果子会先往右下角弹一下再回去。
- **拿不到布局要不要紧**：jsdom 的 rect 全是 0，`fruitDropTo` 直接 return，动画退回默认值——测试照样跑，只是测不到落点。落点只能靠无头浏览器量（`build/probe_fruit_drop.py`）。
- **headless 拍不到动画中间帧**：既不推进 CSS 时间，也不吃负 `animation-delay`。要看"飞在半路"的样子只能摆帧；而 `.fruit` 带 `filter:drop-shadow(...)`，是独立合成层，摆帧后截图仍按旧像素画（v44 钓鱼踩过三次），所以摆帧时先把 `filter` 摘掉。
- **果子尺寸别用百分比**：`.fruit-wrap` 只有舞台的 60%，百分比会跟着缩，宽窄屏差太多。改成跟着视口（`clamp(78px,9.4vw,104px)`），字用同一条曲线。

## 七、验收

- 门禁 174 → **181 项**：画布等比（且禁止 `preserveAspectRatio="none"`）/ 树冠比例 / 树干分叉 / 舞台包住树果篮 / 场高同公式 / 落点走真实坐标且先算后飞 / keyframes 用变量。
- 测试 927 → **956 项**，smoke2 756 → **785**（新增 §39 共 29 条）。
