# T-034 · 游戏结算按「一次就点对」算正确率

- **日期**：2026-11-04
- **版本**：v39
- **状态**：已发布（v39 随 v40 一起上线，newVersion 28，2026-11-04）

## 一、用户需求（原话）

> 「有一个问题，就是在游戏的时候如果点错了后来再点对，最后还是显示100%正确率，有点不对把」

先确认了一件事：**游戏结算页其实没有「正确率」这个数字**，只有「找到 8 / 8 个」+ 三颗星 + 满分。
老师嘴里的「100%」就是那个「8 / 8」。所以这不是「百分比算错」，是**游戏根本没有把答错记进结果**。

## 二、根因

`p7.js` 原来的记账：

```js
function gameRight(el){
  GAME.combo++; GAME.done++;                        // 答对就 +1
  GAME.score += 10 + Math.min(GAME.combo - 1, 5) * 2;
}
function gameWrong(el){
  GAME.miss++; GAME.combo = 0;                      // 只记 miss，不扣分、不减 done
}
function gameQuestion(){
  GAME.miss = 0;                                    // ← 每换一题就清零
}
function gameOver(){
  var stars = (done >= total) ? 3 : ...;            // 只看 done
  '找到 ' + done + ' / ' + total + ' 个，得了 ' + GAME.score + ' 分'
}
```

- `GAME.miss` 是**每题**计数器，换题清零 → 「这一题错了几次」这个信息在结算时已经没了；
- `GAME.done` 只数「这一题最后点对了没有」→ 错一遍再点对，和一次点对完全等价；
- 结算星数只认 `done >= total`，而这个条件**一局打完必然成立**（`gameOver()` 只在队列走完时调用）。

结论：一局里错三遍再对，结算照样是「全部找到啦 + 三颗星 + 满分」。

## 三、口径（已与老师确认）

给了三条口径，老师选的是**第一条**：

> 「错过的就不算对（正确率下降）」

| 项 | 旧 | 新 |
|---|---|---|
| 记账 | `done` 一个数 | `oneTry`（一次就点对）+ `retried`（试过才找到），`done` 保留为「找到几个」 |
| 正确率 | 没有 | `Math.round(oneTry * 100 / total)` |
| 星数 | `done >= total` 三星 | `rate >= 90` 三星 / `>= 70` 两星 / `>= 40` 一星 |
| 标题 | 一律「全部找到啦！」 | 只有 100% 才「全部一次就找到啦！」 |
| 副标题 | 找到 N / M 个，得了 X 分 | **正确率 83% · 得了 90 分** |
| 注脚 | 无 | `.go-note`：「找到 6 / 6 个，有 1 个是试了才找到的」（全对时「全是一次就找到的」） |

**分数不动**：答错本来就 `combo = 0`，连击奖励自然没了；`10 + min(combo-1,5)*2` 这套照旧。
老师要改的是「结算结论」，不是把游戏变成扣分游戏。

**六题一局错一个 = 83% → 两颗星**（8 题一局错一个 = 88%，也是两颗星）——错一个就掉一颗星，是刻意的。

## 四、刻意不与练习结算页统一

练习（9 种题型）是 v22 的宽松口径：错过的题重试答对仍记「独立答对」，正确率照给，
只在下面补一行 11.5px 灰字「其中 N 题是试了再答对的」。那套是**测评**，重试本身是设计的一部分。

游戏是**玩**，老师要的是数字别骗人。两处口径不同，各有各的理由。下次谁想「顺手统一」，
先回来看这一节和 `03-变更日志.md` 的 v39 条目。

## 六、验收

`smoke2.js` §34（14 条，全绿）：

1. 点错记一次 `miss`；
2. 点错不推进题目、还能接着点；
3. 试过才找到的不算「一次就对」（`oneTry=0` / `retried=1`）；
4. 一局打完出结算框；
5. 结算页直接报「正确率」，不再只写「找到 X / X 个」；
6. 正确率按「一次就对」算（6 题错 1 → 83%）；
7. **不再是 100%**（老师报的就是这个）；
8. 错一个就掉一颗星（2 颗）；
9. 标题不再一律「全部找到啦」；
10. 注脚写明「有 1 个是试了才找到的」；
11. 一次就全对仍是 100%；
12. 一次就全对给三颗星；
13. 一次就全对的标题「全部一次就找到啦！」；
14. 没有试出来的就写「全是一次就找到的」。

门禁 G1（4 条）：`gameRight` 必须按 `GAME.miss > 0` 分账 / `gameOver` 必须按 `oneTry` 算正确率 /
不许再出现「全部找到啦！」/ `.go-note` 样式与节点都在。

门禁 145 → **149 项**，测试 798 → **812 项**（smoke2 627 → 641）。

## 七、踩过的坑

- **别在 `GAME.queue` 的题对象上打标记**：`GAME.queue` 是 `STATE.chars` 里那些字对象的引用
  （`startGame` 里 `base = shuffleArr(chars)` 直接推同一个对象），写 `q.retried = 1` 会污染字表、
  甚至被 `saveSnap` 存进本机数据。所以「这一题错没过」只能读 `GAME.miss`，不能往题上写字段。
- **`GAME.miss` 不能再当成「这一局总共错了几次」用**：它每题清零，正因为它每题清零，才正好能当
  「这一题错没过」的判据。要记全局次数得另开字段（这次用 `retried`）。
- **测试里别等 880ms**：`gameRight()` 用 `GAME.timer` 延时推进下一题，一局 6 题全等要 5 秒多。
  测试改成 `w.GAME.i = i; w.gameQuestion(); w.clearGameTimer();` 手动摆位，14 条断言 1 秒内跑完。
