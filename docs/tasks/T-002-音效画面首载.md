## 用户原话

> 还有几个需要优化的地方，1.优化正确反馈音效，目前的音效不够直接，尤其是正确的音效，听起来反而像错误的。2.优化游戏逻辑和画面：目前的游戏主题不错，但是画面需要优化，特别是操作后应该有一些对应的变化，这一部分可以不用这种扁平的画风 ，戳泡泡还好，但是其他的就显得有点生硬。首次加载优化

## 目标

### A. 音效（正确/错误必须一听就分得清）
- 正确：明亮上行大三和弦「叮咚」，300ms 内完成，**合成优先（零解码延迟）**
- 错误：低沉温和下行两音，明确但不可吓人
- 连对：音高随连击数递进，比固定音更有「越玩越顺」的反馈

### B. 游戏画面（不要扁平，操作后必须有对应变化）
- 钓鱼：鱼有渐变鳞光、水层光柱、鱼竿鱼篓；钓中 → 鱼上浮转向 + 水花 + 飞进鱼篓 + 篓内计数 +1
- 摘果子：树冠分层受光、果子有高光与叶；摘中 → 果子落下 + 树摇 + 落进篮子 + 篮内计数 +1
- 喂小动物：食盆质感、草地；喂中 → 食物飞进嘴里 + 咀嚼 + 爱心 + 肚子计数 +1
- 戳泡泡：保留，补破裂水花碎片
- 通用：答对在点击位置飘「+10」，场景右上角有战利品计数

### C. 首载优化
- 语音包不阻塞首屏渲染（惰性解析）
- 首屏可见骨架/进度提示，避免白屏
- 给出体积与耗时实测对比

| DCL · 惰性 JSON | — | 188 ms | `perf_probe.py` 默认变体 |

**首载结论（如实记录，不夸大）**：本地 `file://` 下惰性 JSON 比内联 JS **慢约 14 ms**（多一次 `getElementById` + `JSON.parse`）。真实收益只体现在慢网络与低端机——4 MB 不参与脚本编译，主线程不必等它。这个差别在本机量不出来，**不能拿本地数字当战果**。

## 踩坑

1. **改音效后 `e2e_av` 报「播了 0 段」**：mock 只统计 `bufferSource`，合成走 `oscillator`。修：mock 补 `createOscillator.start(){ srcCount++ }`。
2. **游戏读题偶发多念一遍 / 上一局声音串到新局**：`gameQuestion` 里的读题 `setTimeout` 没挂 `GAME.timer`，旧定时器在新局又触发。修：挂上 `GAME.timer` + `readAsk` 加 `GAME.locked` 守卫 + `GAME.i !== gi` 校验。
3. **练习页的延时读题串进游戏页**（`q_same` 混进 fish 队列）：`readQuestion` 加 `$('scrPlay').hidden` 判断。
4. **食盆上的字被碗形 `::before` 盖住**：字改包 `<span class="plate-ch">` 且 `z-index:3`，碗高降到 52%。
5. **树冠盖住树干像一颗大土豆**：`.tree-trunk` 提到 `z-index:2`，三块树冠收高（82%/54%/42%），`.a` 用不规则 `border-radius`。
6. **喂鱼给鱼很怪**：`FEED_ANIMALS` 移除 `'鱼'`，一局固定一只动物。
7. **先发布了才发红**：首次 commit 后才发现 `e2e_av` 时序 bug → 没有沿用 v7 发布态，重建事务上传修好的产物、commit 为 v8。**教训：门禁必须在 commit 之前跑完。**
