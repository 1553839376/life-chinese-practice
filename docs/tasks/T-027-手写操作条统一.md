# T-027 · 手写操作条统一（v33）

> 提出：2026-11-02　交付：2026-11-02　版本：v33
> 关联：`T-026`（橡皮擦图标与「擦掉」常显）、`T-025`（结算页胶囊按钮，同一次「别再铺满整行」的判断）

## 一、老师原话（配两张截图）

> 「你觉得这个样式好看吗？乱七八糟的很丑。」（练习页手写题底部：大绿按钮 + 右边一句小字 + 下面一排小白按钮）
>
> 「这再看一遍和擦掉的文本框为什么还搞的不一样？」（乐园描写屏底部：三个按钮三种长相）

## 二、两张图，其实是同一个病根

拆开看是两件事，往根上追是同一件：**同一个动作在两个界面里各用了一套按钮**。

| 界面 | 「再听/再看」 | 「擦掉」 | 主按钮 |
|---|---|---|---|
| 乐园描写屏 | `.secondary`：2px 边 / 半径 12 / 高 44 / 15px 字 | `.ghost-btn`：1.5px 边 / 半径 12 / 高 44 / 15px 字 | `.wg-main`：半径 20 / 高 64 / 宽 ≥200 |
| 练习 · 听写 | `.ghost-btn` | `.ghost-btn` | `.wg-main`：宽 ≥280 / **另起一行**，右边挂一句 13px 小字 |
| 练习 · 描红 | `.ghost-btn`（写「念一遍这个字」） | `.ghost-btn`（写「擦掉重描」） | `.wg-main`：宽 ≥280 / **另起一行** |

于是：

1. **「文本框长得不一样」**——边宽 1.5 vs 2、圆角 12 vs 20、高度 44 vs 64，紧挨着摆当然不像一套。
2. **「乱七八糟」**——练习页把「绿按钮 + 一句小字」当一组 `justify-content:center`，绿按钮被那行字挤到盒子左边；下面再一排小白按钮居中。一屏里三个对齐线，谁也没对齐谁。
3. 顺带还有**同一个东西三种叫法**：「擦掉」/「擦掉重写」/「擦掉重描」；主按钮在描红里叫「描完了」、在乐园里叫「写好了」。

## 三、改法

### 1. 一条操作条 `.hw-acts`，一套按钮 `.hw-btn`（`p1.html`）

```css
.hw-acts{display:flex;align-items:center;justify-content:center;gap:12px;flex-wrap:wrap}
.hw-btn{display:inline-flex;align-items:center;justify-content:center;gap:7px;
  min-height:56px;padding:0 22px;border:1.5px solid var(--line2);border-radius:16px;
  background:#fff;color:var(--ink2);font-size:17px;font-weight:800;white-space:nowrap;
  box-shadow:0 3px 0 #E9E1CD}          /* 白按钮也垫一道实色：和绿按钮同一套「实体键」语言 */
.hw-btn.main{min-width:min(150px,40vw);padding:0 26px;border:none;border-radius:16px;
  background:linear-gradient(180deg,#43C878,#2C9F58);color:#fff;font-size:20px;
  box-shadow:0 4px 0 #1F7A42,0 10px 16px rgba(34,122,67,.18)}
```

- **顺序固定**：`再听/再看一遍` → `擦掉` → `写好了`。主按钮永远在最后一个，两个界面手指记住的位置一样。
- **主按钮只比旁边宽一圈**（`min-width:150`）。v31 在结算页踩过「`width:100%` 铺满整行，很长很生硬」的坑，这里不再犯。
- **`.ico-i` 继续用**，但不再需要 `.ghost-btn.with-ico` 那个补丁类——`.hw-btn` 天生是 `inline-flex` + 7px 间距。

### 2. 一处生成（`p5.js`）

```js
function hwFootHTML(mainTxt, tip){
  return (tip ? '<p class="hw-tip">' + esc(tip) + '</p>' : '') +
    '<div class="hw-acts">' +
      '<button type="button" class="hw-btn" data-wg-act="say">再听一遍</button>' +
      '<button type="button" class="hw-btn" data-wg-act="clear">' + ICO_ERASE + '擦掉</button>' +
      '<button type="button" class="hw-btn main" data-wg-act="done">' + esc(mainTxt) + '</button>' +
    CLOSE('div');
}
```

`renderDictation` / `renderTrace` / `wgFootWrite` / `wgMiss` 都调它；判分那一步换成 `写对了 / 没写好，重写` 两个也走 `.hw-acts`。

`wgToolsShow()` 删掉——v32 那套「点完「写好了」藏起工具按钮、点「没写好」再显示回来」是因为按钮分两排才需要的，现在整条一起换，不需要了。

### 3. 那句说明搬到按钮上方（`.hw-tip`）

```
[田字格] [田字格]
   写完点这里，我们一起看对不对        ← .hw-tip（14px 灰字，居中）
 [再听一遍] [擦掉] [写好了]            ← .hw-acts
```

### 4. 文案统一

| 位置 | 原来 | 现在 |
|---|---|---|
| 乐园 擦掉 | 擦掉 / 写完变「擦掉重写」 | **擦掉**（不随状态变） |
| 听写 擦掉 | 擦掉重写 | **擦掉** |
| 描红 擦掉 | 擦掉重描 | **擦掉** |
| 描红 主按钮 | 描完了 | **写好了** |

「再听一遍 / 再看一遍」**保留差别**：练习里是重放读音，乐园描写屏是重放笔顺动画，是两个功能；只是按钮终于长得一样了。

## 五、踩的坑

1. **护栏判旧类名要避开注释**。第一版写 `'wg-main' not in html`，被 CSS 注释里「主按钮用 64px 的 `.wg-main`」命中，假红。改成只判 `class="wg-main"` / `.wg-main{`。
2. **判「不许再出现某句文案」同理**。注释里写着「原来是擦掉重写」也会命中，改成只判 JS 字符串字面量（`'擦掉重写'`，带 ASCII 引号）和 `>擦掉重写<`。
3. **字符串拼接要按真实代码写**。`"ICO_ERASE + '擦掉'"` 少了半截 `</button>`，永远匹配不上，白红一次。
4. **媒体查询里的旧类名容易漏**。`.wg-tip{display:none}` 是 v25 时代窄屏藏提示用的，类名早换了，护栏抓出来后删掉。
5. **`.hw-btn.main` 靠继承圆角视觉一样、护栏看不出**——显式写 `border-radius:16px` 更省事。

## 六、遗留

- 「再听一遍」在描红练习里其实是「念这个字」（不是重放上一句），文案仍然只是「再听一遍」。老师若觉得不够具体，可改成「再念一遍这个字」，但那会让三个按钮宽度不一致，要再量一轮。
- 判分态两个按钮宽度几乎相等（150 / 148），层级只靠颜色区分。若老师反馈「孩子分不清哪个是走」，把 `.main` 的 `min-width` 提到 180 即可。
