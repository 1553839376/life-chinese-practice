# T-007 · 老师端"按钮点了没反应"（v13）

| 项 | 内容 |
|---|---|
| 用户原话 | 「你设置的一些按钮不能使用，比如新增汉字」 |
| 状态 | done（2026-10-22，v13 已上线） |
| 影响面 | 老师端全部新增/编辑表单（学生、汉字、词语） |
| 根因 | **不是按钮坏了，是表单被顶到页面最底下** |

## 1. 症状与实测

jsdom 里点「新增汉字」一切正常（`libForm.hidden=false`、保存能落库），所以先怀疑是"看不见"而不是"不工作"。
用 headless 加上位置探针量了一下：

```
字库 700 行 → .list-wrap 高 44142 px（没有 max-height，表格把整页撑开）
文档总高 44676 px
「新增汉字」按钮 top = 392
表单 #libForm top = 44628      ← 离按钮 44190 px
```

结论：`openWordForm()` 确实把表单打开了，但表单排在 700 行表格**后面**，老师点完按钮，
浏览器什么都没动，看起来就是"按钮没用"。学生表单、词库表单是同一个写法，同一个毛病。

## 2. 改了什么

| # | 改动 | 说明 |
|---|---|---|
| 1 | 字库/词库列表改为**容器内滚动** | `#tpLib .list-wrap,#tpWord .list-wrap{max-height:min(56vh,620px);overflow:auto}`；表头本来就 `position:sticky`，正好配 |
| 2 | 三个表单整体**移到列表前面** | 学生 / 汉字 / 词语；G1 加了一条断言钉住 DOM 顺序（表单 index 必须小于 tbody index） |
| 3 | 打开表单后 `revealForm()` | `scrollIntoView({block:'center',behavior:'smooth'})` + 340ms 后 `focus({preventScroll:true})` 首个输入框 |
| 4 | 表单变成"卡片" | 米黄底 + 琥珀描边 + 阴影，一眼看出这是正在填的东西，不是列表的一部分 |
| 5 | 保存/取消行**粘在视口底部** | 学生表单要滚好几屏（字表 22 组），`position:sticky;bottom:6px` |
| 6 | 校验失败时**高亮出错控件** | `markField()`：滚进视线 + 红框 + 抖动，姓名框/题型区各自定位；不再只弹一条 2.6 秒就消失的 toast |
| 7 | **重复字/词拦截** | 新增时若字库已有同字，提示"直接点它的编辑"；`charMap` 是按字查的，重复会让出题池出现重复项 |
| 8 | 保存后**保住滚动位置** | `_lwQuery` 记住筛选条件：条件没变就恢复 `scrollTop`，改了搜索词才回顶部 |

## 3. 踩到的坑

**① `requestAnimationFrame` 在 headless 里可能不跑**
`revealForm` 最初用 rAF 再滚动，探测发现"滚不滚"取决于有没有渲染帧。改成 `setTimeout(go, 0)`，
在任何环境都执行。**凡是"必须发生"的副作用，别挂在 rAF 上。**

**② jsdom 里 `offsetTop` 恒为 0**
smoke2 里想断言"表单在列表上面"，jsdom 没有布局，量不出真实位置。改成两个层面测：
DOM 顺序由 G1 静态检查（字符串 index）+ smoke2 只测行为（表单展开、能保存、拦得住）。

**③ G4 逐块比对会错位**
线上比本地多一个平台注入的 `inject.js` script 块。上一版只过滤了本地侧的空块，
索引对不上 → 明明内容一样却报 DIFF。**两边都要过滤空块再比。**

**④ 变量名撞车**
smoke2 是一个巨型 async 函数，`const libRows / before2` 和旧章节撞名，直接 SyntaxError 起不来。
新章节统一加 `v13_` 前缀。
