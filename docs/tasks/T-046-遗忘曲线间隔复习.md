# T-046 · 遗忘曲线：按 1 / 3 / 7 / 15 天把学会的字拉回来复习

- 版本：v52（2026-11-13）
- 状态：✅ 已交付 ／ 门禁全绿 ／ GitHub 已同步
- 相关：`T-043`（v50 跨天掌握）、`T-013` / `T-014`（今日字卡与主页的字单来源）、`T-021`（题型进度，同为本机键）

---

## 一、老师的原话

> 「2）为汉字练习增加类似遗忘曲线的出题逻辑，学生学会后间隔若干天仍会重新进入该字的练习，以便及时巩固，并按此逻辑选择出题汉字。」

间隔档给了三个选项，老师选 **「1/3/7/15 天（推荐）」**。

---

## 二、口径：Leitner 五个盒子，到期才回来

```js
var REVIEW_GAPS = [1, 3, 7, 15];
var REVIEW_PER_DAY = 2;
```

每个 `学生|字` 记 `{ box, due, n, last }`：

| 情况 | 动作 |
| --- | --- |
| 独立答对 | `due = dayAdd(GAPS[box])`，然后 `box = min(3, box+1)` |
| 答错 / 靠提示 / 描红 | `box = max(0, box-1)`，`due = dayAdd(1)` |
| `box` 到顶 | 仍每 15 天回来一次，**不设「毕业」** |

**顺序要紧：先取当前 `box` 定到期日，再 `box+1`**。反过来的话第一次答对就直接排到 3 天后，第 1 天那一档永远用不上。

`reviewDueChars(stu)` 只取到期且**今天还没排过**的字（`if (r.last === day) continue;`）——一轮里 9 个题型都从同一批字出题，不去重的话同一个字一天内被排进四次复习。

---

## 三、怎么进到题里

`todayChars()` 把到期复习字**接在在学字后面**，上限 `REVIEW_PER_DAY`：

```js
due = reviewDueChars(stu);
for (i = 0; i < due.length && i < REVIEW_PER_DAY; i++){ … out.push(map[due[i]]); }
```

- 不改 `levelOf()` / `syncActive()` 一行：复习字**不占在学名额**（`stu.count` 那 3–10 个还是在学的），它是额外拉回来练的。
- 今日字卡上多一个 `.pre-card.due` 标记、标题写「· 要复习 N」；主页多一句 `.home-note.due`。
- 抽练（`QUIZ_FOCUS`）仍然优先——复习字只在没抽练时才有机会进。

---

## 四、为什么不写进学习记录

`reviewMark()` 只动 `wb2_review_v1`，**不碰 `STATE.logs`**。

理由：`alone` / `wrong` 是「这字学得怎么样」的账，复习答对一次就再 +1，会把 v50 那套「跨天两个独立日」的判定搅乱；而复习的目的只是「别忘了」，不是重新评一次级。老师要看复习情况时看字卡上的「要复习 N」。

---

## 五、目标 / 非目标

**目标**：学会的字在 1 / 3 / 7 / 15 天这四个点回来一次；一天最多回来 2 个，不把当天的在学任务挤掉。

**非目标**：
- 不做「复习专用题型」——就用现有 9 个题型。
- 不做闹钟 / 提醒横幅（老师没提）。
- 不进云端 schema、不进进度分母。
