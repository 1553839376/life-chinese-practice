# T-020 在学名单补不满（上限 8、字表 28、在学只剩 1）

- 报障人：老师（2026-10-29，两张截图）
- 影响：**v19 – v26 所有版本**，只要「先建学生、后补字表」就会中
- 状态：已修（v26，未发布）

---

## 一、现象

截图一（学生档案表单）：在学字数 **8**、已选 **28** 字。
截图二（学生主页）：已学会 **1**、还在排队 **26**、正在学 **1**，「今天练这 **1** 个」只摆了一个「女」。

三个数字加起来正好 28，说明字表没丢、记录没丢，就是**在学名单只剩一个字**。

老师原话：「为什么会出现一天只有一个字的情况，我设置的是八个字，也有待学的很多字」。

## 二、复现

`build/_probe_active.js` 三条路径，全部复现：

| 路径 | 操作 | 期望 | 实际 |
|---|---|---|---|
| A | 字表 1 个字时建学生（上限 8），后来把字表补到 28 字 | 8 | **1** |
| B | 字表 28 字，上限先填 1，再改成 8 | 8 | **3** |
| C | 上限 8 建好，临时改 1，再改回 8 | 8 | **3** |

A 就是老师遇到的：**先建学生（字表只勾了 1 个），回头再补字表。**

## 三、病根

`syncActive()`（`build/p4.js`）里补位额度是这么算的：

```js
var quota = first ? cap : dropped;   // dropped = 这一轮「练到已掌握」让出的名额
```

也就是**只认「学会让出」这一种空位**。另外两种空位它不认：

- 字表后来变大（从 1 个字补到 28 个字）→ 新字永远进不来；
- 在学字数被调大（1 → 8）→ 名单不长；
- 顺带：上限被调小时 ① 循环 `out.length < cap` 会把多出来的直接丢掉，调回来也找不回。

v19 这么写是有原因的：如果无条件补满，老师点「移出在学」后字立刻被补回来，那个按钮等于没做。
问题在于**它没有别的办法区分「老师手动移出」和「字表变大」**，只好一刀切都不补。

## 四、改法

1. **`off` 名单**：`actDel()` 移出时把字记进 `stu.off`；`actAdd()` 加回来时从此表删掉。
   `offList(stu)` 读它。
2. **`syncActive()` 补满**：① 照旧保留在学、剔掉已掌握的（锁定的除外）；
   ② 只要 `out.length < cap` 就从 `stuProfile().focus` 依次补，**跳过 `off` 里的字**。
   额度不再只算 `dropped` —— 三种空位一视同仁。
3. **`mergeCloudStudents()`**：云端 schema 没有 `off` 列，和 `chars` 一样从本机带过来，
   否则刷新一次就忘了「这个字别再补」。

新语义：**在学字数就是手上练的字数，永远补满；「移出」＝这个字别再自动进来，名额换别的字。**

## 五、验收

| 场景 | 结果 |
|---|---|
| A 字表 1 → 28 字 | 在学 **8** ✅ |
| B 上限 1 → 8 | 在学 **8** ✅ |
| C 上限 8 → 1 → 8 | 在学 8 ✅（中间掉到 3 是下限，正常） |
| 移出一个字 | 名单仍 10（换个字补上），被移出的不在名单里、进了 `off` ✅ |
| 手动加回来 | 排最前、从 `off` 删除、下一轮还能自动补 ✅ |
| 已掌握的字拉回来复习 | 自动锁定（否则下一轮又被踢出去）✅ |

- 门禁 **64 项 0 红**，测试 **513 项**（smoke2 334 → 344，新增 10 条钉住上面这些）。
- 老数据不用迁移：没有 `off` 字段就当空表，下次渲染自动补满。

## 六、留下的

- 老师如果以前「移出」过某个字，那时没有记录，升级后会重新补进来一次；再移出一次就会记住。
- 「移出＝换字」是这次定的口径。如果老师其实想要「移出后手上就少一个」，得改成「目标 = cap − `off` 个数」，
  先问再动。
