## 二、逐项方案

### 问题 1：单字发音不清（三声 vs 二声）

**根因**：不是录音坏了（8 个文件的 md5 各不相同、时长正常），是**孤立单字的声调本来就不完整**。
TTS 念单字时，三声没有后续音节，声带不会真的"升上去"；二声本来就是升调。两者在孤立状态下都偏"平"，差别被压薄了。

**可选修法（可以叠加）**

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A 换音色** | 生成几个候选（云希/云扬男声、晓伊女声）对比 | 可能某音色的三声更明显 | 用户 2026-10-21 已定「晓晓」，换音色要重新确认；1691 条全部重生成 |
| **B 单字放慢** | 单字 `rate=-30%`（其余保持 -10%） | 声调轮廓拉长，更容易听出升降 | 单字录音要重生成（701 条），约 3 分钟 |
| **C 单字读两遍** | 「耳。耳。」（两遍之间留 0.6 s） | 两遍都听不清的概率低 | 与「目标字只念一遍」的既有约定冲突（那条是**读题**时的要求，字卡点读是另一回事，但容易让人混淆） |
| **D 字卡加「听词语」** | 字卡上多一个小按钮，念该字的组词（耳朵）——词语有语境，声调完整 | 不改任何录音，972 条整词现成 | 只是辅助，单字本身仍不清楚 |
| **E 三声字单独处理** | 只对三声字用 B/C，其余不动 | 精准 | 需要标拼音声调（已有 `p` 字段，但部分字没有拼音） |

**我的建议**：先做 **B + D**（单字放慢 + 字卡能听词语），这两个不用换音色、不用改约定，成本最低。

### 1-b 二次排查（2026-10-23 用户听完 6 个版本后：「耳和儿都怪怪的，其他还好」）

用户这句话把范围收窄了：**别的字都没问题，只有 er 韵母这两个字怪**。
这排除了「语速太快听不清」，指向**这两个字的发音本身不对**。

查到同类型证据：edge-tts 有已知 issue（rany2/edge-tts #454）——「齁」单字被读成 ku4，
原因是**词典里有「齁齁」但没有单字「齁」词条，缺词条时会 fallback 到一个错读音**。
er 是自成音节的卷舌元音，在普通话里最少见，正是这类「单字词条缺失」的高危字。

于是按三条路各生成样本实测（`build/_tts/try_er/试听.html`，20 条）：

| 路 | 做法 | 结果 |
|---|---|---|
| A 换音色 | 8 个 zh-CN 音色各念「耳」「儿」（晓晓/晓伊/云希/云健/云扬/云夏/小北/小妮） | 待用户听 |
| B 从整词切 | 「耳朵」的「耳」、「儿子」的「儿」按能量包络找边界，切出来再编码回 mp3（词首声调有后字撑着，通常更完整） | 待用户听 |
| C 本地大模型 | CosyVoice2 / GPT-SoVITS | **不可行**：本机只有 Intel 核显（无 NVIDIA），这类方案要 6–8 GB 显存 + 2–4 GB 模型 |

**关于「上次让你在 GitHub 找语音方案」**：上次的结论是 Piper / CosyVoice 等**模型下载源在这个环境全部不可达**
（GitHub raw / codeload / jsdelivr / HuggingFace 都被拦），所以退到 edge-tts。
这次复核：本机也没有能跑本地模型的显卡，所以「本地大模型」这条仍然走不通。

**终局方案（如果 A、B 都不行）**：Azure 官方 TTS 免费层（每月 50 万字符，够用完这 1691 条）
支持 SSML 用**拼音直接指定读音**：

```xml
<phoneme alphabet="sapi" ph="er3">耳</phoneme>
```

这是唯一能「精确指定 er3 / er2」的办法，不用猜。代价是要注册 Azure 账号拿一个 key（约 10 分钟）。
edge-tts 用的是同一条 Azure 语音链路，但免费接口不传 SSML，所以拿不到这个能力。

> 顺带记录：我试过用 F0（基频）曲线判断哪个版本的三声更完整，**结论不可靠**——
> 单音节只有 0.2–0.5 秒，清音段和鼻音会让自相关法误判，实测连「无」（二声）都被算成"有回升"。
> 所以这件事以人耳判断为准，不拿频谱数据装作精确。

**已做**：生成了试听样本（见文末「附：语音试听」），你可以直接听三个版本再定。

### 问题 2：错误反馈音太小

现状两个音：`392 Hz→349 Hz`（0.13 s，音量 0.20）+ `261 Hz→233 Hz`（0.22 s，音量 0.17）。
对比正确音是往上走的明亮和弦，音量 0.26 起。**错误音既轻又低**，在教室环境里很容易被环境音吃掉。

| 方案 | 做法 | 效果 |
|---|---|---|
| **A 只提音量** | 0.20→0.32、0.17→0.28 | 最简单，但只是"更响的错误音" |
| **B 提音量 + 换波形** | 正弦 → 方波/锯齿（更"扎"），音量 0.30 | 同样响度下更醒目 |
| **C 改结构** | 「降-降」两短音 + 一个低频"咚"（三个音），音量 0.30 / 0.26 / 0.22 | 更"错"的感觉，和正确音区分度最大 |

**建议 C**（或 B）。另外可加一个**视觉**配合：选项抖一下（`.opt` 现在错了只是变红，不抖），和游戏里 `.miss{animation:shake}` 一致。

> 注意：音效音量一直是个敏感点（v8 因为 0.075 太小返工过，v10 提到 0.26）。这次再提，说明**教室环境**下 0.20 确实不够。我建议直接到 0.30 档，别再一小步一小步挪。

### 问题 3：答错不能重试（这条最该改）

**现状**：点错 → 立刻判死 → 只能点「跳过这题」或等自动下一题。
对特需学生来说，「我还没试完就不让我试了」比答错本身更挫败。

**改法**（直接搬游戏里已经验证过的逻辑）：

```
点错 → 该选项变灰 + 抖一下 + 错误音 → 其余选项仍可点
点对 → 正常反馈（答对了 / 音效 / 自动下一题）
连错 2 次 → 把正确选项"亮一下"（glowRight，游戏里已有）
```

**记录口径必须一起改**，否则会算歪：

| 情况 | 现在 | 改后 |
|---|---|---|
| 一次就点对 | `alone++` | `alone++`（不变） |
| 用提示后点对 | `hinted++` | `hinted++`（不变） |
| 点错一次再点对 | 记 `wrong++`，这题结束 | 记 `wrong++` **和** 新增的 `retry++`（说明"能自己纠错"） |
| 点了 2 次错才点对 | 同上 | `wrong += 2`，`retry++` |

`levelOf` 判定保持 `alone >= 3 && wrong <= 1 → 已掌握`。加了重试后 **wrong 会变多**，所以要想清楚：
- 严格：错一次就记一次错（`wrong` 会涨得比以前快，掌握变慢）
- 宽松：一题最多记 1 次错（不管错几次）

**建议宽松**：一题只记 1 次错（`wrong++` 只加一次），因为重试的目的就是"给他机会"，不该双重惩罚。
`retry` 只作为档案里的一个参考数字，不参与判定。

### 问题 4：预习字卡不够，学不会就进练习

**为什么不够**：现在的预习是「看 + 听」，全过程**不需要学生做任何判断**，点 8 下就"读完"了。
认字要过三关：**看形 → 听音 → 辨形**。现在只做了前两关，第三关直接跳到正式练习（还可能抽到「听音找字」之外的题型）。

**三个可叠加的做法**

| 方案 | 具体 | 成本 |
|---|---|---|
| **A 字卡加「这是哪个字？」** | 每张卡读完，立刻出一道三选一（听读音，从 3 个形近/音近字里选） | 中：要生成干扰项（用现有 `pickN` 逻辑即可） |
| **B 预习后插一局小游戏** | 用「今天的这几个字」开一局，玩法从 4 款里随机（`startGame(kind, chars)` 已支持传字集，游戏内部会自动补足题量） | 低：接口现成，只需接一个"预习完 → 开游戏 → 回来"的流程 |
| **C 字卡分两轮** | 第一轮"认"（看+听），第二轮"挑"（只给读音，从卡片里挑出对应的字） | 中：等于把预习做成一个小测验 |

**建议 A + B**：
- 字卡每张加一次「三选一」，逼学生做一次辨认（**这一步才是"学会"的关键**）
- 全部认完，自动开一局小游戏（随机玩法，用今日在学字），游戏结束再进正式练习

小游戏这一步对你说的「是否要引入前面的趣味练习的游戏呢？随机呈现一个游戏？」正好是肯定回答，而且**技术上零障碍**（`startGame(kind, chars)` 已经能接受任意字集）。

### 问题 5：学生自己的界面

**现在**：点照片 → 今日字卡 → 练习。学生全程不知道"我学到哪了""今天要干什么"。

**建议做成「我的主页」**（复用练习页顶栏：头像 + 名字 + 换人）：

```
┌────────────────────────────────────────┐
│            [头像]  小明                 │
│                                        │
│      ╭─────────╮                       │
│      │   38%   │   已学会 11 个         │
│      │ 掌握率  │   还有 19 个在排队     │
│      ╰─────────╯                       │
│                                        │
│   ★★☆☆☆   连续 4 天                 │
│                                        │
│   今天要练这 6 个：                     │
│   [上] [下] [口] [耳] [小] [天]         │
│                                        │
│        ┌──────────────────┐            │
│        │  开始今天的学习   │            │
│        └──────────────────┘            │
└────────────────────────────────────────┘
```

**趣味化用什么**（不要做太花，特需孩子容易分心）：
- **圆环掌握率**（`ringHTML` 现成，进度页在用）
- **星星**：每掌握 5 个字点亮一颗（最多 5 颗）
- **连续天数**：要有火苗图标；数据从 `logs` 的 `last` 日期算（现在没有这个函数，要新写 `streakOf(stu)`）
- 不做排行榜、不做虚拟货币（跨学生比较对这些孩子没好处）

**数据都现成**：`stuProfile(s)` 已经给出四态、掌握率、`p.act`（在学数）、`p.standby`（排队数）。

**流程变化**：
```
现在：点照片 → 今日字卡 → 开始练习
改后：点照片 → 我的主页 →（开始今天的学习）→ 今日字卡 → 小游戏 → 正式练习
```
返回键要能一层层退回去（主页 ← 字卡），不能一下子跳回选人页。
