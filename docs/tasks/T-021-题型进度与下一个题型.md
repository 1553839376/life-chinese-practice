# T-021 题型进度：「下一个题型」与「今天练完了」

- 提出人：老师（2026-10-29）
- 状态：已实现（v26，未发布）

---

## 一、老师原话

> 「学生预习完进入练习后，有很多个练习，完成一个练习后应该给一个选项比较明显一点的让学生进入下一个题型。
> 而且在总的上面也应该有一个进度条或者别的上面打勾？等等让学生理解还有几个题型没完成。
> 全部题型完成后要提示已完成今天的全部练习。」

同一条消息里还问了字表与退出机制（见第四节）。

## 二、改造前是什么样

- 一局只练一个题型，顶部只有「第 3 / 8 题」，**没有任何跨题型的进度**；
- 结算页两个按钮一样大：「再来一轮」「换题型」——后者点下去只弹一句 toast
  「点上面的题型标签，就能换一种练」，等于把孩子又扔回顶部标签栏；
- 全部练完**没有任何总结**，看不出「今天是不是都干完了」；
- 「开始今天的学习」永远从学生勾选的**第一个**题型开始，练到第三个再进来又从第一个重头。

## 三、改法

### 3.1 会话进度（不进 STATE）

`wb2_sess_v1` 存本机，结构 `{day, name, done:{题型:1}}`：

| 函数 | 作用 |
|---|---|
| `sessEnsure(stu)` | 取今天的进度；日期变了或换了学生就新开一份 |
| `sessMark(type)` | 走到结算页才算这个题型做完（点进去没做完不算） |
| `sessDoneN(stu)` / `sessTypes(stu)` | 数已完成 / 列出这位同学的题型 |
| `sessNext(stu)` | 下一个还没做完的题型，全做完返回空 |

**不进 `STATE`**：这样就不用进云端 schema、不用管导出导入，跨天自动清零。

### 3.2 顶部一排圆点

`#typeProg`（在题型标签下面、主页上方也显示）：

- 做完的 → 绿底 ✓；当前的 → 蓝圈；没做的 → 灰圈里写序号。
- 旁边一句话：「已完成 2 / 6 个题型，还有 4 个」；全做完改成「今天的 6 个题型都练完啦」。

### 3.3 结算页

| 情况 | 主按钮 | 次要 |
|---|---|---|
| 还有没做完的题型 | **整行大按钮**「下一个题型：图字配对 →」（23px / 高 72px） | 这个题型再练一轮 / 回我的主页 |
| 全部做完 | 「回我的主页」 | 再练一轮 |

全部做完时额外给一块绿色大字「今天的练习全部完成」+「N 个题型都练过了，真棒」，
**正确率照样显示**——只排一个题型的学生，第一次做完就等于全部完成，不能因此看不到分数。

### 3.4 「开始今天的学习」接上次

`preStart()` 改成从 `sessNext()` 取题型（第一个没做完的）；都做完了才回到第一个题型重练。

## 四、字表与退出机制（老师同一条消息里问的，核对结果）

| 老师的说法 | 现在的实现 | 结论 |
|---|---|---|
| 字表老师随时可以调、按调完的字单练 | `charsOf(stu)` 每次出题现读字表；在学名单每次渲染都重新摆正 | ✅ 已是这样 |
| 以前学完、还有错的继续学 | `levelOf()`：`wrong ≥ 3 && alone === 0` → 需巩固，留在在学 | ✅ |
| 三次练习正确率高就可以退出、补位下一个 | `alone ≥ 3 && wrong ≤ 1` → 已掌握 → 退出在学、从待学补位 | ✅ 口径一致，但是**累计**不是「连续三次」 |
| 除老师手动移除 | 档案页「移出」→ 进 `stu.off`，不再自动补（T-020） | ✅ |

**没改这条阈值**：老师说的是「差不多就可以退出」，跟现有 `alone ≥ 3 && wrong ≤ 1` 对得上。
若以后要改成「最近三次连续都对」才退，需要给 `logs` 加一个最近结果序列（云端没有这列），得单独立项。

## 七、补记（2026-10-30）：鼓励语和按钮长得一样

老师看完窄屏截图后直接否掉：

> 「你这个截图就有问题，我问你，学生等下在那一直点做的不错怎么办，这两个都没有区分开来。
> 学生本来就不认识几个字。」

**问题**：结算页的「做得不错，继续加油」用的是 `.feedback.ok`——浅绿底、2px 描边、圆角块，
跟下面的「下一个题型：看拼音写字 →」几乎是同一个形状，只有字号差一点。
特需学生认不了几个字，判断「哪个能点」全靠形状和颜色；两个一样，孩子就会一直戳那句表扬。

**改法（只动结算页，其它屏一个字没碰）**：

| 元素 | 改前 | 改后 |
|---|---|---|
| 鼓励语 | `.feedback.ok`：浅绿底 + 描边 + 圆角块，17px | `.fb-say`：**透明底、无描边**、21px 粗体绿字、居中 |
| 下一个题型 | `.primary.next-type`：浅绿底 + 细边 + 16~24px（被 `.primary` 压过） | 实心深绿 `var(--green)` + 白字 + `border:3px solid #245741` + `box-shadow:0 4px 0` 立体，24px / 最小高 76px / 整行宽 |
| 次要按钮 | 「这个题型再练一轮 / 回我的主页」= `.secondary` | 不动 |

**踩的坑**：`.next-type` 与 `.primary` 都是**单类选择器、同优先级**，谁的规则写在后面谁赢。
第一版把 `.next-type` 写在 `.primary` 之前，字号、底色全被压回去（真机上看着还是个小浅绿按钮）。
现在放在 `.primary.sm` 之后，并在 G1 里用下标比较钉住顺序，下次再挪位置会直接红。

**新增断言**：G1 5 条（进度结构、下一个题型入口、鼓励语不用 `.feedback`、`.fb-say` 无 background/border、`.next-type` 在 `.primary` 之后）；
smoke2 6 条（鼓励语是 `.fb-say`、结算页没有 `.feedback`、整屏只有一个 `.primary`、按钮字比鼓励语大、鼓励语无底色）。
门禁 64 → 69 项，测试 533 → 539 项（smoke2 364 → 370）。
