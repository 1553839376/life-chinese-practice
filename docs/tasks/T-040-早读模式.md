# T-040 · 早读模式（发四张牌，一张张翻开带读）

- 版本：v47（2026-11-06）
- 状态：✅ 已交付
- 相关：`T-030`（先选玩法再挑字）、`T-035`（游戏乐园听写，同样是「不写记录的乐园模式」）

---

## 一、老师的原话

> 「乐园里面增加一个早读模式，老师可以选择几个字，然后轮播读，留足时间给学生跟读。最好是有动效的可以吸引学生注意力。我提供几个你看哪个好。一种是发牌的，一次发四张拍，一张一张自动翻开读。然后或者是搞一个吹泡泡的机器，自动出泡泡，泡泡里面有字可以跟读你看看哪个好」

老师给了两个选项，要我挑一个。

---

## 二、为什么挑发牌

| 维度 | 发牌 | 吹泡泡 |
|---|---|---|
| 读的时候画面 | **静止**（翻开就定住） | 一直在飘，孩子正认字时目标还在动 |
| 提示 | **动作即提示**（翻开＝读这张） | 冒泡只是装饰，读哪个靠声音 |
| 字能多大 | 矩形牌，字放到 **144px** | 圆形，字一大就撑成一块圆背景 |
| 节奏 | 牌停在那儿，想留多久留多久 | 有飞行时间，读完还得等它飘走 |
| 和现有玩法的关系 | 全新，不撞车 | **戳泡泡已经是另一款游戏**（`GAME_KEYS` 里的 `bubble`），飘着又戳不破，孩子会反复去戳 |

结论：**发牌。泡泡留给戳泡泡那款。**

---

## 三、三个口径（老师 2026-11-06 当场选的）

| 项 | 定的 | 备选 |
|---|---|---|
| 跟读时长 | **5 秒** | 3 / 8 / 老师现场可调 |
| 朗读内容 | **只念这个字** | 字 + 一个组词 |
| 牌面 | **只显示大字** | 大字 + 拼音 / 大字 + 拼音 + 组词 |

## 四、怎么做的

### 4.1 入口：第六张玩法卡

`p2.html` 的 `#gamePick` 里加 `data-gp="read"`（太阳图标，独占一行实线，排在四款游戏之后、听写之前）。**不进 `GAME_KEYS`**——「随便玩」「换个玩法」只在四款场景游戏里转，早读是带读不是游戏。

`pickBegin('read')` 复用 v35 那条「先选玩法再挑字」的路；`pickVerb()` 让底部按钮说「开始早读」（原来一律「开始练习」）；`pickStart()` 里 `kind === 'read'` 就交给 `startRead()`，**不进游戏引擎**（`startGame()` 顶上另有一道兜底，别的路径拿 `'read'` 来调也不会炸）。

### 4.2 屏幕：`#scrRead`

```
[退出]  早读                    第 1 遍 · 第 1 / 6 个字   [暂停]
┌────────────────────────────────────────────────────────┐
│  ┌────┐ ┌────┐ ┌────┐ ┌────┐                            │
│  │ 人 │ │ ?? │ │ ?? │ │ ?? │   ← 四张牌，翻开一张，其余是牌背 │
│  │ ▬▬ │ └────┘ └────┘ └────┘   ← 牌面底部一条 5 秒进度条    │
│  └────┘                                                  │
└────────────────────────────────────────────────────────┘
翻开一张，跟着读一遍；读完自动翻下一张            [ 下一个字 ]
```

- 标题条留在顶上（和其它屏一致），牌桌和底栏用 `margin:auto` 上下推开（牌桌只有 367px 高，全堆在屏幕上沿像没做完）。
- 尺寸：牌宽由列宽定，`aspect-ratio:3/4` 反推高度；**牌桌高度 `auto`**（裹住牌），不再写死 vh。
- 窄屏（≤640）：2×2 摊开，牌改成「按行高定尺寸」（宽由 aspect-ratio 反推），场高给死。

### 4.3 发牌（`readDeal()` / `readDealTo()`）

- 一次最多四张，从字表里**按顺序**抓：`list.slice(READ.i, READ.i + READ_TAKE)`。
  **一批里不重复**：选了 6 个字就是 4 + 2，不回头补两张凑满四张（否则「第几遍」算乱，孩子也会看到刚读过的字又发一次）。
- 牌从**牌桌右缘中点**飞进来：`readDealTo()` 量「起点 → 每张牌中心」写进 `--dx/--dy`；量不到布局（jsdom / 还没排版）就什么都不写，CSS 的 `translate(var(--dx,42px),var(--dy,0))` 兜底。
- 四张错开 90ms 落地：`--i` → `transition-delay:calc(var(--i) * 90ms)`。
- 顺序要紧：**先量坐标、再上牌**（量的时候牌还在原位）；`void tb.offsetWidth` 强制回流，否则「加 dealing 又立刻加 in」会被合并，动画不播；`in` 上去的同时摘掉 `dealing`。

### 4.4 翻牌与跟读（`readFlip()`）

- 3D `rotateY(180deg)` 翻过来，**已翻开的不翻回去**——一屏四张，看得到读过哪些。
- 当前这张挂 `.now`（描边高亮）+ `.run`（进度条开走）。
- 翻到一半（300ms）开口念：`saySeq([{ t: 字 }])`，字和声音同时到，5 秒里大约 3.5 秒是静给孩子跟读的。
- 5 秒到了 → `readNext()` → 还有牌就翻下一张；这一批没了就停 1.7 秒再发下一批。

### 4.5 5 秒只有一个来源

```js
var READ_HOLD = 5000;
tb.style.setProperty('--hold', (READ_HOLD / 1000) + 's');
```
```css
.rd-wait::after{animation:rdHold var(--hold,5s) linear forwards;animation-play-state:paused}
.rd-card.run .rd-wait::after{animation-play-state:running}
.read-stage.paused .rd-wait::after{animation-play-state:paused}
```
改节奏只改常量，样式里没有第二个 5 秒（G1 盯着）。

### 4.6 暂停 / 继续（`readPause()`）

不是简单清个定时器。所有等待都走 `readWait(ms, fn)`，它把「还要等多久（`left`）＋ 等完要做什么（`job`）」一起存下来：

- 暂停：`clearTimeout`、`left -= 已经过的时间`、`sayStop()`、牌桌挂 `.paused`（进度条同步停）、按钮变「继续」；
- 继续：`left` 原样排回去。

所以停在「5 秒跟读」和停在「1.7 秒换批」两种位置都接得上——只存毫秒数不够，因为这两段不是同一个数。

### 4.7 离开就收摊

`showScreen()` 里兜一道：

```js
if (name !== 'read' && typeof READ !== 'undefined' && READ.on) readStop(false);
```

定时器不清会在后台继续翻牌、出声（人已经回乐园了）。`readStop(true)` 是点「退出」，**先关 `READ.on` 再换屏**——不先关会绕回 `showScreen` 的这道兜底。

### 4.8 不判分、不写学习记录

和听写同一个口径：乐园里的事不污染档案。G1 有一条盯着 `startRead()` 里不许出现 `logs`。

## 五、踩到的点

1. **类名撞车**：第一版把按钮叫 `.read-next`、提示叫 `.read-tip`，而这两个类在 v18 的「今日字卡」里已经存在（`.read-next` 有 `min-width:min(360px,84vw)`）——按钮当场变成 360px 宽的绿条。整套换成 `rd-` 前缀。**新屏别捡像「通用名」的类名，先 grep 一遍。**
2. **牌桌高度写死 vh**：第一版场 539px、牌只有 317px，宽屏上一大片空桌面。改 `height:auto`，367px 正好裹住牌；窄屏反过来必须给死高度（2×2 的行高没有依据）。
3. **标题条被拉到页面中间**：给整屏 `justify-content:center` 后标题条跟着往下跑，像弹窗。改成标题条留顶上、牌桌和底栏 `margin:auto` 推开。
4. **「第几遍」算乱的隐患**：用取余凑满四张时，6 个字会发成 4 + 4（后两张是刚读过的），`done` 一涨就跨遍。改成 slice 顺序取、只发剩下的。
5. **暂停断在半路**：只清定时器不记 `job` 的话，继续时只能重新开始一段——所以 `readWait()` 把两件事一起存。
