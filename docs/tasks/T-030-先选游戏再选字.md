# T-030 · 先选游戏，再挑一批字

- **日期**：2026-11-02
- **状态**：done（v35，已构建 / 门禁全绿，待发布）
- **触发**：老师转达同事意见

> 「同事提了个意见，就是能否先选择游戏再去选练哪个字呢，我觉得可以在首页认字乐园那里留一个这样的入口，方便有时需要先选游戏再选字，然后这个字可以选很多个字，让学生针对性做这些字的练习」

## 一、要解决的问题

原来只有一条路：**点一个字 → 学字卡 → 卡里挑玩法**，`startGame(kind, [CARD_CH])` 一次一个。

「随手玩一个字」很顺，但「今天这几个字学生老记不住，用一种玩法过一遍」做不到：

| 想要的 | 原来 |
|---|---|
| 一次挑 5 个字，同一个玩法连着练 | 点 5 遍，每遍还要重新选玩法 |
| 一上挑两个、二上挑三个 | 得来回翻册次，弹回乐园还可能丢位置 |
| 玩完换个玩法继续练这批字 | 换玩法只作用在一个字上 |

## 二、方案（已落地）

`需求盘点 → 页面搭建 → 数据接入 → 自动化流程 → 优化迭代` 里的「页面搭建」，只动乐园这一屏。

```
乐园顶部「先选游戏」
   → #gpMask 面板：戳泡泡 / 钓鱼 / 摘果子 / 喂小动物（data-gp）
   → 字格进入多选态（PICK.on）：每卡一个 .ch-ck 圆圈，点一下勾上、再点取消
        册次筛选 / 搜索照旧可用，勾选跨批次不丢
   → #pickBar 底部常驻：「钓鱼 · 已选 3 个字」+ 开始练习（3）/ 取消
   → startGame(kind, PICK.list)  ← 整批交进去，引擎一个字没改
```

**为什么不另做一份「选字页」**：老师已经会用册次和搜索筛这 700 个字，再教一套筛选手势只会更乱；复用同一张字格，「勾选」只是给卡片加了个状态。

## 四、验收

- **真浏览器**（`build/_probe_v35.py`，Chrome headless）：
  `entry=true mask=true games=4 maskShut=true picking=true/true bar=true ck=700`
  → `bar0=钓鱼 · 还没选字|true`（空选禁用）
  → 点三张 `sel=3`、`bar3=钓鱼 · 已选 3 个字|false|开始练习（3）`
  → 再点第三张 `sel2=2`
  → 开始 `phase=game|kind=fish|origin=2|queue=6`，`barGone=true`、`pickingOff=true`、`ckGone=true`
- **窄屏**：390px iframe 截图（headless 直接开 390 会被钳到 ~500，看起来像溢出，其实是截掉了右边）——底部条三块都在屏内。
- **门禁 121 项全绿**（新增 8 条：入口位置、`data-gp` 不复用 `data-gk`、`PICK` 四函数、`PICK.on` 分支必须排在 `openCard` 之前、整批交 `startGame`、底部条常驻＋空选禁用、离开乐园自动退出、退出后还原）。
- **测试 727 项全过**（smoke2 520 → 558）。

## 五、踩的坑

1. **`data-gk` 不能复用**：学字卡那条委托读 `CARD_CH`，乐园里它是 `null` → 复用就等于「弹一句『先选一个字』然后什么都不发生」。新面板用自己的 `data-gp`。
2. **`position:fixed` 的底部条会跟人走**：必须 `showScreen` 兜一道自动退出，否则进老师端还压着一条「开始练习」。
3. **写测试时踩到搜索是三路匹配**：搜「人」会把「大人」「二人」全带出来，第一张卡可能就是已选的字——测试里要挑「还没勾的那张」，不能直接拿 `querySelector` 第一张。
4. **headless 窗口宽度被钳到 ~500px**：想看真实 390 排版，得套一个 390px 的 iframe。
