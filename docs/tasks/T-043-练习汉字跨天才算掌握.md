## 二、先查清「才练过一次」到底是什么

临时探针 `build/_probe_exit_tmp.js`（用完即删）实跑：

```text
初始在学(上限4)： 人手男女 ｜盯住这个字： 人
独立答对 1 次 → 练习中 ｜还在在学名单吗： 在
独立答对 2 次 → 练习中 ｜还在在学名单吗： 在
累计独立答对 3 次（同一天三个题型各答对一次） → 已掌握 ｜已被换掉 ｜现在在学： 手男女大
累计答对 3 次、但错过 2 次 → 练习中 ｜已被换掉
锁定的字： 已掌握 ｜被换掉
```

**根因**：旧 `levelOf()` 只看 `r.alone >= 3 && r.wrong <= 1`。一轮有 9 个题型、
都从同一批在学字出题，一天里同一个字很容易被独立答对 3 次；`syncActive()` 立刻
把未锁定的已掌握字移出在学名单并补一个新字。**一旦换出，后来降级也不会自动回来**，
所以老师第二天打开就「没有这个字了」。

结论不是「练一次就换」，而是「同一天多个题型重复练到 3 次就毕业」。

## 三、目标 / 非目标

**做**：把「已掌握」改成至少两个**不同本地日**独立答对过才算，并保留老数据兼容。

**不做**：
- 不改「在学字数」「在学名单永远补满」「锁定 / 移出」这套状态机（`syncActive()` 一行没动）。
- 不改 `alone >= 3 && wrong <= 1` 这个原有门槛，只**加**一个跨天条件。
- 不改练习结算页、不重做主页 / 档案页、不改节奏与语音。
- 不追溯老数据：云端已标「已掌握」的记录、本机没有日期记录的老数据一律沿用旧口径。
- 不进 STATE / 云端 schema / 导出导入 / 学习记录，不加新界面、不加新按钮。

## 四、实现口径

| 项 | 定法 |
| --- | --- |
| 键 | `LS_SOLO = 'wb2_solo_days_v1'`，本机 `localStorage`，与 `wb2_sess_v1` / `wb2_read_pick_v1` 同口径 |
| 值 | `{ '学生\|字': ['2026-11-09', '2026-11-10'] }`，只存日期字符串，不存字对象或成绩 |
| 缓存 | `soloLoad()` 读一次缓存在 `SOLO`，`soloMark()` 直接改缓存对象再落盘 |
| 去重 | `soloMark(key, day)` 里 `a.indexOf(day) >= 0` 直接返回；按 `学生\|字` 隔离 |
| 日期 | `todayKey()`（p4.js 已有，本地 `YYYY-MM-DD`，不是 UTC / ISO 前 10 位） |
| 写入点 | `p5.js` 两处：`wbLogWord()` 与 `gradeAnswer()` 的 `else { r.alone++; soloMark(r.key, todayKey()); }` |
| 判定 | `levelOf(r)` 在 `alone >= 3 && wrong <= 1` 内：① `r.level === '已掌握'` → 已掌握（云端老数据）；② `soloDays(r.key) === 0` → 已掌握（本机老数据）；③ `soloDays >= 2` → 已掌握；其余练习中 |

**为什么只记独立答对**：提示后答对、描红记的是 `hinted` / `prompts`，
那不是「自己认出来」，记了日期会把靠着提示混过去的字也送毕业。

**为什么要留 `d === 0` 这条兼容分支**：老师机器上现有的学习记录里没有日期字段，
如果一律要求 2 天，升级当天全班「已掌握」会集体变回「练习中」，在学名单被整批打乱。
宁可让老数据维持现状，从 v50 之后新练的字开始按新口径走。
