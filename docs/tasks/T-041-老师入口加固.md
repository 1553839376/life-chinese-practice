# T-041 · 老师入口加固（四条路都能进）

- 版本：v48（2026-11-06）
- 状态：✅ 已交付
- 相关：`T-028`（v34 把长按改成连点两下——这次是它的补丁）、`T-014`（老师端入口）

---

## 一、老师的原话

> 「有个问题就是我在希沃智慧屏上点两次点不开老师不知道为什么，在这用鼠标就可以」

「在这用鼠标就可以」这句是钥匙：**同一个页面、同一份代码，换个输入设备就能进**，说明不是判定太严，而是那个设备的事件根本没送到。

---

## 二、根因

v34 改「连点两下」时，入口只挂了一个监听：

```js
entry.addEventListener('pointerup', function(e){ … });
```

希沃那台一体机（或它的浏览器 / 系统触摸驱动）**不派发 `pointerup`**。于是：

- 鼠标点 → 派发 `pointerup` → 数到两下 → 进得去；
- 手指点 → 只派发 `touchend`（+ 补发的 mouse / click）→ 监听器一次都没跑 → 永远进不去。

顺带两个阈值也是照鼠标设的：`520ms` / `40px`。65~86 寸屏上，老师第二下往往要挪半个手掌才能落回同一个点，40px 在这么大的屏上「就等于没动过」。

---

## 三、改法：四条路进同一个门

| 路径 | 何时生效 | 为什么要有 |
| --- | --- | --- |
| 主事件流 | 按设备挑一种：`'ontouchstart' in window` → `touchend`；`window.PointerEvent` → `pointerup`；否则 `mouseup` | 真机上的正常路径，不再假设存在 `pointerup` |
| `click` 兜底 | 主事件流在 700ms 内**没响过**时才算 | 只发 `click` 的一体机（键盘/遥控/某些投屏软件） |
| `dblclick` 直通 | 只要派发就直接进 | 有的 Windows 触摸驱动只给 `dblclick`，连 `click` 都省 |
| 按住 900ms | 按住不放；**不因手指微动取消**，只在松手时收 | 三条并列进法之一。v34 把它删掉的理由是「按住时一滑就作废」，这一版只在 `up / cancel` 时清定时器 |

阈值：`ENTRY_GAP` 520 → **800**、`ENTRY_SLOP` 40 → **80**、新增 `ENTRY_HOLD = 900`。

---

## 四、三个坑

### 1. `click` 兜底必须去重，但自己不能刷新 `used`

一次物理触摸会连着派发 `touch → mouse → click`。不去重就会被数成两下——**学生碰一下老师端就开了**，这是事故。
所以 `used` 记「主事件流最近一次用的时间」，700ms 内跳过 `click`。

而 `click` 分支里**必须传 `entryTap(e, false)`**：第一版传了 `true`（顺手写成和主事件流一样），
于是第一次 `click` 把自己的 `used` 刷成现在 → 第二次 `click` 落在 700ms 内被跳过 → **兜底完全没用**。
`build/probe_entry.js` 第 ① 条当场报 `learn ✗`，改 `false` 后变 `teacher ✓`。

### 2. 按住进屏后要吞掉紧跟着的那下 `click`

按住 900ms 到点进屏，手指还在屏幕上，**一松手那一下会落在刚打开的老师端页面上**，正好点到某个按钮。
做法：进屏时在 `document` 上挂一个捕获期 `click` 吞掉器（`preventDefault + stopPropagation`），600ms 后自己摘掉。

### 3. 旧测试写死了 `pointerup`，改完变成「空过」

smoke2 §29 是 v34 写的，两条断言都用 `new MouseEvent('pointerup')` 派发。主事件流改成按设备挑之后，
jsdom 里挑中的是 `touchend`，于是：

- 「只点一下不进老师端」——没派发任何被监听的事件，**天然通过**（空过）；
- 「隔 0.6 秒再点不算连点」——同样空过；
- 只有「进得去」那条红。

测试改成跟着设备挑事件流（`('ontouchstart' in w) ? 'touchend' : …`），并把 0.6 秒改成 0.9 秒（窗口已经放到 800ms）。

> **教训**：改判据的时候，先看测试是「真的在测」还是「根本没触发」。0 失败 ≠ 全测过。
