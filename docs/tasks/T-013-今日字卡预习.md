# T-013 · 今日字卡预习（进练习前先认一遍）

- 日期：2026-10-23
- 版本：v18
- 触发：用户原话「我觉得这个识字启蒙台还是可以借鉴的，这个显示学生每天要学的字在一个界面，可以让学生整体复习学习一遍。我认为可以放在所有学生个人练习之前。点进学生后，应让学生看今天所学的字卡，每个读一下，再去做各种练习」

## 一、现状

`enterStudent()` 点学生卡片后直接 `startQuiz(第一个题型)`，学生一进来就是一道题，没有「先认一遍」的环节。
旧「识字启蒙台」有一屏 `#deck`（`renderDeck`）：大汉字卡片网格 + 序号 + 掌握状态，点卡翻面看拼音/词语。

## 二、要做什么

在学生个人练习**之前**插一步「今日字卡」：一屏看完今天要练的字，点一张读一张，读完再开始做题。

| 元素 | 内容 |
|---|---|
| 标题 | 「今天的字」+ 「共 N 个 · 已掌握 M」 |
| 字卡 | 大汉字（76px，主角）+ 拼音（15px）+ 组词（20px，次要）；左上序号、右上四态标签 |
| 点卡片 | 朗读该字（`charKey` 单字录音，整字合成），卡片描绿 + 右下「读过了」 |
| 底部大按钮 | 「开始练习」（≥60px）→ `startQuiz(当前题型)`；全读过时文案变「都读过啦，开始练习」 |
| 没排题型 | 仍可看字卡，按钮文案改为「还没排练习题型」并禁用 |

## 三、关键决定

1. **字单按档案的建议顺序取，出题再收敛到这份字单**：`todayChars()` = `stuProfile().focus`（需巩固 → 靠提示 → 练习中 → 待学）取前 N 个，
   第 N+1 个起才是已掌握的字（只有练习量不够时才拉来复习）。**不能直接用出题的 `weightOf`**——
   那里「待学」权重最低（新字先出），拿它当字单会把最该补的「需巩固」挤到后面。
   取完之后 `startQuiz` 收敛到 `PRE.list`，所以预习和做题是同一批字；否则两处各自随机，
   孩子刚认完 8 个、做题却是另外 8 个。
2. **抽练（`QUIZ_FOCUS`）优先**：从老师端「抽练」进来时，预习只显示抽练的那几个字，数量也随之收敛。
3. **不做「自动连读」**：`vaPlay` 内部不回调播放位置，做高亮会不同步；课堂上老师点一个、学生读一个才是真实节奏。
4. **预习状态不落盘**：`PRE = {list, read, name}` 只在本次会话，换人即重置。这不是学习记录，不该写进 `STATE.logs`。

## 四、踩坑

- **出题的 `weightOf` 不能拿来当字单**：待学=0 排最前，字单会全是新字，需巩固的一个都进不来（第一版就这么错的，靠测试里「需巩固必须出现在前两张」才发现）。
- **拼词语的题量按词算，不能按字数**：今日字单让 `isFocus` 为真后，`raw = tp.length` 把 6 个字的字表压成 2 组。改成只有真抽练（`isDrill`）才缩词量。
- **预习态老师辅助按钮**：`useHint` / `skipQuestion` 里有 `if (!STATE.quiz) return` 兜底不会崩，但对特需孩子「按了没动静」比没按钮更糟，直接 `.is-pre` 藏起来。
- **headless 截图 `--window-size=1180` 实际视口 1156**：量尺寸要 `getBoundingClientRect`，别拿窗口宽当视口宽（第一版怀疑卡片高度不齐，实测 8 张全是 154×186，是眼睛骗人）。

## 五、验收

- 门禁全绿；`smoke2` 新增 §22（预习字单/卡片数/四态标签/点读打勾/开始练习进入答题/抽练收敛/空字表提示）
- G1 护栏：`enterStudent` 体内必须调 `renderPreStudy`（不许绕过预习直接开题）、`todayChars` 体内用 `stuProfile` 的 focus（字单按建议顺序）、`startQuiz` 体内必须有 `PRE.list`、`preSay` 体内必须有 `say(` + `PRE.read`
