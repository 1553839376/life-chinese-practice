## 问题（改之前实测）

截图对照：`build/_shots/v12-进度总览.png`（改后）／改前见 `docs/logs/2026-10-22.md` 描述。

1. **口径错，而且是最致命的一条**。旧矩阵的分子分母都是「字库里那一册的全部字」：
   小明字表只有 20 个字、已经学会 9 个（45%），页面「全掌握率」却显示 **3%**（9 / 300）。
   老师看到的结论是「这孩子几乎什么都没学会」，实际是算错了。
2. **矩阵横铺 22 个册次**（教材 22 册），1080px 宽也放不下，右侧直接被切掉；而且学生字表通常只覆盖 1–2 册，
   其余 20 列永远是 0%，纯噪声。
3. **数字之间没有结论**：「字库字数 700」「已练过的字 22」并排，老师看不出任何可行动的信息。
4. **没有逐字视图**。看到 3% 之后无从下手：不知道该练哪个字、哪个字反复错。
5. **档案只有字表字数**，没有掌握度、没有最近练习时间，判断不了「这个孩子现在学到哪」。

## 设计

### 一、口径（唯一真相）

- 一切进度以 **`stu.chars`（这个学生自己的字表）** 为分母。字库、册次都不参与。
- 四种状态（`lvOf`）：**已掌握 / 练习中 / 需巩固 / 待学**。
  - 无练习记录 → **待学**（不是「练习中」）
  - 沿用 `levelOf`：`alone≥3 且 wrong≤1` → 已掌握；`wrong≥3 且 alone=0` → 需巩固；其余练过 → 练习中
- 掌握率 = 已掌握 / 字表字数。
- 「建议先练」排序：**需巩固 → 练习中但靠提示（prompts≥2）→ 练习中 → 待学**；已掌握不进名单。

### 二、学生名单（学生管理）

表格列改为：学生 / 题型 / **字表进度（四段条 + 9/20 已掌握 + 待学数）** / 题量 / 状态 / **最近练习** / 操作。
操作三个键：**档案** / 编辑 / 删除。没有字表的学生显示红色「未选字」，不给 0% 的假进度。

### 三、学生档案（点「档案」下钻）

```
[返回名单]  头像  小明                                      [编辑资料与字表]
            在读 · 听音找字 / 认读跟读 · 字表 20 字 · 最近练习 昨天
┌ 已掌握 9 ┐┌ 练习中 5 ┐┌ 需巩固 2 ┐┌ 待学 4 ┐
[====== 45% 绿 ====][== 蓝 ==][红][灰]
掌握率 45%（9 / 20）   练过 16 个字   还没碰过 4 个字

逐字掌握   点一个字，看它练过几次
[一][二][人][手][男][女][三][大][小][天][上][下][口]…
  ↓ 点「门」
门  需巩固  mén  门口, 开门                        [收起]
练习次数 4   独立答对 0   提示后答对 0   答错 4   最近 3 天前
答错 4 次、还没有独立答对过。建议先只练这一个字，答对 3 次就算掌握。
[听一听]

建议先练这几个   按需巩固 → 靠提示 → 练习中 → 待学排序
[门][日][天][上][下][口][耳][月][巾][米][十]
[只练这 11 个字]  [按整张字表练]  [设为暂停]
```

### 四、进度总览

- 6 张卡：学生人数 / 字表总字数 / 已掌握（占字表 %）/ 需巩固 / 待学 / 今天练过的人。
  每张卡下面一行小字写清口径。
- **谁学到哪了**：学生一行 = 头像姓名 + 四段条 + 掌握率 + 待学 + 最近练习 + 看档案。
- **全班共同难点**：同一个字 **≥2 个孩子**同时卡住（需巩固或靠提示）才列出，附学生名。
  单人卡住的字不在这里凑数，归到下面。
- **今天该抽谁单独练**：按人列出「需巩固 N / 靠提示 N」+ 字 chip（红=需巩固，琥珀=靠提示），
  右侧一个「抽他练这些字」直接进抽练。

### 五、抽练（只练这几个字）

- `QUIZ_FOCUS`（一次性）：目标字从这个子集取，**干扰项始终从整张字表取**，否则子集只有 3 个字时凑不出 4 个选项。
- 题目数 = 子集字数（不重复问同一个字）。
- 练习页顶部出现抽练条：`本次只练这 5 个字 [天][上][下][门][日]  [改回整张字表]`。
- 从老师端进来的，左上返回键文案是「回老师端」，回去后**档案还开着**，不用重新找学生。

## 数据模型

没有新增存储字段。全部由现有 `STATE.logs`（`学生|汉字 → {n, alone, hinted, wrong, prompts, last}`）+ `stu.chars` 现算。

新增纯函数（`p4.js`）：`lvOf` / `stuProfile` / `sinceText` / `isToday` / `classProfile`。

### 挂载点

- `renderTeacher()`：学生 tab 现在是「名单 / 档案」两态，`PROF_NAME` 有值就渲染档案，否则名单
- `openStuForm()` 从档案进来时先收起档案；`closeStuForm()` 保存后回档案
- `deleteStudent()`：删的就是正在看的人 → 清 `PROF_NAME` 退回名单
- `btnExitTeacher`：主动退出老师端清 `PROF_NAME`，下次进来不下钻

### 踩坑

1. **进度条变成一根灰线**。`#profBar` 本身已经带 `.prog-bar big`，`progBarHTML()` 又返回一个
   `.prog-bar` div → 嵌套后内层宽度按内容算，而内容宽度是按内层宽度算的百分比 → 循环塌成 0，
   只剩外层的灰底。修法：拆出 `progSegsHTML()` 只产出 `<i>`，档案直接塞进 `#profBar`。
   教训：**容器元素已经带布局类时，不要再往里套同类容器**。
2. **旧断言把结构钉死了**。`mx-cell > 0` 和「统计卡 5 张」在改版后必红。按约定改断言测新行为
   （`.prow` 行数、`.prog-mini i` 段数、6 张卡），**项数不减**（81 → 116）。
3. **抽练测试一开始静默失败**：测试字表用了 `一/二/三/日/月/水`，但 jsdom 预置字库只有
   8 个字（日月山水火木人口），`charsOf` 过滤后不足 4 个 → `startQuiz` 提前 return，
   `STATE.quiz` 是 null，后面直接崩。教训：**字表里的字必须在内置字库里**，否则出题池是空的。
4. **窄屏 `.prow` 用 grid-template-areas 但没给三个数值列分配 area** → 自动放置跑位，
   待学和最近练习被挤没。改成 flex + `order`，并给数值列加 `pr-rate` / `pr-todo` / `pr-last`，
   窄屏用 `<i>` 前缀标签（桌面隐藏，靠表头）。
5. **headless 的 `--window-size=420` 实际视口是 492**（和 v9 那次同一个坑）。
   判断有没有溢出只能看 `documentElement.scrollWidth === clientWidth`，不能看截图。
   这次实测 598 / 598，无溢出。
