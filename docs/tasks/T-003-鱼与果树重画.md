## 用户原话

> 有几个问题，一个是钓鱼游戏的鱼画的不对，很奇怪，尾巴长在嘴上。还有摘果子的树很怪，树干很细也不衔接。

## 根因

### A. 鱼的尾鳍接在嘴上

`fishSVG` 里身体是 `ellipse cx=82 rx=58`（跨度 24–140），眼睛在 `cx=116`、嘴的弧线在 `x=138`，也就是**头在右端**。
但尾鳍路径写的是 `M132 56 L176 27 Q167 56 176 85 Z`，起点 `x=132` 几乎压在嘴上，向右张开到 `x=176`。
结论：**尾鳍画在了头那一侧**，与嘴重叠。同时鳃线在 `x=56`（尾部），也放反了。

### B. 树干细且与树冠断裂

- `.tree-trunk` 固定 `38px` 宽、`height:32%`，顶端 `y=68%`；
- `.tree-crown.a` 用 `border-radius:47% 53% 44% 56% / 58% 46% 54% 42%`，最底点在 `y=68%` 正中。
两者**恰好在一个点上相接**，而树干是等宽直棍、平顶，所以看起来像「绿墙下面插了根签子」。
树冠本身是单个椭圆铺满 86% 宽度，也读不出树的轮廓。

## 改法

### A. 鱼（`build/p7.js` `fishSVG`）

按「尾鳍 → 背鳍 → 身体 → 头」重排坐标，viewBox 由 `180×112` 改为 `200×116`：

| 部位 | 位置 | 说明 |
|---|---|---|
| 尾鳍 | `M58 58 L14 24 Q36 58 14 92 Z` | 根部接在身体左端，两叶朝左张开，叉口适中 |
| 背鳍 | `M84 28 Q106 2 130 32 Z` | 身体最高点上方 |
| 身体 | `ellipse cx=106 ry=36 rx=54` | 跨度 52–160 |
| 鳃线 | `M120 32 Q132 58 120 84` | 在头与身体交界，向头侧鼓 |
| 眼睛 | `cx=142 cy=46` | 头在右 |
| 嘴 | `M155 64 q7 4 0 9` | 身体右前缘 |
| 侧鳍 | `M132 72 …` | 眼下方面积 |

配套把 `.fish-ch`（字）从 `left:9%;right:27%` 调成 `left:8%;right:20%`，让字压在鱼身中段偏尾一侧，避开眼睛。

### B. 果树（`build/p7.js` 新增 `treeSVG()`，替换 `.tree-trunk` + 三个 `.tree-crown` div）

整棵树画在**同一张 SVG**（viewBox `400×250`）里，树干与树冠共用坐标系：

- **树干**：`M189 124 C187 160 184 210 181 250 L219 250 C216 210 213 160 211 124 Z`
  上口 22 单位、下口 38 单位（上细下粗），**顶端 `y=124` 位于树冠内部**（树冠底 `y≈140`），
  连接处被叶子从外面盖住 —— 接缝由几何保证，不靠调像素。
- **树冠**：9 个圆取并集做 `clipPath`，内部垫一层 `radialGradient` 统一打光 + 一层 `linearGradient` 压暗右下，
  轮廓有起伏，不再是一整块椭圆。
- **抖动**：`id="treeCrown"` 挂在树冠的 `<g>` 上，CSS 用 `transform-box:fill-box`；
  重启动画从 `void crown.offsetWidth` 改为 `crown.getBoundingClientRect()`（SVG 元素没有 `offsetWidth`）。

配套 CSS：`.tree-art`（z-index 1）、`.grass` 下沉到 z-index 0（否则草地渐变会把树干底部冲成半透明）、
`.fruit-wrap` 改 `inset:2% 9% 46% 9%` 让 4 个果子落在新树冠上。

### C. 顺带：场景高度封顶（`.game-field`）

树用 `preserveAspectRatio="none"`，场景越竖越容易被纵向拉长，树干又会变细。
实测窄屏（492px 宽）场景是 `468×511`（比例 0.92），树被纵向拉伸 1.74 倍。
加 `max-height:min(620px,80vw)` 后场景变成 `468×374`（比例 1.25），拉伸降到 1.3 倍。
桌面端 `80vw = 944 > 620`，不生效，**桌面布局零影响**。

### 树冠抖动探针（`build/probe_crown.py`）

headless 下 CSS 动画不会被推进（`currentTime` 恒为 0），直接采样 `getBoundingClientRect` 会得到 `dx=0` 的**假阴性**。
正确做法是把动画时间手动跳到指定点再读计算样式：

```
tr@150=matrix(0.999907,-0.0136206,0.0136206,0.999907,-6.83038,0)   rectDelta=-25.76px
tr@320=matrix(0.999925, 0.0122144,-0.0122144,0.999925, 5.99871,0)
tr@520=none
```
