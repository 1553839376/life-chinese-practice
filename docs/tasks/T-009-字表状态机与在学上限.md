# T-009 · 字表状态机 + 在学上限按学生可调（**未开工 · 等用户确认**）

- 触发：用户 2026-10-22 原话「在学上限是否可以根据学生的情况去调整，有的学生可以八个，有的学生可以才五个等」

## 一、现在是什么样

- 学生的字表就是 `stu.chars`（显式汉字数组），**全部字都在池子里**，没有「在学 / 不在学」之分
- 每次练习按「每日题量」`stu.count`（4–20，默认 8）从池子里抽题
- 掌握度是算出来的三态（`levelOf`）：已掌握 / 练习中 / 需巩固，没记录算「待学」
- 借今日字卡（v18）看，一屏就是「今天要练的 8 个」，取法是 `stuProfile().focus` 的前 N 个

所以现在**上限其实就是每日题量**，但它有两个问题：
1. 只是「一次抽几个」，不约束「同时在学几个」——学生字表 40 个字时，第二天抽到的 8 个可能全换一批
2. 改题量是改「一次练多少」，不是改「同时管几个字」，老师容易混淆

## 二、方案（2026-10-22 给过，待确认）

| 项 | 设计 |
|---|---|
| 每个学生一个 `stu.cap` | 同时在学的字数上限，**3–10 可调，默认 6**；有的学生 8 个、有的 5 个，互不影响 |
| 字表加状态 | 每字一个状态：`待学`（在字表里但还没轮到）/ `在学`（当前这一批）/ `已掌握` |
| 自动补位 | 某字连续答对达到掌握线 → 自动标 `已掌握`，从 `在学` 里退出，下一个 `待学` 字自动补进来 |
| 手动干预 | 字表里可以「锁定某字在学」（不想让它被自动换掉）/ 「手动移出在学」 |
| 今日字卡 | 预习的字单 = 当前 `在学` 的那几个（不再按题量从整张表取） |
| 每日题量 | 保留，但语义收窄成「一次练习出几题」，可以大于 `cap`（同一批字来回练） |

**用户 2026-10-23 选了 A，已实现。** 下面是最终落地方案，和上面设想的两处修正：

| 设想 | 实际做法 | 为什么改 |
|---|---|---|
| 新增 `stu.cap` | **不新增**，把 `stu.count` 升格成「在学字数」 | 两个数字（题量 / 上限）并存，老师分不清，代码里也会打架 |
| 字表每字存状态 | 不存，`stageOf()` 现算；只存 `stu.active` 名单 | 存一份状态就会和练习记录分叉；名单是唯一需要落盘的东西 |

## 三之二、补位规则（踩了两次才对）

1. **只补「因学会而让出来」的名额**。无脑补满会让「先移出在学」这个按钮失效
2. 手动加入的字 **unshift 到最前**，否则被「保留前 N 个」截掉
3. 已掌握的字被手动拉回来 = 复习，**自动锁定**，否则下一轮又被剔出
4. 计数**按字去重**（字库 700 条只有 561 个不重复字），否则「在学 11 / 10」

## 四、验收要求

- 老数据迁移后有备份，且 `chars` 不丢
- `cap` 改动只影响该学生
- 掌握自动补位后，今日字卡的字数不变（补一个走一个）
- G1 护栏：`cap` 有上下限钳制；今日字单必须读「在学」集合而不是整张字表
