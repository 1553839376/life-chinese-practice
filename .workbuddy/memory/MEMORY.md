## 发布流程（踩过的坑都在这）
1. `create_page_transaction.py --node-id ...` → 记下 transactionId + baseVersion + 静态 URL
2. 用 **curl** 下载基线（urllib 走代理会 502），再覆盖为本地产物
3. **不要用** `upload_page_artifact.py` 上传（PUT 走 urllib，代理必失败）→ 用 `build/upload_curl.py`
4. `commit_page_transaction.py` → `publish_page.py`
5. **commit / publish 都会随机 `TEMPORARY_ERROR`，必须循环重试**（10~12s 退避，常见 1~6 次）
6. 校验用 `download_page_artifacts.py --source publish`（`workbuddy.link` 直连 502，别 curl 抓发布链接）
7. **G4 逐块比对：两边都要过滤空块**。线上多一个平台注入的空 `inject.js` script 块，只过滤本地侧会让索引错位，内容一致却报 DIFF
8. **线上产物不能做字节比对**：平台给每个元素注入 `data-page-node-id`、带子节点加 `data-pnid-children`、还重排属性顺序（线上比本地大 ~19 KB 属正常）。正确做法：抽出 `<style>` 与各 `<script>` 块逐一比对（`docs/02-验收清单.md` G4）
8. `lint_page_quality.py` 在 >2MB 文件上要跑 16 分钟以上（base64 正则回溯），一律后台跑或跳过

## 老师端表单（v13 定）
- 长列表必须在**容器内滚动**（`#tpLib/#tpWord .list-wrap{max-height:min(56vh,620px)}`）。字库 700 行没有限高时整页 4.4 万像素，新增/编辑表单被顶到最底下 → 用户报「按钮不能用」
- 表单 DOM **排在列表之前**；打开后 `revealForm()` 滚动 + 聚焦；保存行 `position:sticky` 粘底
- 校验失败用 `markField()` 红框 + 抖动 + 滚进视线，**不要只靠 toast**
- 「按钮不能用」先分三种：① 逻辑没跑 ② 跑了报错 ③ 跑了但结果在视口外。第 ③ 种最容易被误判成 ①
- 必须发生的副作用**别挂 `requestAnimationFrame`**（headless/后台标签可能永不执行），用 `setTimeout(fn, 0)`

## 拼词语题型（v14 定）
- **词表不另存一份**：`wordBank()` 从字库「组词」栏 + 老师自建词库现抽（969 个双字词）。另存必然和字库分叉
- 一屏 3 个词 = 6 个字块，两两点选。同组字块不共用；**任取两字不能拼成本组以外的词**（`wbCrossHit`），否则拼对判错
- 顺序反过来也算对（先点「人」再点「大」＝「大人」）
- 记分**只给词里属于学生字表的字**，另一半没学过就不记，否则掌握度虚高
- 结算按**词**算不按组算：8 个词对 6 个 = 75%
- 读题**绝不念词**（念了就是答案），G1 有护栏；拼对后才整词朗读
- **加一条语音要改三处**：`gen_tts.py` 的 SENTS、`p_voice.json`（用 `add_voice.py`）、`p8.js` 的 `SENT_FULL` 映射。漏第三处会静默回退成逐字念
- 字表只有 2 个字也要跑一遍出题：会暴露"整组重复"和"题量被字数截断"两个坑

## 词库（v15 定）
- 词库页 = **内置组词（只读派生，`builtinWords()`）+ 我的词库（`STATE.words`，可编辑）**两源渲染，`wordRowsHTML()` 负责
- **内置词绝不写进 `STATE.words`**：写了就和字库分叉、备份多 87 KB、老师删了下次开题又回来
- 想改某个内置词 → 「收进词库」复制一份（`copyBuiltinWord`，`data-wcopy` 委托），出题时按 `byW` 去重
- 派生点只在 `builtinWords`，`wordBank()` 复用它；G1 护栏钉的是 `builtinWords` 体内有 `STATE.chars`（不是 wordBank）
- 词库表窄屏**必须砍列**（释义/图示），别用 `min-width` 横滚——「收进词库」会被滚出屏幕，等于没有
- 老师报「词库是空的」先分清：数据在不在（`builtinWords().list.length`）vs 界面有没有渲染；这类"派生数据没露面"最容易误判成缺数据
- **同一个症状第二次出现，一定要往下游找**（v16 教训）：v15 修的是「派生数据没渲染」，用户还说空，真因变成「派生源 `STATE.chars[*].words` 本身为空」。上游有三处会弄丢这一列：云端 `mapWord()` 取 `row['组词']`、`importBackup()`、老存档；`migrateCharset()` 只在 charsetVer 不匹配时重灌，所以组词栏一空就**一直空**且界面毫无提示
- **v16 定：`repairCharWords()` 三处必须都调**（`boot()` / `loadAllData()` / `importBackup()`），少一处重启就空回去，G1 钉 `repairCharWords();` ≥3 处
- 体检的边界：**只在整表一条组词都没有时才补**，老师填过一条就一律不动（有测试钉住），否则会覆盖老师的手工数据
- `builtinWords()` 有兜底：扫完字表仍无词就用页面内置字表 `CHARS`（同一份 700 行字库，不是第二份词表），置 `fallback` 后界面直说「字库组词栏是空的，已用内置」，**不许装正常**
- **v16 起老师端顶部有版本角标**（当前 `v23 · 内置词 969`）（兜底标「（兜底）」）。老师报「还是老样子」先要这一句：角标是新版且写着 969 → 问题在别处；角标是旧版本 → 他打开的是缓存页面。发版要同步改 `p4.js` 的 `APP_VER`

## 语音（v21 换豆包，用户 2026-10-24 定稿）
- **引擎：豆包语音合成 2.0（火山引擎）**，音色 **`zh_female_zhixingnv_uranus_bigtts`（知性女声）**，`speed_ratio 0.85`。
  用户先嫌晓晓「三声（耳/雨）模糊、单字偏快（江/京）、音质发闷」，听完豆包 App 说「每个音调都读得准确」，从 6 个通用音色里挑了知性女声。
  **明确不要儿童绘本 / 少儿故事 / 角色扮演类**——只要读得清晰准确、不加情感。
- **编码：豆包直出 `encoding=wav` 的 24 kHz 无损**（不是 `ogg_opus`，那是 48 kHz 上采样的 267 kbps 虚高）→ 本地**只编码一次** 48 kbps AAC / mono / MP4。
  **选 AAC 不选 Opus**：Opus 更省体积，但旧 Safari/iPad 的 `decodeAudioData` 对 ogg-opus 不可靠，课堂里「完全没声音」比多几 MB 严重得多。
- 流程：`build/gen_doubao_voice.py`（断点续传，`ONLY_KEYS=` 可单条重做）→ `build/pack_doubao_voice.py`（裁 50 ms 头 /150 ms 尾、RMS 归一 -20 dBFS、写 `p_voice.json`）→ `build/build_html.py`。
  `DOUBAO_APPID` / `DOUBAO_TOKEN` 走环境变量，仓库与日志里不留。
- **豆包接口偶发返回垃圾音频**（同参数重请求就正常）：「到了」被拉成 3.2 s、「破了」3.0 s。
  → `VERIFY=1 python build/gen_doubao_voice.py` 是离线时长自检，**「0 失败」不等于「全对」，必须跑**；顽固的用 `TEXT_OVERRIDE`（「到了」写成 `到 了` 才正常）。
- **判断"语速快慢"绝不能看文件总时长**：知性女声总长比 Vivi 长，但尾部垫了 0.3~0.5 s 静音，**有效发音段反而短 8%~25%**。要按 10 ms RMS 去掉首尾静音再比。
- **词语必须整词合成**，不能拿单字拼：`w` + 每字 4 位 hex（小手 = `w5c0f624b`）
- 规模：**1691** 条（701 单字 + 972 整词 + 18 指令句），`p_voice.json` **12.85 MB**，离线内联、运行时零网络。
- 老链路 `gen_tts.py`/`pack_audio.py`（edge-tts 晓晓，24 kbps MP3）**已弃用但保留**，v20 及以前的声音就是它。
- 体积预算：G0 `manifest.max_bytes` 6 MB → **16 MB**（v21 产物 13.99 MiB）

## 音效音量与音色（v10 定，v22 提响，v23 换音色）
- 语音总线 `VA_VOICE_GAIN = 1`、音效总线 `VA_SFX_GAIN = 1`。**不要压总线**，用每个音的 `vol` 控力度
- 正确音峰值 0.26/0.24/0.21/0.18；连对 0.18/0.16。低于 0.15 在教室里基本听不见（v8 的 0.075 就是教训）
- **错误音 v23：方波两级下滑 + 闷响**，`233→175`（差 12Hz 打拍）`→175→131`（差 10Hz）`→147→110`，峰值 **0.32/0.30/0.30**，总长 0.62s
- **「响度够」≠「听得见」**（v23 最大教训）：v22 把音量顶到 0.32 老师还说「不明显」，真因是**那层 98Hz 在小喇叭上没有声压**——平板/笔记本外放 200Hz 以下衰减极狠，加了等于没加
  → 错误音全部频率**≥100Hz，主音≥200Hz**；靠**方波泛音**顶到中高频，不靠低频「氛围感」
  → 只说「响不响」会一直往音量上加，最后削顶失真还听不清；要问「这个频段这台设备放不放得出来」
- **音色比对错更重要**：triangle 下行 = 叹气，闭眼能和「明亮上行」混；方波差频打拍 = 嗡嗡，三个维度（响度/音区/音色）同时拉开
- 护栏：e2e_av 断言正确音 ≥0.2 / 错误音 ≥0.30 且不低于正确音 / 含 square / 最低音 ≥100Hz / 主音 ≥200Hz / 总线 ≥1.0
- G1「错误音不比正确音轻」原来只统计 `synthTone(` 的 vol，加 `synthBuzz` 后必须**两种发声器都数**（只数一种会把真正发声的层漏掉，v23 被它挡过一次）
- 试听页 `build/错误音对比.html`（答对音 + A/B/C/D 四候选），换音色前先让人耳拍板，别凭描述决定
- **2026-10-24 老师试听后定稿「A 版」**（就是 v23 内置这版方波下滑），代码无改动。C 长鸣蜂鸣器 / D 木琴三连留作退路，再被说「不够明显」或「太吵」时先翻试听页换档，别重新设计

## 答错可重试（v22 定，T-014 第 1 期）
- 点错**不判死**：只给点错的那个选项加 `.opt.miss`（灰+虚线+shake+`pointer-events:none`），题目不结束，其余选项和「提示一下」都还能用
- **第一次错绝不念答案**（念了就没得试）；**连错 2 次**才给正确项 `.glow` 并念一遍读音——这时"测"已失败，目的改成教会他
- 记录口径：一题**最多记 1 次错**（宽松）；`n` 错时 +1、对时再 +1，所以 `alone+hinted+wrong===n` 不变量仍成立
- 重试后答对算 `alone++` 但 `wrong` 也 +1 → 「每次都错一次再对」的字停在**「练习中」不是「已掌握」**，这是刻意的（靠试出来的字不稳）。`levelOf` 一行没改
- **不要加 `retry` 字段落库**：云端 logs schema 没这列，写了会被同步覆盖成 0（和 v16 组词栏同类坑）。结算页用 `STATE.quiz.retried` 只在本次练习内报一句
- 结算页 `rate` 仍按「最终答对 ÷ 总题数」，**重试不扣分**（那是给孩子的激励，不是考核榜）
- 每道新题必须过 `resetQState()` 清 `missed/wrongLogged/picked`，否则第 2 题错第一次就不记档案
- G1 四条护栏：`pickOption` 体内有 `missOption(ch)` 且没有老写法、`missOption` 用 `wrongLogged` 挡重复记账、`.opt.miss` 有 `pointer-events:none` 且 `missOption` 不置 `answered`、`sfxNo` 三音且每个 vol ≥0.26

## 在学上限与字表状态机（v19/v20 定，用户问过两次）
- **不新增 `cap` 字段**：把 `stu.count` 升格成「在学字数」（3–10，默认 6）。两个数字（题量/上限）并存老师分不清、代码也打架
- `stu.active` = 当前在学名单（长度 ≤ 上限）；`stu.lock` = 锁定不换；`stageOf()` 现算「在学/已掌握/待学」
- **`levelOf` 和状态机是两个维度**：前者说「练得怎么样」（已掌握/练习中/需巩固），后者说「排没排进手上这批」——档案页分两行写，别混成一个词
- **补位只补「因学会而让出」的名额**。无脑补满会让「先移出在学」失效（踩过）
- 手动加入的字必须 **unshift 到最前**（push 会被「保留前 N 个」截掉，踩过）
- 已掌握的字被手动拉回 = 复习，**自动锁定**，否则下一轮 syncActive 又剔出去
- 计数**按字去重**：字库 700 条只有 561 个不重复字，学生字表可能带重复，否则出「在学 11 / 10」
- `openStuProfile` 必须先 `syncActive` 再画，否则老数据显示「在学 0 / 6」但练习时有 6 个字

## 游戏美术约定（v9 定）
- **鱼**：头在右、尾在左。`fishSVG` viewBox `200×116`，身体 `cx=106 rx=54`，眼 `cx=142`、嘴 `x=155`，尾鳍 `M58 58 L14 24 Q36 58 14 92 Z` 接身体左端，鳃线在头身交界
- **果树**：整棵树一张 SVG（`treeSVG()`，viewBox `400×250`），树干顶端深插树冠、接缝被叶子盖住。**别退回 div 树干 + div 树冠**，接缝对不齐
- **场景高度**：`.game-field` 有 `max-height:min(620px,80vw)`；等比 SVG 在窄屏会被纵向拉长
- **动效必须有可见幅度**（v10）：游动 ±20px/3.4s；`.fish-tail` 摆尾 ±13°、`.fish-fin` 划鳍 ±10°，都要 `transform-box:fill-box`（否则 origin 按整个 SVG 视口算，轴心跑飞）
- 测量陷阱：headless 不推进 CSS 动画（要手动设 `getAnimations()[0].currentTime`）；判断横向溢出量 `clientWidth` 而不是看截图；SVG `<g>` 没有 `offsetWidth`，重启动画用 `getBoundingClientRect()`
- **区分「没播」和「幅度太小」**：量 `currentTime` 逐点跳变后的 rect，若能变化就是幅度问题，别去改动画定义
