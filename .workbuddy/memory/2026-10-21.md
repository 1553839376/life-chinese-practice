# 傍晚：读题朗读 + 对错音效（v3.1）

## 用户诉求
> 特需学生很多时候不认字，需要读题；以及选对错的时候给一个音效反馈。

## 新增 p8.js（语音与音效层，插在 p4.js 与 p5.js 之间）
- `say(text)`：speechSynthesis，zh-CN，默认 rate 0.68（慢档 0.52 / 正常 0.68 / 快 0.88）
- `spkPick()` 选普通话语音：`voiceschanged` + 400ms/1500ms 双击重试（Chrome 首次 getVoices 常为空）
- `readHint(el, ok, fb)`：读不出来时在题面显示「请老师读：…」
  - 无 API → 「这台设备不能朗读」
  - 有 API 但语音列表非空且无 zh → 「没装中文语音」（英文腔会误导）
  - 列表为空（还在加载）→ 静默，不误报
  - 老师手动关了朗读 → 静默
- 音效：`tone/sfxOk/sfxNo/sfxTap/sfxPop/sfxWin`，Web Audio 合成；**错音改 sine 下行 311→233，音量 0.07/0.06**（原 triangle 偏刺）
- 设置存 `wb2_av_v1`：`{voice, sfx, rate}`

# 晚间：语音与音效全面换成「录音 + 开源音效包」（v4，已上线）

## 用户诉求
> 语音还有对应的音效还是很生硬，可以到 github 上找一些开源的语音包等等，优化一下这个操作反馈，优先找 stars 多的项目。

## 关键决策：不从「换 TTS 引擎」入手，改成「预生成录音 + 内联」
- 系统 speechSynthesis 的生硬**无法靠调参解决**，而且受制于设备装没装中文语音包
- 音色质量与「在线/离线」可以解耦：**离线生成、离线播放**
- 读音文本是有限集合（561 主字 + 140 组词用字 + 17 句指令），完全可以全部预生成

## 试过但走不通的路
- **Piper**（rhasspy/piper，MIT，3.7k~11k★，本地神经 TTS，有 zh_CN-huayan-medium）
  → 模型托管在 HuggingFace，`huggingface.co` 与 `hf-mirror.com` 全部 502，模型下不来，放弃
- **uisfx 素材**：`raw.githubusercontent.com`、`codeload.github.com`、`jsdelivr` 都不通

## 最终方案
**语音**：edge-tts `zh-CN-XiaoxiaoNeural`，rate=-8%
- 718 条：`u{hex4}` = 单字读音（561 主字 + 140 组词用字），`q_*`/`g_*`/`fb_*`/`av_*` = 指令句

**音效**：uisfx（github.com/romainsimon/uisfx，875★，MIT 代码 / CC0 音频）

# 傍晚（续）：语音节奏重做 —— 更慢 + 停顿 + 不再连读（v5，已上线）

## 用户反馈（4 条，全部是「节奏」问题）
1. 普遍语速很快，学生反应不过来
2. 点开学字卡直接就读，没有反应时间，应该停一下再读
3. 其他页面语音呈现太快，还没反应过来就开始读了
4. 字卡读字再读词应该停顿，不能连着读；练习题不该连读两遍字再叫你「找出这个字」

## 根因（不是「参数没调」，是两处实现缺陷）
- 语速：录音按 `rate=-8%` 生成，几乎等于正常语速，靠 `playbackRate` 再降会**降调发闷**，所以必须重生成
- 停顿：`sayParts()` 里块间停顿只补 `0.2s`，而 `textParts()` 给每字 `0.06s`，`out[i].gap` 是 truthy → 「块之间补停顿」那段 `if (!out[i].gap)` 根本没生效 → **字和词之间实际只有 0.06s，等于连读**
- 读法：`w + '。' + w + '。找出这个字。'` 先连念两遍字再给指令，顺序和语感都别扭

## 做法
**语音全部重生成**：`gen_tts.py` 加 `TTS_DIR` / `TTS_RATE` 环境变量，按 **rate=-30%** 生成到 `_tts/raw_slow`
- 时长对比（去静音后）：手 0.42→0.55s，找出一样的字 1.26→1.65s，答对了 0.94s
- `pack_audio.py` 加 `TTS_DIR`；音效源目录已删，改成**复用 `_tts/small/sfx_*.mp3`**，重打包不会丢音效
- base64 1.38MB → **1.68MB**；页面 2.43MB → **2.80MB**；实测 load 187~211ms（700 卡正常）

**playbackRate 只做微调**：`AV_RATES` = 0.85 / 1.0 / 1.12，默认 1.0（= 录音本身的慢速）。
`avLoad()` 老值一律**吸附**到最近档（0.52/0.68/0.88/0.84 → 1.0/0.85），避免 UI 高亮和实际倍率对不上。

**新增节奏常量 `PACE`（p8.js，全局）**
```
ready .85    界面出现→开口
afterAsk .8  指令→目标字
afterChar 1.0  字→组词
afterOk .35  音效→反馈语
PACE_GAP .7  句与句之间（sayParts）
```
**新增 `saySeq(list)`**：`list=[{t:文本, gap:这句之后停多久}]`，用于「字→停→词」「指令→停→字」这类受控节奏；`say()` 保持原样。

## 各处读法（统一「先说做什么 → 停 → 再给字」）
- 听音找字：`找出这个字。` +0.8s+ `字`（**只念一遍**，旧版念两遍）
- 找一样的字：`找出一样的字。` +0.8s+ `字`
- 认读跟读：`字` +1.0s+ `字`
- 看拼音 / 图字配对：只念指令，不念答案
- 游戏四种：`把这个字戳掉/钓上来/摘下来` 或 `小动物要吃这个字，喂给它。` +0.8s+ `字`
- 学字卡：打开后**等 0.85s** 再念，`字` +1.0s+ `组词`；用 `CARD_CH` 做凭据，中途关掉/换字就作废
- 练习/游戏进题：一律 `setTimeout(PACE.ready*1000)` 后才读（原 240ms）
- 学字卡「听一听」改成和自动朗读同一节奏（字→停→词）

**反馈节奏**：答对 → 音效，+0.35s 才说「答对了」，自动翻页 1.5s→**2.3s**；
答错重读正确字 430→560ms；结算先让庆祝音效放完，+0.8s 再报成绩。

## 测试
`e2e_av.js` 重写为 **66 项**（原 42）：hook `vaPlay` 记录 `{k,gap}`，
直接断言「界面出现 300ms 内不出声」「指令与字之间 gap≥0.6」「字与词之间 gap≥0.8」
「目标字只出现 1 次」「音效响完前不叠『答对了』」。
回归：e2e_learn 全过 / smoke2 64 / check_pair 16 / check_lib 19 = **206 项全过**

## 发布 v5
tx `tx_6DRwKV4FUVuZdXRHLIqCsc`（base 4）→ 上传 2,807,072B（`upload_curl.py`，首次即成功）
→ commit newVersion 5 → publish **第 3 次才成功**（前两次 `TEMPORARY_ERROR`，必须循环重试）
线上 artifact 2,826,118B（+19KB 平台注入）；已核对 `saySeq` / `PACE` / `gameSay` / VOICE_PACK 1,734,172 字符

## 经验
- 靠 `playbackRate` 降速会降调，**要慢就得重新生成录音**，倍率只用来微调
- 排版式的「补停顿」逻辑容易写错：`if (!gap)` 这种判断，只要上游给了个极小值就永不生效
- `PACE` 统一放常量，以后调节奏只改一处

# 晚间二轮：语音改整词合成 + 恢复自然语速 + 字卡主次（v6，已上线）

## 用户反馈
> 现在有点太慢；单字还好，连贯起来读词语特别生硬，读句子也是；有没有更好的语音模型，能否直接生成连读的词语或句子（暂时不管加载慢）；字卡里没图时左边直接变成词语，主次没分清——这是字卡不是词卡，词语应该小一点。

**词语是单字拼接出来的**：972 个组词全部由单字录音按 0.05~0.16s 间隔拼播放 → 必然一字一顿。
句子生硬是同一个原因（非固定句也会走逐字拼）+ -30% 过慢让神经语音拖腔。

## 做法
**全部重生成 1690 条**（`gen_tts.py` 加整词任务，`_tts_words.json` 由 lib.js 导出）：
- 单字 701 + 组词 972（全部 2~3 字）+ 固定句 17 = 1690，`TTS_RATE=-10%`，22 分 48 秒，0 失败

**运行时最长匹配**（p8.js）：`wordKey()` + `textParts()` 每位置先试 3 字、再 2 字、最后单字，`vaB64()` 命中就用整词
